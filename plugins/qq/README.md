# QQ 持续助手模块

来源与模型输入详情为只读页面，入口是 `ui/QqSourceDetail.vue` / `ui/useQqSources.ts`；请求经宿主管理权限校验后由 Backend `db/sourceManagement.ts` 读取固定来源与采用记录。按模型步骤选择准备版本，目录、消息、正文及来源关系分别分页，刷新不自动换到新步骤。正文只作文字显示，不加载缩略图、远程链接或原始工具结果；401/403 清理受限缓存，关闭页面中止读取并释放正文，不取消业务。当前离线检查与未完成项见[验证记录](../../docs/plan/conversation-observability-and-input/qq-context-verification.md)，不代表实际页面验收或部署。

范围说明分别标识本地记录起点、未确认接收区间和已保存但未纳入所选输入的消息。没有已知来源的说明不展示查看按钮；有来源的查看操作定位到本任务的来源关系区域，加载、空结果和错误均在该处显示，返回时回到原按钮。跳转不切换模型步骤、不修改所选输入，迟到读取不把用户带离新的任务或选择；追加关系页不重新定位。

来源详情采用紧凑阅读分区：宽窗口左侧显示所选模型输入、右侧显示来源关系及已有消息/回复/发送/摘要，窄窗口按此顺序单栏排列。白底阅读区长内容内部滚动，正文保持完整并保留续页入口；每条消息不再单独设滚动条。折叠资料仍按需读取，生成文字不等于实际发送，来源原文不等于模型采用。滚动区可用键盘访问，查看与返回同时保留原按钮定位。自动验证不替代宽/窄窗口及滚动的人工确认；导航和固定选择回归见 `apps/manager/test/qqSourceNavigation.test.ts`、`apps/manager/test/qqSources.test.ts`，实际验收状态见上述验证记录。

左侧版本/调用状态、模型/预算用量以及输入内容分别成块，使用独立标题、完整边框和块间留白，不套总白框或总阅读滚动区。`ui/sourceSections.ts` 的 `groupSourceSections` 只合并连续同类项；消息、范围说明、已采用摘要、附加资料、工具过程和受限内容保持原始位置顺序，不将相隔同类项移到一起，也不为每条消息创建嵌套滚动区。模块重组不改固定选择和来源编号；`sourceReturnTarget` 按原按钮稳定编号保留返回定位。纯数据分组回归为 `apps/manager/test/qqSourceSections.test.ts`，实际分界与滚动仍由用户确认。

QQ业务由本包负责，NapCat适配器只整理事件和收发，Manager仅提供受保护的设置页面。单独@机器人即使没有正文或附件也必须提交后端，由正常对话流程判断如何回应；非@的空消息仍忽略。确认表情按原消息独立保存，合并回答不合并确认；失败不记为成功，适配器按同一消息、同一表情的设置操作恢复重试，不阻断模型和后续请求。发送结果不确定的正文、文件和视频不自动重放；单次失败不设置群级永久锁。发送调度独立于模型任务状态，异常由程序生成明确文字说明，不依赖模型；异常通知失败保留记录并受控恢复，不递归生成通知。QQ离线、禁言或网络不可用时无法保证即时可见，恢复后处理未完成的基础确认和状态通知。入口为 `src/index.ts`，协议为 `../../packages/protocol/src/qq.ts`。

## 任务目标约束

## 聊天配置

`QQConfigSchema`仅接受格式2；旧格式由`src/configConversion.ts`离线转换，不在正常运行时猜测补全。`historyLimit`分别转换为背景消息数和管理历史显示数，不代表存储删除；`continuationMaxMessages`移除。转换程序不会改实际运行配置。

聊天策略由协议`qqConversation.ts`统一解析，默认@后续聊、自然随和、参与适中。群覆盖逐字段继承；缺失继承，空表达补充清空，null拒绝。私聊使用独立默认风格，不启用群主动观察。管理`qq.policy.get`按已生效版本读取，草稿预览不代表已生效；能力未调用验证时不宣称可用。保存保留规范化结果、后续草稿和应用失败原因；结果不确定必须先回读，不换请求ID重复写入。

自动学习限额独立于讨论摘要和聊天请求费用。关闭记忆保留学习/公共词义的配置值，但不再执行后续记忆操作；关闭学习不关闭摘要，也不删除已保存资料。

## 参与判断

默认模式只在@后续聊；主动模式的非活跃观察按群聚合，次数与最后成功参与时间持久保存，正常续聊不套用额外观察间隔。群员互聊不延长机器人续聊时间，明确@及成功交付才延长。判断前只能限次读取当前范围资料；reply必须选择固定候选来源，wait/end不能发正文或互动。观察本身无发送权限，观察结束后才以真实成员创建独立回复任务。

Core的`source_observation_batches`固定候选与权限版本，`source_derived_replies`保存唯一派生关联。派生授权要求真实成功的参与工具结果，不改原收件回执，不放宽单成员输入检查。重启结束旧普通任务和观察，不自动补发；关闭主动模式取消尚未发送的主动回复。自然聊天与实际参与效果需真实模型验收，离线断言不代表效果已通过。

## 工具与操作选择

历史由`qq_history`读取，`qq_information`只查资料；互动合并为`qq_interact`，提醒为`qq_reminder`，文件为`qq_file_read/write`并明确personal/group。信息、互动、提醒按动作严格校验参数。语音要求由模型结合真实来源理解，requested模式必须引用本次输入来源，不靠固定关键词授权。

工具组可选择基础名（全部动作）或`qq_interact.reaction`等操作键；操作键不是可调用工具。注册定义、参数解析、模型可见动作和执行权限使用同一声明。基础/操作角色权限取更严格结果，选择的监管等级不被请求钩子覆盖。QQ入口只自动声明内部参与决定，业务工具必须由工具组明确选择；离线转换映射见`src/toolConversion.ts`。写操作使用稳定operationId，结果未知不盲目重试。

## 网页证据与独立学习

Core在实际工具完成处保存web_search/web_fetch的结构化结果，`source_tool_observations`保留状态、正文摘要值和调用关联；普通模型文字不能代替网页证据。只有成功web_fetch的正文可生成证据，匿名传输、无凭据参数及非私有响应的网页才有公开资格；搜索片段不生成有效公共词义。无法确认公开资格时不共享，不重新抓取网页补证。

`source_learning_operations`固定范围、消息、运行、网页证据和发送事实，与摘要操作独立。学习调用通过learning类型验证，不借摘要授权，摘要推进不使学习失效。QQ的`src/sourceLearning.ts`负责持久位置、分片、额度、失败退避和前台优先；存储回执由记忆提交方返回。普通聊天重启不续跑；学习重启重新检查权限后从尚未完成部分继续。关闭期间不回补，额度含每次学习重试/分块，摘要不计入。

学习在等待来源、缓存及调用后再次检查当前范围和开关，来源被删除或权限失效时取消，不借旧快照继续写入。公共管理员纠正保留原网页与管理员依据；相同网页正文的再次提取不能自动撤销争议或停用，须有新的公开证据。离线边界测试为`test/sourceLearning.test.ts`、`test/knowledge.test.ts`与`apps/backend/test/service/sourceLearning.test.ts`。

通用执行规则由src/conversation.ts维护，查询仅用于完成目标、排除实际障碍或验证结果；不得自行开展无关调查再替换用户指定任务。视频下载先探测并按选择确认，不凭域名或作品名称推断具体授权状态；真实访问限制须据实说明。

## 旧来源转换

旧状态不能直接交给正常运行路径。一次性工具入口为 Backend `service/ingress/sourceMigration.ts` 的 `migrateLegacyQQSources`，命令为 `pnpm exec tsx apps/backend/src/service/ingress/sourceMigrationCli.ts --db <主库绝对路径> --data-dir <QQ 数据目录绝对路径>`，默认只读预览；预览在内存副本中运行，不更改实际数据库表或 JSON。

执行写入前必须停止业务，并备份同一时点的 QQ 数据目录、主库、月库、资产及固定引用；工具自身的文件与主库备份不替代这一完整备份。预览必须没有冲突，且备份可核对后才允许写入。转换保留配置、凭据、群记忆和未知发送，不自动重跑旧任务、不补发未知正文、不付费生成过渡摘要。无法还原的旧内容只留在旧执行历史；新范围明确标记历史起点不完整。

转换的来源指纹、输出文件和完成状态由 `source_legacy_migrations` 保存；中断后按同一记录补齐，不重新猜测部分已转换的文件，不覆盖原备份。状态文件最后发布版本 2，群记忆发布版本 3。同一目标存在不同机器人或预设的可信输入时拒绝转换，不猜测归属；原生问题答案独立保存来源并关联原问题，未知发送保持未知，不补发。离线验证入口为 `apps/backend/test/service/qqSourceMigration.test.ts`；真实迁移另需授权。

获得实际迁移授权后，写入命令另加 `--mode apply --stopped --assets-dir <资产根绝对路径> --backup-dir <工具备份绝对路径> --recovery-manifest <完整备份清单绝对路径>`。工具备份放在被扫描目录之外。清单结构为 `{ "files": [{ "originalPath": "原文件绝对路径", "backupPath": "独立备份文件绝对路径", "sha256": "64位小写摘要" }] }`，须覆盖主库所在目录的全部数据库文件、QQ 数据目录和资产目录的全部文件。工具逐一核对原件和备份，拒绝缺项、不符和符号链接；`--stopped` 是维护者确认业务已停，不代替停服务。中断后保持业务停止，重新核对并备份当前一致状态，再运行同一命令；工具沿已保存的转换记录补齐文件，原转换备份保留。命令参数与完整备份校验另见 `apps/backend/test/service/sourceMigrationCommand.test.ts`。

## 受权限约束的问题与暂停

多任务保存、队尾调度与原任务恢复的正式约定见[QQ 原任务问答](../../docs/shared/protocol/qqbot-plugin.md#qq-原任务问答)。旧已取消等待状态仅在备份后的受控维护中同步结束，不执行、不发送。新版本实现、部署和验证状态见[当前任务](../../docs/plan/conversation-observability-and-input/README.md)。

### 停写问题维护

状态版本 2→3 使用独立的 `apps/backend/src/service/ingress/questionMaintenanceCli.ts`，不启动环境配置、宿主、模型或发送。先停止 Backend/NapCat 业务写入，确认无活动运行，正常关闭 SQLite 并检查 WAL 已写回；新增同一时点的主库/月库、QQ 数据、资产完整备份。备份清单沿用 `files[{originalPath,backupPath,sha256}]`，只接受绝对路径、独立备份及匹配摘要。

```sh
npm run qq-question:maintain -- --db /absolute/data/soul.db --data-dir /absolute/qq --operation-id qq-questions-20261024 --stopped
npm run qq-question:maintain -- --db /absolute/data/soul.db --data-dir /absolute/qq --operation-id qq-questions-20261024 --stopped --mode apply --assets-dir /absolute/assets --recovery-manifest /absolute/backup/manifest.json
```

默认只读预览仅输出数量、请求编号、阶段及许可原因码。关联不足保留历史并禁止恢复；矛盾阻止写入。消息归属由 `workflow_occurrences` 中唯一运行的消息关联证明，成功问题回执按出站 `eventId` 核对。已取消问题仅在原请求、Core 运行、问题批、消息归属和取消事实吻合时同步结束，不伪造用户取消，不动同会话其他运行。旧未结束任务按停止规则结束，不获得跨重启执行许可。未知发送保留未知，不创建输出；配置、凭据、附件、工具结果及原备份不删除。主库保存固定维护编号、指纹和阶段，最后才发布版本 3。中断后保持停写，用同编号、同路径及内容不变的原备份清单补齐，备份不能与原件共用同一文件；不得启动业务或仅换回旧镜像。回退需恢复整套同一时点备份。验证入口为 `apps/backend/test/service/questionMaintenance.test.ts`。

`ask_user_question` 使用 Core 持久问题批。请求内工具模式也将提问交回正常 checkpoint 保存，而不是只保留临时工具历史。QQ 只公开问题、选项及回答方式，不公开 rationale、思考或内部工具参数；群聊与私聊均通过已认证原生引用文字发送。

问题发送成功回执中的 QQ 消息 ID 绑定原问题。仅原发起者在原目标中明确引用该问题才能提交答案；答案按原文写入 Core 的自由文本字段，由模型理解，不以数字、关键词、唯一待办或其他成员文字猜测选项。多个问题分别引用回答，整批齐全后续接原任务与原运行。普通非引用文字仍走普通入口。现有群名单、预设绑定、宿主身份及原运行状态在续接时重新检查；已取消、过期、撤权或配置变更不自动续接。

等待问题是 `paused`，不是失败；问题发送失败／未知单独保存，不重发未知问题、不自动执行旧任务。答案已保存但续接确认失败保留 `QUESTION_RESUME_UNCONFIRMED`，原输入重投才受控核对同一命令；重启本身不执行任务。人工工具审批仅提示在已登录工作台处理，群文字不构成批准。Core 未结束的审批等待与真正任务失败分别呈现。

错误与状态说明统一遵循[安全错误映射](../../docs/shared/protocol/errors.md#qq-安全错误事实)。源码离线回归不代表部署或真实 QQ 验收。

QQ 历次问题批保存在 `questionBatches`；答案保存、排队和启动各有独立状态。`QUESTION_ANSWER_SAVED` 表示答案可靠保存、等待轮到该任务，`QUESTION_RESUME_UNCONFIRMED` 表示保存或启动尚未确认，不能显示为正在执行。相同事件重投只核对既有命令或补齐已证明未完成的保存，不增加用户输入或执行次数。重启不自动执行旧任务。其它错误、审批及断线边界不由普通问答验收替代。


等待反馈默认180秒（3分钟），可在Manager的QQ“消息处理与等待”分类调整。保持原周期发送机制：周期内按事件顺序收集工具图标及模型公开正文，一次合并发送；没有正文只发图标，无新内容使用等待文案。只在投递确认成功后登记已发送正文位置，最终回复不重复已确认正文；失败或未知不当作已发送。思考、工具参数和工具结果不进入等待消息，等待反馈不结束任务。

## 下载进度通报

通用视频脚本采集下载及处理阶段，QQ插件后端按请求配置定时发回原群或私聊，不调用模型。`workerProgressEnabled`默认true，`workerProgressIntervalMinutes`默认10，允许1–1440分钟，通过现有受保护QQ配置读写接口管理；Manager的QQ设置页提供开关和分钟间隔。任务结束或取消即停止，短任务不发中间消息；未知总量不展示百分比或剩余时间，大小使用MB/GB。网络上传输使用Unix Socket的逐行JSON进度事件及最终结果，普通执行命令未产生视频进度时不发下载通知。通知发送失败不终止执行。原固定下载流程不变。

## 实现与使用边界

群消息只在允许群缓存；@唤醒后普通接话进入内部参与判断。`qq_participation_decide`给出reply/wait/end，wait/end不发送空回答，end关闭活跃状态。请求顺序执行，不因新消息中断；连续输入按合并等待处理。同群与预设复用会话，后台收尾摘要不会发到QQ。

记忆统一使用`qq_memory_search`和`qq_memory_manage`。`src/knowledge.ts`按机器人及群／私聊分别存本地事实，同一机器人公共词义单独保存；不读取旧个人、成员或群记忆文件。检索用完整词项与别名，空查询不注入全部，单字只匹配明确术语；本地与公共并列，合计受上下文预算限制。公共候选仅由已读公开网页形成，普通聊天不能直接改写公共定义。拒用标记按公共ID持续保存，更新公共版本不恢复采用。修改有预期版本、来源和操作回执；删除只留证据hash，自动导入不能复活原证据。

管理页面通过只读`qq.knowledge.receipt`核对保存编号。网络失败保留原请求和草稿；回执不存在时重试仍使用相同编号、内容及预期版本，不创建新修改。设置回读以实际提交快照核对，不覆盖保存期间的后续编辑。页面关闭或管理权限失效后清除受限内容，迟到响应不恢复它们。

文件统一通过`qq_file_read`／`qq_file_write`的personal/group范围操作；个人仅`share/`公开，群文件限当前群目录。均不接受`apps/`路径；受管应用须通过`managed_app`操作，权限见[角色安全](../../docs/backend/agent/role-security.md#受管请求)，验证入口为`test/managedAppFiles.test.ts`与`test/videoDownloadSkill.test.ts`。

## 讨论总结与恢复

摘要由`src/sourceMaintenance.ts`组织，固定输入、分块进度和提交凭据按来源操作关联；模型调用经宿主核实当前维护权限，不使用最后发言者身份或增加用户轮次。只有提交成功才替换有效摘要。文本维护只提供附件元信息，不宣称读过附件正文；长期记忆使用独立学习操作，不作为摘要提交前提。

讨论结束独立触发总结，不使用容量压缩阈值，也不发送到QQ。状态保存固定操作、讨论版本、覆盖消息、分块进度与最终候选，失败继续未完成部分。学习则按本地与公共阶段分别记录回执、限额、失败及重试位置，关闭学习不阻断摘要。

新的正常群讨论开始时，仅为这次讨论初始化总结等待时间；旧讨论失败的等待不能阻止新讨论结束后开始自己的总结。同一讨论的失败等待和已保存阶段保持，重复事件、被动消息及问题答案不借此启动新讨论。旧失败记录保留，不重试或重新生成其中不合格的记忆候选，不提高记忆字数限制或裁切内容；启动或部署本身不清除已保存等待时间。

总结输入超限时分块保存完整资料及结果，再分层合并；全部摘要块成功后提交覆盖边界。失败保留原资料和旧摘要，记忆失败不阻断摘要。管理页分别显示原因，不公开底层错误正文。

前台输入只合作式取消本目标的总结，不取消用户任务、不增加任务截止。提交前检查讨论版本与 Core 历史快照；旧操作的迟到成功或失败不能更改新讨论的 pending、重试时间和状态。Core 按模块、会话及操作编号产生固定消息编号，完整凭据只在消息、关联、计数、元数据与运行时失效全部完成后返回；跨库部分写入不能冒充成功，原操作重试幂等补齐。已接受但尚未 active 的输入也受保护，维护提交不得 dispose 其 builder。公共接口见 [`packages/plugin-api/src/index.ts`](../../packages/plugin-api/src/index.ts)，实际组件回归为 `test/reliableDelivery.test.ts` 与 `apps/backend/test/service/ingressRequest.test.ts`；这些离线验证不代表已部署或真实模型、QQ 验收。

## 对话与语音

任务理解与事实优先于人设。每次模型调用以固定来源快照组织当前及合并输入、明确引用、已提交摘要和近期背景，另加本请求真实工具过程；不重复加入 Core 的 user/assistant 展示正文。背景选择采用接受任务时的条数、字数和年龄配置，顺序为明确标注的稳定时间近似顺序。不同发起者分别排队；同主体、同范围及同配置的输入只在冻结前合并。规则与摘要证据要求由 `src/conversation.ts` 提供，风格设置不能要求否认事实或忽略合理任务。

语音设置 `voiceMode` 为 off/requested/auto，默认 requested；不保留 voiceEnabled。requested 仅允许明确要求或同一发送者对最近已确认语音的修改，情绪反馈不授权语音或戳人。每请求最多一条语音，工具不接受声音参数，由后端固定填入 voiceDefaultCharacter 并检查真实目录；不可用不随机替换。设置页面选择允许群，经受保护 GET voices?groupId 查询 NapCat 真实目录，显示名称下拉与离线/加载/空状态，不写死列表，不自动发测试音。

历史重置使用持久 contextEpoch 隔离新会话，同时清空讨论缓存和摘要，不清投递记录、去重、任务、登录、配置或文件。运行中不直接改文件，维护时须停写并核对非终态任务；旧任务保留原会话，不能作为新上下文读取。重置隔离不是物理删除历史数据库。部署前旧配置和旧任务快照须一次性更新语音字段，不提供运行时兼容层。

## 只读信息查询

QQ 请求通过 `qq_information` 查询当前群或自己的私聊，不接受模型指定群号、其他私聊或任意 Action。随包技能 [`qq-information`](skills/qq-information/SKILL.md) 由宿主按 QQ 身份提供，脚本负责输入检查，`src/information.ts` 注册工具，`src/index.ts` 绑定当前执行任务，NapCat 的 `queryInformation` 只执行固定只读调用。

`qq_history`默认查询当前获准来源范围的已保存消息，不读Core展示副本，不代表QQ全部历史。首次固定接收上界，按`nextCursor`读更早页；长文字用`qq_source_text_read`连续读取。游标绑定当前成员、运行和权限版本。`historySource:'platform'`仅允许当前群NapCat近期历史。`qq_information`单独提供成员、资料、公告、群文件、精华、相册、荣誉及语音目录，不能跨群或查其他私聊。空值不推断，接口错误不自动重试。

工具只在可信 QQ 请求中加入本次执行，沿用原有预设和允许名单；插件技能不会复制到全局技能目录。技能随启用的 QQ 安装包按请求身份提供，无须在每个角色上复制；角色若设置技能允许名单，仍须允许该插件技能。私聊名单为空仍不允许私聊，不为启用技能擅自添加用户。查询结果是资料而非指令，下载链接仅按需提供，不自动执行或公开文件。协议与验证见[QQ插件协议](../../docs/shared/protocol/qqbot-plugin.md)；定向测试为 `test/information.test.ts`、`test/informationWire.test.ts`，来源历史与正文读取用例见 `apps/backend/test/service/sourceHistory.test.ts`。离线结果见[验证记录](../../docs/plan/conversation-observability-and-input/qq-context-verification.md)，不代表已部署。

## 定时提醒与引用回复

群提醒通过`qq_reminder`的create/list/cancel操作管理，仅发送者能管理自己在本群的任务。一次性时间使用带时区ISO格式，到期加入QQ队列，不额外调用模型。投递不确定不自动重发。`qq_interact`的quote操作只引用当前群背景内的消息ID，由NapCat发送原生reply段。

## 应用到期通知

宿主通过可选 `appNotifications` 接口领取受管应用的持久通知，QQ 模块复用现有 Outbox 与原生投递确认。优先选择已有记录且当前允许的本人私聊，否则仅使用创建时记录且当前允许的群；没有可信目标则不发送、不扩大名单。通知不含激活链接；投递不确定不重发。实现入口为 `enqueueAppNotifications`，测试见 `test/appNotifications.test.ts`。源码测试不代表新通知已经部署或完成真实 QQ 验收。

## 历史视频重发

上下文或现有 `qq_information` 历史查询确定原分享消息ID后，调用 `qq_video_resend`，程序关联当前会话的下载任务和视频文件，通过现有视频队列创建新的发送事件。群内成员催问明确视频“怎么没发／视频呢”按发送意图处理，不重复确认；只排查或明确禁止发送时不调用。允许复用本群其他成员的分享，私聊只限当前本人。原 unknown 不改写，进行中的发送不重复排队，每请求最多一次；文件失效不自动下载。文件核验、MP4 发送兼容性规范化（视频流置于首轨、非 AAC-LC 音轨转码为 AAC-LC 并写入 `+faststart`）和副本准备在下载清理锁内完成，失败副本删除。排队不代表收到，真实 QQ 验收由用户触发。实现与回归见 `src/videoResend.ts`、`test/videoResend.test.ts`。

## 媒体下载与清理

B站固定下载的地址和音轨规则见随包[技能说明](skills/douyin-download-send/SKILL.md)：仅 MCDN 允许 HTTPS 8082 端口；没有独立音轨的提取结果可下载并返回真实 `hasAudio`，已有音轨不因失败而被丢弃。

一般附件由宿主资产接口保存固定版本，按原消息的文字/附件顺序提交。生成与工具结果的文件通过受认证分段接口送到 NapCat 临时目录，核对完整长度与摘要后原生发送，不建立永久公开链接；执行、保存与渠道发送分别判断。下载不安全或文件导入失败时明确告知未读取内容。协议及边界由[QQ 文件消息](../../docs/shared/protocol/qqbot-plugin.md#插件到后端)维护；新文件流程未作真实 QQ 发送验收，既有媒体下载验收不自动覆盖它。

公开B站视频及抖音分享文字（未 `@AI` 时）走固定下载流程，不需要模型。当用户明确 `@AI` 发送任意视频网站链接（或在私聊向 AI 请求下载）时，进入模型对话并由随包技能 [`video-download`](skills/video-download/SKILL.md) 配合隔离工具容器 `cherynyxus-qq-worker`（插件工具 `qq_container_exec` 与 `qq_deliver_media`）处理：先探测可用清晰度、文件大小（带 MB/GB 单位）、提醒流量对发送速度的严格限制并结合手机观看环境优先推荐 720P/480P，待用户确认后下载并规范化为视频首轨 + `AAC-LC` 的 MP4（单次下载硬限制默认 1024 MB 即 1 GiB，可在 QQ 设置页调整 CPU/内存/进程数/下载上限；体积超过气泡上限默认 200 MB 时自动通过 `upload_group_file` / `upload_private_file` 作为群文件/私聊文件上传），同时支持将新站点的解析下载脚本沉淀到群共享空间 `scripts/` 并记入群记忆供后续零调研复用。B站固定流程使用yt-dlp读取格式、检查音视频合计长度，在150 MiB内选择最高不超过1080P的版本，用ffmpeg合并。画质按宽高中较短的一边判断，支持1080×1920竖屏；先排除非允许域名及含凭据的音视频地址，再依次探测合法音视频组合。同画质优先AVC，再HEVC及其他编码。大小只接受HEAD或Range返回的精确值，不用估算值放行；无法确认的候选跳过，所有候选均不可用则拒绝。每条流保留已确认大小作为下载上限；单个候选下载或合并失败后清理再尝试下一组，最多4组实际下载。无合法音频或候选暂时不可用时允许一次刷新，超限不刷新。合并时保持视频轨在前，若音轨非AAC-LC则自动转码为AAC-LC（画面流直接复制不重编码），成品通过ffprobe核对音视频轨及尺寸，再核对总大小。失败返回明确阶段及安全错误码，不输出媒体签名地址。回归入口为 `apps/backend/test/service/bilibiliFormats.test.ts`。抖音使用Playwright读取作品数据，可用多版本时选择已核实大小的适合版本。大小未知拒绝，下载过程限制大小并严格核对接收字节数等于 `Content-Length`；保存前自动对MP4执行相同的流顺序与AAC-LC音轨规范化；JSON卡片只提取允许域名的链接，只有标题封面不猜。两站复用media目录及下载锁，每日清理超过24小时文件，未确认投递文件受保护。图片仍有独立的单图限制，不能把视频限制解释为相册总量限制。

## 隔离执行与资源配置

QQ插件通过权限为0600的Unix Socket调用宿主受限控制器（`src/workerController.mjs`），不向Backend或命令容器挂载Docker Socket。控制器为每条命令创建可丢弃的工具容器，仅挂载当前群或本人的目录到`/workspace/files`及当前目标的媒体目录到`/workspace/media`。CPU、内存、PID按设置在创建容器时实际应用；当前命令保持配置快照，修改影响下一条命令。控制器串行执行，繁忙时明确拒绝而不无限堆积。取消连接删除对应任务容器；正常请求正文结束不取消命令。

控制器是独立的宿主进程，更新 Backend 镜像或 QQ 安装包不会更新已启动的控制器。部署来源 ZIP 能力时，必须同步发布并重启控制器及其 `sourceWorkspace.mjs`，将 `QQ_WORKER_SOURCE_FILES_ROOT` 指向 QQ 包实际来源目录的宿主路径；它与包内 `QQ_SOURCE_FILES_ROOT`（未指定时为包数据目录的 `source-files/`）须对应同一份持久数据，不能使用群或个人共享根。启用命令容器时，请求准备同时提供 `qq_container_exec` 和 `qq_source_file_read`；关闭时同时排除两者，不要求维护者另改预设的工具名单。部署核对须实际验证原件可见、解压和分页读取，不能只看资产已保存或工具已注册。

来源挂载使用宿主绝对路径，不把 `/proc/<pid>/fd/<fd>` 交给 Docker。控制器仍保持已校验目录的打开句柄，并将设备编号、目录编号按十进制字符串传入镜像内的 `src/workerEntrypoint.py`；入口从 `/` 以 Python `-I -S` 启动，先确认容器实际挂入目录的身份，再逐级无符号链接进入工作目录，最后执行命令。检查失败不执行用户命令、不退回普通路径。工具镜像与控制器须配套重建，旧镜像缺少入口时不能启动命令。构建以 `plugins/qq/` 为上下文，显式提供 `deploy/Worker.Dockerfile` 的 `BASE_IMAGE`；不依赖不存在的旧默认镜像。

来源 ZIP 使用共享根之外的独立持久目录，`src/sourceWorkspace.mjs` 固定目录描述符、原件摘要及私有槽位登记；发布先独占登记不可变来源身份，再补齐同一份原件。不同进程同时发布只接受相同身份与摘要，不覆盖已有文件或解压结果；登记后中断可重试补齐文件，不能据登记本身声称已挂载。完整文件通过不覆盖已有目标的方式发布，遗留的第二个硬链接仅在确认它是私有登记目录中的对应临时文件时移除；任意其他硬链接拒绝。解压脚本以系统文件锁排除并发写入，先在独立临时目录校验整个成员，再发布到 `extracted/`，中断重试不把半份文件当作成功。命令只额外挂载当前获准来源范围；移除目标、换预设、重置或停用时中止该范围命令。控制器先创建容器，核对取消状态后才启动，防止创建期间取消却仍启动命令。长文入口 `qq_source_file_read` 只读本范围已登记槽位内的普通 UTF-8 文件，并在异步权限检查后再次检查取消。相关用例见 `test/sourceWorkspace.test.ts`、`test/archiveInspect.test.ts` 与 `test/workerController.test.ts`；离线通过不代表真实容器、QQ 或模型操作已验收。

群共享目录不是QQ云端群文件：它是插件管理的本机文本/脚本空间，群文件上传仅是交付方式。`mediaScope`绑定真实群或本人，原生适配器按目标校验，不能指定其他目标的媒体目录。1GiB是本项目下载策略；200MiB气泡切换值是可配置策略，不是腾讯官方硬上限，也不能保证原生上传成功。脚本只在实际跑通后沉淀，保存站点范围、参数、依赖和验证方法，不记录临时签名、Cookie或密钥；失效应明确报告并修正，不能直接假定可复用。部署入口为`deploy/Worker.Dockerfile`，控制器需宿主Docker权限并受systemd管理，命令容器不得取得该权限。

## 长任务与周期反馈

任务没有固定运行截止；默认每3分钟合并新工具图标及已有公开正文，否则发送等待提示，每轮重新安排直到实际执行结束。QQ断线不终止执行；反馈和正文分开投递，未发送旧反馈合并，恢复不刷屏。适配器和后端不以15秒或45秒结束在途发送；NapCat返回未知只影响投递记录，不中断正在执行的任务。服务重启是实际中断，不能宣称所有外部任务均可自动续跑。协议和测试见[持续运行与周期反馈](../../docs/shared/protocol/qqbot-plugin.md#持续运行与周期反馈)、`test/reliableDelivery.test.ts`。

## 固定图片重读配置

QQ 使用的感官组需要显式分配 `file_assets_list`、`file_images_find`、`file_image_read` 和 `file_capabilities`，注册工具不等于当前角色可以调用。模型按需选择已授权固定版本，核心按当前会话重新校验权限；不自动重试审核拒绝，不通过 OCR 替代原生图片，也不改变图片保留轮次。当前请求未携图与来源未保存分别说明。

## 安全故障事实

原生引用和 @ 回复工具的 `text` 长度为 1—500 字符，语音工具为 1—200 字符，公开参数定义与运行时校验使用同一限制。长文字回复直接输出普通正文，由既有流程拆分发送，不用更换回复工具绕过长度限制。参数校验拒绝表示调用未执行，不是 QQ 发送失败；已排队、已发送、失败或未知仍以真实投递记录区分，不因模型的文字说明改写。

QQ 任务将 Core 的已声明错误码、追踪码、重试标志与输入图片资产引用数保存为 `failure`，通知和同会话后续上下文使用同一安全说明。错误正文和上游响应不直接进入群聊或模型上下文。具体原因不被通用失败覆盖；迟到事件只补原运行事实，不重复通知或影响新任务。图片引用数不表示模型成功看图，本轮到期占位不能解释为上轮接收失败。验证入口为 `test/failureFacts.test.ts`。

模型运行前的准备或提交异常以 `entryFailure` 保存固定许可的错误码、阶段和时间，并按请求编号记录安全日志；不保存异常正文、调用栈或嵌套原因。未知错误统一为 `EXECUTION_ENTRY_FAILED`，不从正文猜测原因。停机已取消的任务不因迟到异常发送失败通知。新 QQ 请求的停机处理遵守[空队列恢复规则](../../docs/shared/protocol/qqbot-plugin.md#服务停止与空队列恢复)，不以新输入续跑旧工具。

## 发送事实

模型上下文自动提供当前及同会话近期请求的发送记录，覆盖文字、视频、图片、文件、互动及程序失败通知。每条记录独立区分 sent、failed、unknown、pending 和 inflight；通知发送成功不能替代原内容的成功回执，历史缺失不能证明发送失败。仅提供有限相关记录，不暴露本地文件路径。

## 当前限制与验证边界

通用执行容器的CPU、内存和PID限制实际作用于容器；下载大小上限由视频脚本检查，不能视为任意shell命令的磁盘配额。当前可写挂载没有独立硬磁盘配额，获准命令仍可能写满宿主文件系统。入口和重定向地址校验不能覆盖外部下载器请求的全部HLS分片、密钥及DNS变化；bridge网络尚无禁止访问内网的出站规则，不应把该执行环境视为完全隔离的不可信代码沙箱。

HLS独立音频组关联及输出完整时长核验尚不完善；部分源可能出现无声或提前截断，不能仅凭下载器退出成功保证整片完整。N_m3u8DL-RE为可选工具，默认HLS使用FFmpeg；可选工具的版本检查不代表下载验证通过。


真实 QQ 发送和媒体功能已通过用户验收，不再等待这两项实际业务验证。该结论不扩展为所有异常场景、Manager 页面或其他模块均已验收，也不表示下列已知问题已修复。

构建、类型与定向测试通过不代表所有群场景已验收。后续修改按影响范围核对多人合并、参与判断、摘要、群事实、提醒、投递异常和重启恢复；不能将这些异常场景的待核对项解释为真实发送或媒体尚未验收。真实群动作由用户触发，不自动发送测试。
