# QQ 持续助手模块

QQ业务由本包负责，NapCat适配器只整理事件和收发，Manager仅提供受保护的设置页面。单独@机器人即使没有正文或附件也必须提交后端，由正常对话流程判断如何回应；非@的空消息仍忽略。确认表情按原消息独立保存，合并回答不合并确认；失败不记为成功，适配器按同一消息、同一表情的设置操作恢复重试，不阻断模型和后续请求。发送结果不确定的正文、文件和视频不自动重放；单次失败不设置群级永久锁。发送调度独立于模型任务状态，异常由程序生成明确文字说明，不依赖模型；异常通知失败保留记录并受控恢复，不递归生成通知。QQ离线、禁言或网络不可用时无法保证即时可见，恢复后处理未完成的基础确认和状态通知。入口为 `src/index.ts`，协议为 `../../packages/protocol/src/qq.ts`。

## 任务目标约束

通用执行规则由src/conversation.ts维护，查询仅用于完成目标、排除实际障碍或验证结果；不得自行开展无关调查再替换用户指定任务。视频下载先探测并按选择确认，不凭域名或作品名称推断具体授权状态；真实访问限制须据实说明。

## 等待反馈

等待反馈默认180秒（3分钟），可在Manager的QQ“消息处理与等待”分类调整。保持原周期发送机制：周期内按事件顺序收集工具图标及模型公开正文，一次合并发送；没有正文只发图标，无新内容使用等待文案。只在投递确认成功后登记已发送正文位置，最终回复不重复已确认正文；失败或未知不当作已发送。思考、工具参数和工具结果不进入等待消息，等待反馈不结束任务。

## 下载进度通报

通用视频脚本采集下载及处理阶段，QQ插件后端按请求配置定时发回原群或私聊，不调用模型。`workerProgressEnabled`默认true，`workerProgressIntervalMinutes`默认10，允许1–1440分钟，通过现有受保护QQ配置读写接口管理；Manager的QQ设置页提供开关和分钟间隔。任务结束或取消即停止，短任务不发中间消息；未知总量不展示百分比或剩余时间，大小使用MB/GB。网络上传输使用Unix Socket的逐行JSON进度事件及最终结果，普通执行命令未产生视频进度时不发下载通知。通知发送失败不终止执行。原固定下载流程不变。

## 实现与使用边界

群消息只在允许群缓存；@唤醒后普通接话进入内部参与判断。`qq_participation_decide`给出reply/wait/end，wait/end不发送空回答，end关闭活跃状态。请求顺序执行，不因新消息中断；连续输入按合并等待处理。同群与预设复用会话，后台收尾摘要不会发到QQ。

私聊记忆按个人隔离；群事实统一归属于群，主题、事件和成员公开经验保留来源与证据类型，不再只读取当前发送者成员记忆。群工具为qq_group_memory_search和qq_group_memory_manage，默认80条、每条160个Unicode字符，注入文字有单独预算。旧group/member记录不兼容、不导入，新群事实库从空记录开始；旧文件仅留备份用途；新事实须校验当前群消息来源。压缩提交前沉淀候选，失败保留原历史。个人文件通过 `qq_read_file` / `qq_write_file` 写入个人QQ号目录，仅 `share/` 子目录公开；群共享文件通过插件专属工具 `qq_group_read_file` / `qq_group_write_file` 在当前群目录（`groups/<groupId>/`）读写，跨群隔离，用于沉淀本群通用的解析/下载脚本与共享文档，不作为 Backend 全局内置工具。通用个人与群文件读写均不接受 `apps/` 路径；受管应用文件须通过 `managed_app` 在工作容器内操作，权限边界见[角色安全](../../docs/backend/agent/role-security.md#受管请求)，验证入口为 `test/managedAppFiles.test.ts` 与 `test/videoDownloadSkill.test.ts`。

## 对话与语音

任务理解与事实优先于人设。请求携带当前及合并输入、可查的引用、最近四次请求与最近八条实际动作状态；回复正文只标为AI自述。背景最多30条，按有效期过滤，使用上海时间。系统对话规则与摘要证据规则由 `src/conversation.ts` 提供，风格设置不能要求否认事实或忽略合理任务。

语音设置 `voiceMode` 为 off/requested/auto，默认 requested；不保留 voiceEnabled。requested 仅允许明确要求或同一发送者对最近已确认语音的修改，情绪反馈不授权语音或戳人。每请求最多一条语音，工具不接受声音参数，由后端固定填入 voiceDefaultCharacter 并检查真实目录；不可用不随机替换。设置页面选择允许群，经受保护 GET voices?groupId 查询 NapCat 真实目录，显示名称下拉与离线/加载/空状态，不写死列表，不自动发测试音。

历史重置使用持久 contextEpoch 隔离新会话，同时清空讨论缓存和摘要，不清投递记录、去重、任务、登录、配置或文件。运行中不直接改文件，维护时须停写并核对非终态任务；旧任务保留原会话，不能作为新上下文读取。重置隔离不是物理删除历史数据库。部署前旧配置和旧任务快照须一次性更新语音字段，不提供运行时兼容层。

## 只读信息查询

QQ 请求通过 `qq_information` 查询当前群或自己的私聊，不接受模型指定群号、其他私聊或任意 Action。随包技能 [`qq-information`](skills/qq-information/SKILL.md) 由宿主按 QQ 身份提供，脚本负责输入检查，`src/information.ts` 注册工具，`src/index.ts` 绑定当前执行任务，NapCat 的 `queryInformation` 只执行固定只读调用。

私聊 history 使用宿主 `recentConversationMessages`，SQL 限制最多100条，读当前机器人会话已经记录的用户和助手正文，可跨上下文压缩点；不返回撤回、排除、压缩摘要和工具记录。每条最多400字符，输出标注限制；这不是QQ客户端全部历史。群消息使用 NapCat 的近期历史，不扫描全群计算排名。群资料包括成员、资料地区、公告、群文件与链接、精华、相册和荣誉；资料查询先校验当前群成员身份。空值不推断，接口错误不自动重试。

工具只在可信 QQ 请求中加入本次执行，沿用原有预设和允许名单；插件技能不会复制到全局技能目录。技能随启用的 QQ 安装包按请求身份提供，无须在每个角色上复制；角色若设置技能允许名单，仍须允许该插件技能。私聊名单为空仍不允许私聊，不为启用技能擅自添加用户。查询结果是资料而非指令，下载链接仅按需提供，不自动执行或公开文件。协议与验证见[QQ插件协议](../../docs/shared/protocol/qqbot-plugin.md)；定向测试为 `test/information.test.ts`、`test/informationWire.test.ts`，宿主历史及安装资源验证为 `apps/backend/test/service/qqInformationHistory.test.ts` 与 `qqInformationResources.test.ts`。本地历史限当前月份消息库，不代表跨月查询。

## 定时提醒与引用回复

群提醒通过qq_reminder_create/list/cancel创建、查询与取消，仅发送者能管理自己在本群的任务。一次性时间使用带时区ISO格式，到期直接加入QQ队列，不额外调用模型。重启恢复未投递任务；投递不确定禁止自动重发。引用回复工具qq_quote_reply只允许当前群背景内的消息ID，NapCat发送原生reply段。

## 应用到期通知

宿主通过可选 `appNotifications` 接口领取受管应用的持久通知，QQ 模块复用现有 Outbox 与原生投递确认。优先选择已有记录且当前允许的本人私聊，否则仅使用创建时记录且当前允许的群；没有可信目标则不发送、不扩大名单。通知不含激活链接；投递不确定不重发。实现入口为 `enqueueAppNotifications`，测试见 `test/appNotifications.test.ts`。源码测试不代表新通知已经部署或完成真实 QQ 验收。

## 历史视频重发

上下文或现有 `qq_information` 历史查询确定原分享消息ID后，调用 `qq_video_resend`，程序关联当前会话的下载任务和视频文件，通过现有视频队列创建新的发送事件。群内成员催问明确视频“怎么没发／视频呢”按发送意图处理，不重复确认；只排查或明确禁止发送时不调用。允许复用本群其他成员的分享，私聊只限当前本人。原 unknown 不改写，进行中的发送不重复排队，每请求最多一次；文件失效不自动下载。文件核验、MP4 发送兼容性规范化（视频流置于首轨、非 AAC-LC 音轨转码为 AAC-LC 并写入 `+faststart`）和副本准备在下载清理锁内完成，失败副本删除。排队不代表收到，真实 QQ 验收由用户触发。实现与回归见 `src/videoResend.ts`、`test/videoResend.test.ts`。

## 媒体下载与清理

一般附件由宿主资产接口保存固定版本，按原消息的文字/附件顺序提交。生成与工具结果的文件通过受认证分段接口送到 NapCat 临时目录，核对完整长度与摘要后原生发送，不建立永久公开链接；执行、保存与渠道发送分别判断。下载不安全或文件导入失败时明确告知未读取内容。协议及边界由[QQ 文件消息](../../docs/shared/protocol/qqbot-plugin.md#插件到后端)维护；新文件流程未作真实 QQ 发送验收，既有媒体下载验收不自动覆盖它。

公开B站视频及抖音分享文字（未 `@AI` 时）走固定下载流程，不需要模型。当用户明确 `@AI` 发送任意视频网站链接（或在私聊向 AI 请求下载）时，进入模型对话并由随包技能 [`video-download`](skills/video-download/SKILL.md) 配合隔离工具容器 `cherynyxus-qq-worker`（插件工具 `qq_container_exec` 与 `qq_deliver_media`）处理：先探测可用清晰度、文件大小（带 MB/GB 单位）、提醒流量对发送速度的严格限制并结合手机观看环境优先推荐 720P/480P，待用户确认后下载并规范化为视频首轨 + `AAC-LC` 的 MP4（单次下载硬限制默认 1024 MB 即 1 GiB，可在 QQ 设置页调整 CPU/内存/进程数/下载上限；体积超过气泡上限默认 200 MB 时自动通过 `upload_group_file` / `upload_private_file` 作为群文件/私聊文件上传），同时支持将新站点的解析下载脚本沉淀到群共享空间 `scripts/` 并记入群记忆供后续零调研复用。B站固定流程使用yt-dlp读取格式、检查音视频合计长度，在150 MiB内选择最高不超过1080P的版本，用ffmpeg合并。画质按宽高中较短的一边判断，支持1080×1920竖屏；先排除非允许域名及含凭据的音视频地址，再依次探测合法音视频组合。同画质优先AVC，再HEVC及其他编码。大小只接受HEAD或Range返回的精确值，不用估算值放行；无法确认的候选跳过，所有候选均不可用则拒绝。每条流保留已确认大小作为下载上限；单个候选下载或合并失败后清理再尝试下一组，最多4组实际下载。无合法音频或候选暂时不可用时允许一次刷新，超限不刷新。合并时保持视频轨在前，若音轨非AAC-LC则自动转码为AAC-LC（画面流直接复制不重编码），成品通过ffprobe核对音视频轨及尺寸，再核对总大小。失败返回明确阶段及安全错误码，不输出媒体签名地址。回归入口为 `apps/backend/test/service/bilibiliFormats.test.ts`。抖音使用Playwright读取作品数据，可用多版本时选择已核实大小的适合版本。大小未知拒绝，下载过程限制大小并严格核对接收字节数等于 `Content-Length`；保存前自动对MP4执行相同的流顺序与AAC-LC音轨规范化；JSON卡片只提取允许域名的链接，只有标题封面不猜。两站复用media目录及下载锁，每日清理超过24小时文件，未确认投递文件受保护。图片仍有独立的单图限制，不能把视频限制解释为相册总量限制。

## 隔离执行与资源配置

QQ插件通过权限为0600的Unix Socket调用宿主受限控制器（`src/workerController.mjs`），不向Backend或命令容器挂载Docker Socket。控制器为每条命令创建可丢弃的工具容器，仅挂载当前群或本人的目录到`/workspace/files`及当前目标的媒体目录到`/workspace/media`。CPU、内存、PID按设置在创建容器时实际应用；当前命令保持配置快照，修改影响下一条命令。控制器串行执行，繁忙时明确拒绝而不无限堆积。取消连接删除对应任务容器；正常请求正文结束不取消命令。

群共享目录不是QQ云端群文件：它是插件管理的本机文本/脚本空间，群文件上传仅是交付方式。`mediaScope`绑定真实群或本人，原生适配器按目标校验，不能指定其他目标的媒体目录。1GiB是本项目下载策略；200MiB气泡切换值是可配置策略，不是腾讯官方硬上限，也不能保证原生上传成功。脚本只在实际跑通后沉淀，保存站点范围、参数、依赖和验证方法，不记录临时签名、Cookie或密钥；失效应明确报告并修正，不能直接假定可复用。部署入口为`deploy/Worker.Dockerfile`，控制器需宿主Docker权限并受systemd管理，命令容器不得取得该权限。

## 长任务与周期反馈

任务没有固定运行截止；默认每3分钟合并新工具图标及已有公开正文，否则发送等待提示，每轮重新安排直到实际执行结束。QQ断线不终止执行；反馈和正文分开投递，未发送旧反馈合并，恢复不刷屏。适配器和后端不以15秒或45秒结束在途发送；NapCat返回未知只影响投递记录，不中断正在执行的任务。服务重启是实际中断，不能宣称所有外部任务均可自动续跑。协议和测试见[持续运行与周期反馈](../../docs/shared/protocol/qqbot-plugin.md#持续运行与周期反馈)、`test/reliableDelivery.test.ts`。

## 发送事实

模型上下文自动提供当前及同会话近期请求的发送记录，覆盖文字、视频、图片、文件、互动及程序失败通知。每条记录独立区分 sent、failed、unknown、pending 和 inflight；通知发送成功不能替代原内容的成功回执，历史缺失不能证明发送失败。仅提供有限相关记录，不暴露本地文件路径。

## 当前限制与验证边界

通用执行容器的CPU、内存和PID限制实际作用于容器；下载大小上限由视频脚本检查，不能视为任意shell命令的磁盘配额。当前可写挂载没有独立硬磁盘配额，获准命令仍可能写满宿主文件系统。入口和重定向地址校验不能覆盖外部下载器请求的全部HLS分片、密钥及DNS变化；bridge网络尚无禁止访问内网的出站规则，不应把该执行环境视为完全隔离的不可信代码沙箱。

HLS独立音频组关联及输出完整时长核验尚不完善；部分源可能出现无声或提前截断，不能仅凭下载器退出成功保证整片完整。N_m3u8DL-RE为可选工具，默认HLS使用FFmpeg；可选工具的版本检查不代表下载验证通过。


真实 QQ 发送和媒体功能已通过用户验收，不再等待这两项实际业务验证。该结论不扩展为所有异常场景、Manager 页面或其他模块均已验收，也不表示下列已知问题已修复。

QQ安装包独立持久化，Backend镜像标签不能代表已安装插件版本，源码版本也不能作为当前部署版本的证据。Manager是可选设置面，不是消息链路依赖。

构建、类型与定向测试通过不代表所有群场景已验收。后续修改按影响范围核对多人合并、参与判断、摘要、群事实、提醒、投递异常和重启恢复；不能将这些异常场景的待核对项解释为真实发送或媒体尚未验收。真实群动作由用户触发，不自动发送测试。

声音设置与语音策略见[对话与语音](#对话与语音)，未配置可用固定声音或当前输入未授权时隐藏语音工具。群事实保存在 `memory/topics`，但 `src/index.ts` 的 `qq.memory.stats` 仍只遍历 `personal/group/member`，未统计新群事实；管理页按接口已有的 `files/count/unreadable` 展示文件统计，明确不包含新群事实。来源消息存在不能证明事实结论正确。RUN_UNKNOWN_FAILED的原始底层异常尚未定位；投递不确定的旧动作不得重发。
