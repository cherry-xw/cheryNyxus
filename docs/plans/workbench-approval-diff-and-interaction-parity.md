# 工作台审批差异与工具交互一致性

## 背景与范围

会话 `64b5bf27-074f-4b29-ae56-85e433fade8c` 曾删除开发团队预设、角色、感官组和提示词资产。操作前只有通用参数，没有真实的文件或配置差异，因此用户无法审核具体影响。本计划不自动恢复那些历史资源；仅补足未来变更的可审阅性与工作台交互一致性。

本计划覆盖：

1. 审批前的声明式文件变更预览：`write_file`、`config_manage.patch`、`asset_save`、`asset_archive`。
2. 节点树 hover、卡牌阅读模式与 Lite 模式中的审批和提问交互一致性。
3. Lite 标题栏开关、终态计时、普通节点详情加载问题。

不可可靠预演的命令仅沿用命令、权限与风险说明，不伪造文件差异。

## 实施设计

### 审批差异

- 在 middleware 中生成只用于展示的 `__filePreview`；原始 `argsJson` 始终用于真正工具调用。
- 差异对象支持多文件、创建、修改和归档（删除）状态；配置候选通过 `applyConfigOperations` 计算，并使用脱敏后的稳定 JSON 文本比较。
- 前端使用无依赖的 LCS 行级 diff 显示上下文、`+` 新增和 `-` 删除；预览不可生成时显示明确原因。
- 对 `write_file` 与资产写入/归档保存审批时的原内容 hash。审批通过后再次读取并比对；不一致即拒绝执行并要求重新审核。配置 patch 由已有 `baseRevision` 并发校验保护。
- 完整预览限制为 1MB；超过限制不会截断后假称完整，而是明确提示不能生成差异。

### 三种工作台视图

- 节点树浮层直接使用 `ApprovalCard` 和 `QuestionCard`，使批准、拒绝、选项、自由文本及提交都经过已有 store。
- 卡牌阅读模式把当前卡牌关联的 approval/question 从默认节点 popover 模型传递到 `NodePaperStack` 和嵌套 `PaperGameCard`；不建立额外的审批或回答状态。
- Lite 继续使用现有 canonical interaction 状态，并复用相同的审批预览数据。
- 交互完成、取消或过期后，投影源更新，三个视图都会自动降级为只读或关闭。

### Lite 修复

- 原生窗口标题栏 Lite switch 退出 Electron 拖拽区，确保非全屏也可点击。
- 最终模型回复优先于过期 `waiting` run snapshot，执行状态投影为 completed，计时冻结且不再显示停止。
- 节点已有正文时详情抽屉直接使用 canonical 内容，不再发起 ID 映射不稳定的详情请求；工具详情仍按需加载。
- 工具详情的服务器响应无论请求何种 section 都保持 `TimelineNode.content` 字段；未请求正文时返回空串，以满足公开 response schema。
- Lite 工具详情从首页开始使用 `toolCursor`，后续页严格使用服务器返回的游标；不再用普通文本 offset 重试工具参数和结果。

### 核心协议回归基线

- 节点详情 handler 对默认和全部 7 种 section 组合跑真实输出，每一个响应均通过 public response schema。
- 工具 arguments/result 的跨页游标递进、Unicode 边界和非法游标均归入协议测试。
- 新增真实服务场景：通过 WebSocket 创建根会话、发起需审批的写工具、读取审批前历史节点详情、接受审批并读取完成后结果。测试覆盖了真实 router 响应校验，不允许用静态成功样例替代。

## 开发顺序与验收

1. 预览构建、快照校验和行 diff，覆盖文件、配置与资产操作。
2. 让节点树和卡牌模式复用现有审批/提问组件。
3. 完成 Lite 状态与详情修复，并补充回归测试。
4. 执行 TypeScript 检查及目标 Vitest 测试；手工验证原生非最大化窗口的开关。

验收条件：

- 审批前能看到路径、状态及真实增删行，且不把展示元数据传给工具。
- 文件在审核后被外部修改时，审批不会覆盖该修改。
- 三种工作台视图的审批/提问均可提交，状态同步。
- 完成任务后 Lite 计时冻结、停止按钮消失，用户、事件、最终响应和工具节点均可打开详情。
