# Task 6：MCU 有界执行界面

## 目标

在 MCU 固件中以固定内存展示当前问题、总计时和模型/工具执行步骤，并通过 Lite profile 的受限参数完成重连恢复与详情分页。

## 允许修改范围

- MCU Lite 客户端配置、协议解码和执行步骤固定容量状态。
- MCU 屏幕上的问题、总状态、总计时、活动节点与完成摘要渲染。
- 按键触发的最终正文、thinking 和工具详情分页加载。
- MCU host/static 测试及设备配置文档。

## 禁止事项

- 不修改 Web/Electron UI、store 或 canonical 连接路径。
- 不改变 Task 1 已确定的 wire contract。
- 不使用动态分配保存执行步骤或详情全文。
- 不在首屏自动拉取完整正文、thinking、工具参数或工具结果。
- 不假定全局只有一个活动步骤；必须容纳并行子 Agent。
- 不让任一响应超过设备声明的 `maxFrameBytes`。

## 接口与行为

- MCU 使用独立 `profile=lite` 连接，默认参数：
  - `maxFrameBytes=2048`。
  - `turnDelta=0`。
  - `executionStepLimit=16`。
- 设备允许配置帧预算、时间线页大小、详情字符页大小和步骤容量；默认步骤容量固定为 16。
- 固件使用固定 16 项 `ExecutionStep` 数组，不动态分配。
- 顶部显示截断后的当前问题、root 状态和总耗时。
- 下方显示活动步骤和已完成摘要：
  - 活动节点置顶并实时计时。
  - 多个并行活动节点同时保留，并显示活动数量。
  - 完成节点显示名称、终态和耗时。
  - 超过容量时合并最早完成项为“较早步骤 N 项 / 累计耗时”，不得丢弃活动节点。
- 重连后使用 currentState 的 `startedAt` 与 `executionSteps` 恢复计时，不从零重新计时。
- 最终正文、thinking 和工具详情由用户按键触发 `node.get offset/limit` 分页加载，每次只保留当前页或有界窗口。
- `turnDelta=0` 时忽略/拒绝逐字流式正文路径。

## 测试

- 2048 B 默认帧预算下所有响应均可解码且不溢出设备缓冲。
- 固定 16 项数组无越界、无动态分配。
- 多个顺序工具正确切换独立计时并保留完成耗时。
- 模型轮次与工具步骤按实际顺序显示。
- 多 Agent 并行活动节点不会被顺序覆盖。
- 溢出时只汇总最早完成节点，running 节点始终保留。
- 重连 currentState 恢复总计时和活动节点计时。
- 超长最终正文、thinking 和工具详情分页连续，无重复或缺段。
- `turnDelta=0` 不接收逐字正文；能力开启场景由协议测试覆盖。

## 完成条件

- MCU 在默认 2048 B/16 步配置下稳定展示问题、总计时和步骤计时。
- 固定内存、溢出汇总、断线恢复和分页测试全部通过。
- 文档说明所有可配置参数及默认值。
- 删除本文件，在 master 中标记 Task 6 完成。
