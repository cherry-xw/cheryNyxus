# Task 4：执行监控 UI 与懒加载详情

## 目标

把 Lite 界面重构为任务执行监控器：突出当前问题、总耗时和当前执行节点，完成步骤自动收起，正文与详情按需加载。

## 允许修改范围

- LiteView、执行步骤组件、状态栏和详情抽屉。
- 基于 Task 2 读模型的展示 adapter 与纯 UI 计时器。
- 详情展开时的 `node.get` 分页请求与局部缓存。
- 审批详情定位、对象参数展示、键盘操作、焦点管理与相关前端测试。

## 禁止事项

- 不创建连接、订阅或独立重连逻辑。
- 不更改后端计时协议与执行事件语义。
- 不在 Lite 首屏主动加载 thinking、工具参数、工具结果或完整长正文。
- 不把工具参数、结果、原始 JSON、content hash 等内部数据暴露在普通步骤摘要中。
- 不在本任务重构发送、审批、提问命令状态机；除详情定位外留给 Task 5。
- 不修改 MCU 固件。

## 接口与行为

- 顶部展示当前问题、root 总状态、总耗时和连接状态。
- 总计时从问题进入执行流程开始，到 root `done`/error/abort 封口。
- 下方按真实事件顺序展示模型轮次与工具调用：
  - 活动节点展开，每秒刷新自身耗时。
  - 完成节点自动折叠，只保留名称、终态、耗时。
  - failed、rejected、cancelled 使用可区分终态。
  - 多 Agent 并行时同时展示多个活动节点。
- 工具普通步骤仅显示工具名和计时；审批卡可显示工具名与短风险摘要。
- 最终正文只突出 root 流程最后正文，首屏显示首段并提供“加载更多”。
- thinking、工具参数、工具结果和后续正文只在用户展开时调用 `node.get offset/limit`。
- 详情分页必须分别维护内容类型的 offset，保证不重复、不缺段。
- 对象形式参数/结果须可读展示；没有 anchor 时审批详情可定位到正确工具节点。
- 交互元素支持 Enter/Space；抽屉支持 Escape、焦点锁定和关闭后的焦点恢复。
- 删除无功能的“…”占位或实现真实菜单，不保留误导入口。

## 测试

- fake timer 验证总计时、模型计时、工具计时、完成封口与每秒刷新。
- 顺序工具完成后自动折叠并启动下一节点计时。
- 并行 Agent 同时显示多个活动节点。
- root 最终正文正确，子 Agent/中间正文不被当作最终结果。
- 首屏不额外调用 `node.get`；展开各类详情时才请求。
- 正文、thinking、工具详情分页连续且无重复/缺段。
- 普通工具摘要不泄露参数/结果；审批仅显示短风险摘要。
- 详情定位、对象参数、Enter/Space、Escape 和焦点恢复正确。

## 完成条件

- Lite 首屏清晰呈现“当前问题 + 总计时 + 当前步骤”，完成步骤均为一行摘要。
- 懒加载和无数据泄露测试通过。
- UI 无独立连接或重连副作用。
- 删除本文件，在 master 中标记 Task 4 完成。
- 独立提交：`feat(web): add lite execution monitor`。
