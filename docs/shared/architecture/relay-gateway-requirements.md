# 独立后端与中转网关需求

**状态：** 目标需求；账号绑定、列表权限和中转 OIDC 尚未按本文实现。当前接口行为以[中转协议](../protocol/relay.md)及代码为准，不能把下述目标当作已上线功能。

## 1. 目标

让用户本地运行的 CheryNyxus 后端主动接入公共中转，不开放本地公网端口。公共前端通过中转使用后端；同一台机器上的本地前端可直接连接本地后端。中转统一接入部署方指定的同一个 Pocket ID，普通账号持有人可以在拥有本地管理权限时自行绑定后端，也可以不使用 Pocket ID，凭目标后端用户名密码经中转登录。

后端、前端、中转、Pocket ID 和本地启动管理分别运行。Electron 只负责前端界面，不再内置后端。

## 2. 范围与非目标

### 2.1 范围

- 本地后端通过 rathole client 主动连接中转服务。
- 中转只转发 CheryNyxus 的 HTTP `/api/*` 和 WebSocket 控制面。
- 公共中转统一配置一个指定 Pocket ID 的 OIDC 客户端；每台后端不再各自配置 OIDC 客户端。
- 前端支持中转 Pocket ID 登录和指定后端的用户名密码登录，两者是独立入口。
- 登录页是浏览器前端的前置入口：未完成目标选择、认证、能力说明校验和连接确认前，只加载登录壳及其必要资源，不加载工作台、会话、设置、工具、桌宠、文档或其他业务资源。
- 认证成功后，前端必须先读取并校验当前后端的分级能力，再按允许的能力动态加载业务模块；能力缺失、不兼容或连接失败时停留在登录壳。
- 公共列表只展示后端所有者主动允许公开发现的在线后端；Pocket ID 用户另有“我的后端”列表；未公开的后端仍允许凭 Backend ID 尝试密码登录。
- 本机打开本地前端时，可经本地 loopback 入口免登录连接本机后端；中转专用入口不继承此豁免。
- 一个前端会话一次只绑定一个后端。
- 后端业务端口可配置，前端通过连接发现接口获取实际地址。
- 前端和中转可以部署在域名的任意路径前缀下，例如 `/nyxus/`。
- 本地提供独立管理器和 `127.0.0.1:39980` 管理页面。

### 2.2 非目标

- 不提供任意 TCP、HTTP 或文件服务代理。
- 不把中转做成通用开放代理。
- 不由 Electron 启动或管理后端。
- 不要求前端同时操作多个后端。
- 不在仓库内重新实现 Pocket ID。
- 不使用邀请码作为前端访问凭据。
- 不把本地 `39980` 管理页开放给公网或放进中转代理。
- 不依赖关闭浏览器跨域限制，让公共网站脚本免密操作本机 `localhost`。

## 3. 运行角色

```text
用户本地机器
  ├─ 本地管理器
  │   ├─ 管理页面 127.0.0.1:39980
  │   ├─ 启停后端和 rathole client
  │   └─ 展示运行状态、凭据、端口和 Agent 统计
  ├─ CheryNyxus 后端
  │   ├─ 可变 HTTP 端口
  │   ├─ 可变 WebSocket 端口
  │   └─ 本地管理/发现信息
  └─ rathole client
       └─ 主动连接公网中转

公网服务器
  ├─ nginx：静态前端、HTTPS、路径前缀转发
  ├─ 中转控制服务：后端列表、Backend ID、协议路由、审计和限流
  ├─ rathole server：承载反向连接
  └─ Pocket ID：外部 OIDC 身份服务，已由部署方提供

客户端
  ├─ 浏览器
  └─ Electron：只加载前端并连接选定后端
```

## 4. 后端身份与发现

### 4.1 Backend ID

每个后端拥有稳定的 `backendId`。它是路由标识，不是邀请码，也不是登录凭据。

- Backend ID 由用户设置并持久化，使用 3 至 63 个小写字母、数字或连字符；它只作为易读路由标识。
- 首次本地启动自动生成 Ed25519 密钥对；中转通过挑战签名验证设备，并将 Backend ID 首次信任绑定到公钥指纹。
- 同名 Backend ID 已绑定其他公钥时拒绝连接，不允许覆盖在线或已登记后端。
- 中转允许后端主动连接并下发连接配置，不要求管理员提前逐个注册。
- Pocket ID 登录用户在“我的后端”中选择获准设备；密码用户可选择最近连接或主动公开的设备，也可输入 `backendId`。列表可见、知道 ID 和路由绑定均不等于业务授权。
- 默认不公开发现。关闭公开发现仍允许知道 Backend ID 的人尝试密码登录；是否允许远程密码登录是另一个独立配置。

开放连接不等于开放代理。中转只接受规定的 CheryNyxus agent/rathole 连接协议，并限制注册频率、连接数、转发路径和资源使用。

设备密钥只用于身份签名。公网传输由 HTTPS/WSS 和 rathole 加密，不自定义消息加密算法。稳定字段与错误见[中转协议](../protocol/relay.md)。

### 4.2 连接发现

业务端口不固定，`8182/8183` 只能作为默认值。

后端 HTTP 服务提供权威发现接口：

```http
GET /api/config
```

至少返回实际的传输方式和 WebSocket 连接信息。前端不得根据固定端口自行拼接地址。

本地管理器提供稳定发现入口：

```http
GET http://127.0.0.1:39980/api/connection
```

该接口返回当前后端 HTTP/WS 地址、Backend ID、rathole 状态和运行摘要。

中转返回经过网关处理后的有效地址，不向浏览器暴露本地后端真实端口。例如：

```json
{
  "transport": "binary",
  "httpBasePath": "/nyxus/backend/backend-7c42",
  "wsPath": "/nyxus/backend/backend-7c42/ws"
}
```

前端支持手动填写 HTTP 地址和高级 WebSocket 地址，作为自动发现失败时的备用方式。自动发现成功后，以服务端返回的连接描述为准。

## 5. 身份、授权与完整交互

### 5.1 三种使用路径

| 路径 | 如何找到后端 | 谁核验使用权限 | 体验 |
| --- | --- | --- | --- |
| 本机前端直连 | 本机连接发现 | 本地入口识别真实 loopback 来源 | 同一台机器打开本地前端，免登录使用本机后端 |
| 公共前端 + Pocket ID | 登录后查看“我的后端” | 中转核验选择资格；后端核验用户证明及本机授权 | 选择已绑定后端后直接使用 |
| 公共前端 + 后端密码 | 最近连接记录、主动公开的列表或输入 Backend ID | 目标后端核验密码与后续会话 | 不要求 Pocket ID 账号或事先绑定 |

同一浏览器会话一次只操作一个选中的后端；换后端必须重建连接，不得复用另一台后端的凭据。本机免登录仅适用于本机页面直连本地入口；公共网站脚本即使连接用户电脑的 `localhost`，也不得凭连接来自 loopback 获得管理员权限。

### 5.1.1 登录前置加载边界

登录不是完整前端加载后的弹窗，而是浏览器启动时的唯一可见页面。入口必须满足以下顺序：

```text
最小登录壳
  → 目标发现/选择
  → 登录方式发现与认证
  → 当前目标能力说明读取与校验
  → WebSocket 连接确认
  → 按能力动态加载业务前端
```

登录壳只包含本机目标、Pocket ID、后端用户名密码、目标后端选择所需的输入框和下拉选择。未认证时不得导入或请求工作台、会话、设置、工具、桌宠、文档和其他业务资源；不能通过先加载完整 `App` 再用 `v-if` 隐藏来满足此要求。刷新、退出、目标切换、旧凭据失效和能力不兼容都必须回到登录壳。业务模块只能由认证和能力校验成功后的动态导入触发。

### 5.2 中转部署方的一次性 OIDC 配置

部署方已有指定 Pocket ID 服务，并有权在其中创建**一个供公共中转使用的 OIDC 应用**；中转配置 `issuer`、`client_id`、必要时的 `client_secret` 和固定的中转登录回调网址。中转交换登录授权码；客户端密钥不下发浏览器、本地后端或管理页。普通 Pocket ID 账号无需创建应用，即可绑定自己有本地管理权的后端。若公共 OIDC 应用尚未配置，Pocket ID 登录不可用，但密码和本机直连仍可用。

中转从指定签发方发现并校验 OIDC 端点，核验登录请求与回调的关联、令牌的签发方、接收方和时效。稳定用户身份采用 `issuer + sub`，不以可变邮箱或显示名作授权键。不得允许请求方自行指定另一个签发方。固定登录回调和中转会话退出入口位于公共部署路径下；不生成每台后端的 OIDC 回调网址。

### 5.3 普通用户首次绑定自己的后端

1. 本地后端用设备密钥向中转证明身份并保持在线；Backend ID 只是路由名，不能证明设备所有权。
2. 所有者在受管理密钥保护的 `39980` 管理页选择中转并发起短时、一次性绑定申请。后端用设备身份提交；管理页显示目标设备、确认链接或代码及有效期限，不要求输入 OIDC 客户端密钥。
3. 用户打开中转的确认页，经指定 Pocket ID 登录；页面明确显示当前账号与目标 Backend ID、设备名称。中转核对申请来自该设备、经本地管理操作发起、未过期且未用过；用户主动确认后才建立关系。
4. 中转记录 `issuer + sub` 与设备身份的关系，后端取得可核验的绑定结果并记录该账号的使用或管理权限；任何一侧尚未确认成功，不得显示“已可使用”。
5. 管理页显示绑定账号、权限和撤销入口。已经绑定的设备新增其他账号或更改权限，必须由有本地管理权或已明确授予管理权的用户批准；不能让第一个猜到 Backend ID 或拿到普通访问链接的人抢占设备。

多台后端可绑定同一个 Pocket ID 账号，授权按设备分别撤销；重连沿用设备身份。设备密钥丢失、重装或解绑后的恢复必须通过本地管理者重新确认，不能靠重复注册同名 Backend ID 恢复权限。

### 5.4 日常 Pocket ID 登录

1. 公共前端经中转跳转到指定 Pocket ID；中转核验回调并建立有期限的用户登录会话。
2. 中转按当前账号的绑定及授权记录返回“我的后端”及在线状态；选中时再次核验权限，不以列表隐藏代替服务端校验。
3. 中转建立只指向选中 Backend ID 的路由会话，向后端提供**针对该设备、短期有效、可核验**的用户身份证明。未经验证的用户名请求头或为中转签发的原始 OIDC 凭据不能直接当作后端授权。
4. 后端核验来源、目标设备、期限、防重复使用条件及本机授权记录，建立自己的使用会话；HTTP 与 WebSocket 后续请求都要核验。只有路由会话不得访问业务。
5. 断开设备清除本设备的使用会话；退出中转账号清除中转会话并使关联的后端使用会话失效。是否也退出 Pocket ID 本身须在界面区分。

后端离线、绑定撤销、授权失效、设备身份变化或登录过期时不回退为免登录；OIDC 不可用时用户可主动选择后端密码入口。

### 5.5 后端密码经中转登录

1. 公共前端提供独立的“使用后端用户名密码”入口；可选择浏览器最近连接、主动公开的设备或手动输入 Backend ID。最近记录不表示授权，未公开的在线设备仍能按 ID 定位。
2. 中转建立到该设备的**路由**关系，仅允许发现、登录挑战、密码提交和续期等登录必需请求；未完成后端登录不能进入业务接口或业务 WebSocket。具体可访问路径须在实施时写入[中转协议](../protocol/relay.md)。
3. 界面显示目标设备，用户输入的是后端用户名密码。目标后端处理挑战、校验和失败等待；成功后签发只供该后端使用的访问与续期凭据，后续 HTTP/WS 由目标后端核验；中转转发但不保存密码。
4. 断开时清除该后端凭据；切换设备必须重新登录。知道 Backend ID 或拥有中转路由会话均不构成业务授权。

密码请求经公共中转转发。HTTPS/WSS 保护公网传输，但当前挑战流程不能保证对中转运营方端到端保密；不能宣称中转“无法看到”密码或登录凭据。用户需要信任所用中转；秘密不得进入中转持久化存储或普通日志。

### 5.6 密码重试冷却与发现限制

只统计用户名密码登录失败，不统计 Pocket ID 登录失败。

- 每连续错误 15 次后冷却 5 分钟。
- 之后每增加 15 次，冷却时间翻倍：10 分钟、20 分钟、40 分钟。
- 最大冷却时间为 1 小时。
- 达到上限后继续错误仍保持 1 小时冷却。
- 成功的密码登录清零错误次数和冷却级别。
- 冷却期间拒绝新的 challenge 和密码提交。
- 冷却响应使用 HTTP `429` 和 `Retry-After`。

后端账号级限制与中转来源限流同时存在，避免单个来源持续占用中转资源。

中转还须针对公开列表、按 ID 查询、挑战及密码提交限制来源请求速率，不能接受客户端伪造来源绕过。账号级等待容易被匿名请求用于阻断真正所有者登录：本地管理页应展示等待状态并提供受管理密钥保护的恢复操作；具体解除规则实施前在协议中确定。公开发现默认关闭，由本地所有者主动开启；关掉后只从公共列表移除，仍允许知道 Backend ID 的人尝试密码登录。管理页须分别说明“公开发现”和“允许远程密码登录”，不可合并为一个开关。

### 5.7 本地凭据重复查看

后端生成或管理的用户名密码可以重复查看，不采用“只显示一次”。

- 凭据保存在本地受保护文件中。
- Linux 使用 `0600` 权限。
- Windows 使用当前用户 ACL。
- 凭据不进入 Git、不写普通日志、不经中转返回。
- 本地管理页和本地命令可以读取并展示。
- 手动修改密码时必须同步更新可恢复的本地凭据记录，否则只能重新生成密码。

## 6. 本地管理器

本地管理器独立托管：

```text
http://127.0.0.1:39980
```

它负责：

- 启动、停止、重启 CheryNyxus 后端；
- 启动、停止、重启 rathole client；
- 展示后端和隧道状态；
- 展示实际 HTTP/WS 端口；
- 展示 Backend ID、登录方式和本地凭据；
- 选择中转、查看设备接入与账号绑定状态；发起或撤销 Pocket ID 账号绑定，管理是否公开发现、是否允许经中转使用后端密码以及密码等待状态；
- 展示 Agent 数量等基础运行统计；
- 提供复制连接信息和配置的操作。

39980 默认只绑定 loopback，不经过 nginx 或 rathole；在 `.chery/config.yaml` 的 `manager.host` 设置 `0.0.0.0` 或内网 IP（或用环境变量 `CHERY_MANAGER_HOST`，优先级更高）可开放内网访问，内网访问必须携带启动日志 URL 上的管理密钥（URL `?token=` / `X-Chery-Manager-Token` 请求头 / 密钥 Cookie），本机回环只读访问仍免密钥。管理密钥持久化（重启稳定，7 天自动轮换 + 24 小时宽限），页面用后从地址栏移除密钥；开放内网访问时页面顶部显示危险警告。后端停止后管理页面仍应可访问，以便用户重新启动后端。

Linux 使用 systemd 注册和管理；Windows 使用无控制台窗口的托盘启动器。托盘启动器点击后调用系统浏览器打开 39980，不使用 Electron 窗口承载管理页。

## 7. Electron

Electron 只负责：

- 加载前端静态资源；
- 提供窗口和桌面桥接能力；
- 连接本地、远程或中转后端。

Electron 不负责：

- 启动后端；
- 管理后端 guardian；
- 注入后端端口和数据库路径；
- 打包后端 bundle、Node runtime 或 `.chery` 模板。

Electron 的连接平台和后端连接目标必须分离。`isElectron` 只能表示运行容器，不能表示“当前一定连接本地后端”。

## 8. 子路径部署

前端、中转和认证回调必须支持可配置的公共路径前缀：

```text
https://example.com/nyxus/
```

不能假定应用部署在域名根路径。

路径前缀必须同时作用于：

- 前端静态资源和构建 base URL；
- `/api/config`、登录、退出和回调地址；
- WebSocket Upgrade 路径；
- 中转后端路径；
- 中转唯一的 Pocket ID 回调网址与登录请求返回地址；
- Cookie Path 和同源判断；
- nginx location 配置。

应用内部不得把 `/api`、`/ws` 或 `/` 作为不可配置的绝对根路径。中转路径示例：

```text
/nyxus/backend/<backendId>/api/*
/nyxus/backend/<backendId>/ws
```

## 9. 安全边界

- 中转只转发 CheryNyxus `/api/*` 和 WebSocket 控制面；中转自身还承载账号登录、设备绑定确认与发现接口。
- 中转不记录密码、Cookie、授权码、access token、refresh token 或 client secret。
- Pocket ID client secret 只保存在中转受保护的配置中，不下发给后端或浏览器；不承诺中转无法获知经其转发的密码。
- rathole 设备连接和用户登录是不同的认证层。
- HTTP 与 WebSocket 使用两个只对中转机 loopback 可见的 rathole 私有映射，不直接开放动态公网端口。
- 隧道连接不能因为本地代理来自 `127.0.0.1` 而获得本机免鉴权管理员权限。
- 隧道入口必须使用专用远程认证边界或等效的可信来源标记。
- 本实现采用专用远程 HTTP/WS 入口；隧道只能进入该入口，且该入口始终要求用户认证。本地入口继续保留既有 loopback 行为。
- 39980 不对公网开放。
- 中转必须限制注册、连接、转发路径和请求速率。
- “我的后端”列表只能向已登录且获准使用的账号返回；公共发现只含所有者主动公开的设备。关闭公开发现不阻断按 ID 登录，但任何发现、选中或路由绑定均不授权业务操作。

## 10. 验收重点

### 自动验收

- 后端修改 HTTP/WS 端口后，前端通过发现接口仍能连接。
- 中转不暴露本地真实端口。
- `/api` 和 WS 路径之外的请求被拒绝。
- 一台设备能由普通 Pocket ID 账号通过本地管理申请绑定；其他人只有确认链接、Backend ID 或 Pocket ID 登录状态时不能抢占授权。
- 同一账号可绑定多台设备；未获授权账号不能从“我的后端”看到或选中它们，直接调用代理业务接口也不能绕过后端授权。
- Pocket ID 和目标后端用户名密码两种远程登录路径可独立使用；未配置 OIDC、后端未公开发现或 Pocket ID 故障时，知道 Backend ID 的用户仍可尝试密码登录。
- 公开发现默认关闭；所有者启用时设备出现在公共列表，关闭后从公共列表移除但按 ID 的密码登录仍可用。
- 中转路由会话不能取代后端登录；远程代理业务接口及 WS 对无后端授权者拒绝。
- 密码第 15 次失败进入 5 分钟冷却，冷却最长 1 小时。
- 冷却期间不能通过重新获取 challenge 绕过限制。
- 中转来源限流与本地受保护的等待状态查看、恢复操作可用；匿名请求不能无限延长账号等待而无恢复途径。
- 隧道流量不能触发 loopback 管理员权限。
- 公共网站脚本直连用户的 localhost 不能取得本机免登录权限；本机提供的前端在本机直连仍可免登录。
- 39980 后端停止后仍然可访问并可重新启动后端。
- `/nyxus/` 等非根路径部署下，静态资源、API、WS 和 OIDC 回调均可用。

### 人工验收

- Windows 托盘启动器不打开原生控制台窗口。
- 点击托盘菜单可在默认浏览器打开 39980。
- Linux systemd 可以开机启动和自动重启。
- 用户能通过本地管理页和命令重复查看连接信息及凭据，并识别 OIDC 账号绑定状态、公开发现与密码入口是否开放。
- 浏览器和 Electron 均能在本地、远程和中转模式之间切换。
- Pocket ID Passkey 登录、绑定确认、选择多台已授权设备、断开后端、退出账号和重新登录体验清楚；密码路径可按最近记录、公开列表或手动 Backend ID 定位目标。

## 11. 现有实现与落地边界

本节用于避免把目标需求误读为现有能力；实施时以第 5 节为验收目标，以[中转协议](../protocol/relay.md)维护最终请求路径、字段、错误及会话条件，不在需求文档中预设尚未实现的接口名称。

- [`relay/src/server.ts`](../../../relay/src/server.ts) 的 `handleHttp()` 当前公开列出全部在线后端，`requireBoundBackend()` 只检查浏览器路由会话；[`relay/src/config.ts`](../../../relay/src/config.ts) 尚无 OIDC 应用配置、账号—设备关系及按归属筛选。中转设备签名验证见 [`relay/src/identityStore.ts`](../../../relay/src/identityStore.ts)，不能把设备身份当作用户身份。验证入口：[`relay/test/relay.test.ts`](../../../relay/test/relay.test.ts)。
- [`src/service/auth/index.ts`](../../../src/service/auth/index.ts) 的 `OAuth2Auth` 当前由后端自身处理 OIDC 和密码：配置用户名时优先采用密码模式；本地入口按真实来源地址放行，远程专用入口不豁免。应将中转 OIDC 账号传递与后端授权设计为独立、可核验的机制，保留密码路径及本机直连。验证入口：[`test/manager/server.test.ts`](../../../test/manager/server.test.ts) 和对应服务认证测试。
- [`manager/src/page.ts`](../../../manager/src/page.ts) 当前提供中转连接、绑定、公开发现及密码策略入口；管理入口在 [`manager/src/server.ts`](../../../manager/src/server.ts)。每台后端不再配置 OIDC 客户端。
- 前端现有密码登录入口在 [`web/src/features/auth/ServerLoginDialog.vue`](../../../web/src/features/auth/ServerLoginDialog.vue)、[`web/src/stores/auth.ts`](../../../web/src/stores/auth.ts)。需增加独立的 Pocket ID 路径和两种设备选择视图，并区分本机直连与远程经中转。前端登录说明见 [`docs/frontend/auth-login.md`](../../frontend/auth-login.md)。
