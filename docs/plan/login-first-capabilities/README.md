# 登录优先启动与后端能力分级

**文档创建时间：** 2026-09-29T14:54:17+08:00

**状态：** 执行中

## 目标与边界

首次使用者先选择可连接的服务并看到该服务实际支持的登录方式；认证成功并确认连接后，客户端获取后端实际能力和必要配置，仅启动可用功能需要的代码、请求与订阅。已有有效登录可自动恢复；本地免登录仍需先确认目标与可连接性。后端重启、换服务和能力升降档后，界面与已保存数据收敛到新服务的真实状态。

本文是**待实施计划**，不声明已有五个运行等级。MCU 文档中的 L0–L4 是开发分期，P0–P2 是实现进度，树/对话/精简是显示模式；三者都不能直接用作本计划的后端运行等级。本期只落地登录后的**基础业务档和完整业务档**，其余档位不是本次承诺；未来按实际能力扩展。

范围：**浏览器端**服务选择/发现、经中转统一处理的 Pocket ID 登录、指定后端用户名密码登录、本机 loopback 直连、认证后的启动能力说明、后端真实启用及拒绝边界、按需加载、重连及数据恢复。保留权威时间线与现有 Lite 连接级投影的独立含义；按需加载不是把完整 Web 界面改成 MCU Lite 协议。不把每台后端的 OIDC 预配置当作新版登录入口；中转账号、设备绑定、后端密码和本机管理权限按[独立后端与中转网关需求](../../shared/architecture/relay-gateway-requirements.md)分别处理。

已有事实和冲突：[`src/service/auth/index.ts`](../../../src/service/auth/index.ts) 仍是当前后端自身密码/OIDC 入口；新版需求要求公共中转统一 Pocket ID、后端密码独立经中转登录，因此不能沿用“远端地址即后端密码/OIDC”的旧前端假设。另有 [`web/src/features/auth/ServerLoginDialog.vue`](../../../web/src/features/auth/ServerLoginDialog.vue) 当前只分本地和远端密码；[`web/src/application/runtime/startApplicationRuntime.ts`](../../../web/src/application/runtime/startApplicationRuntime.ts) 的连接成功回调会立即刷新配置、任务、交互、会话；[`web/src/App.vue`](../../../web/src/App.vue) 入口仍同步引用部分重型功能。实施前以新版共享需求和 `docs/shared/protocol/relay.md` 定稿字段，避免把目标需求误当成已有中转接口。

## 已确认的产品决断

这是浏览器存量认证、启动与设置/功能入口的大模块调整。依照项目规则，已由用户在以下两种方式中选定改动方向。

| 维度 | 破坏性修改（推荐） | 直接更新 |
| --- | --- | --- |
| 界面体验 | 用单一轻量入口替换旧的“完整桌面先启动、弹出登录窗”路线；不残留双入口 | 保留现有桌面内登录弹窗及启动路径，新入口叠加；容易让用户面对两种登录流程 |
| 实现及验证成本 | 一次改造浏览器启动状态和连接生命周期；共享前端须先等 Electron 移除计划交接 | 浏览器旧/新启动路径同时维护，条件分支和回归面更大 |
| 数据与配置 | 保留现有服务地址/凭据及会话事实；决定是否迁移旧本地登录偏好，旧的 UI 路径直接移除 | 保留原有偏好及展示方式，不需一次性迁移；能力缺失时旧路径仍可能提前发请求 |
| 长期演进 | 单一事实源便于后续新增等级和登录方式 | 必须明确双轨退出时间及消除死代码的验收点 |

**D1：破坏性修改。** 用单一登录优先入口替换旧的先启动完整应用、后置登录弹窗路径，不保留双轨兼容入口；不清除仍在使用的服务地址、认证凭证或已保存会话。

**D2：登录在所有业务等级之前。** 服务发现、服务选择、认证、获取启动能力说明和不兼容提示都是始终可达的顶层入口，不能列入任何可关闭的业务档位。业务分级只在认证/本地信任确认后生效。

**D3：首批两种业务档。** 基础业务档保证基础会话、待处理审批/提问和已提交历史可用；完整业务档保持现有业务能力。具体可关闭功能以本计划的能力矩阵为首批范围，之后增档只追加业务能力预设，不改变登录入口。

**D4：旧后端缺少能力说明时提示升级。** 不以“旧版等于完整能力”或猜测 RPC 是否存在继续启动业务；目标地址、登录状态和重新选择服务入口保留。错误提示同时说明需要更新后端而不是反复重试。执行任一小任务前仍需报告其复杂度和需要的模型能力，由用户确认执行 Agent 或模型。

**D5：浏览器唯一产品入口，Electron 拆除另立计划。** 用户决定同期彻底移除 Electron，但两任务在共享文件上按序接力：移除计划先完成原生桥、共享前端清理及 R5 自动和必要人工回归，本计划随后实现浏览器登录优先和业务分级。可与其并行的仅是本计划 A/B 的只读与协议工作、C 的后端工作；不能两边同时改前端入口。移除计划的用户审批不阻塞代码交接。此选择取代此前“保留旧 Electron 完整档路径”的临时边界。

## 拟定流程及必须保持的行为

1. 浏览器最小页面判定当前同源服务或中转入口及可恢复的目标：同源本地后端、已绑定的中转后端、手动提供的前端访问地址；服务不存在/离线时停留在可重试的选择页。中转在线列表不是已经登录。首次选服务；已存目标可预选，凭据有效时允许自动恢复。手动远端若不在当前 origin，先导航到该服务的受控前端入口，再在那里认证；不把跨域 API 访问当作默认能力。本地管理器是独立的本机发现入口，不要求公网网页跨域读 `127.0.0.1:39980`。
2. 针对**选定目标**读取公开登录方式；本地 loopback 信任与远端强制认证边界不变。OIDC 经目标后端发起跳转和回调，回到原服务及允许的页面；密码继续走现有挑战机制。获取失败不得凭地址猜测必然支持密码或 OIDC。
3. 检查已有会话或完成登录；凭证有效且启动能力说明可解析、连接成功才进入业务启动。认证完成但 WebSocket 失败仍展示重试/改服务；不得把 `connected` 单独认作已登录。登录方式不可用或版本不兼容时应留在轻量入口。
4. 拿到后端的启动能力说明后校验协议兼容性，选择可用的最小业务入口，再下载相应页面代码和读取首屏数据。后续功能在打开时加载，未启用的功能既不导入重模块，也不发该功能的请求或建订阅。
5. 浏览器重连重新发现地址和身份；后端实例或能力版本变化时刷新能力，撤销失效订阅并恢复仍支持的功能。换服务时先停旧连接、请求和缓存，防止不同服务数据串用。
6. 升档重读已持久化时间线及按需详情；降档保留后端已提交事实，不将摘要冒充完整数据。没有持久化的临时输出无法承诺升档补回。协议兼容失败、能力查询失败、功能未启用三类错误应分别可见且有明确处理方向。

## 契约草案的约束（字段仍待首批任务定稿）

- **登录前**：复用 `/api/auth/capabilities` 作为目标后端公开的方式发现；本地管理器和中转发现继续由各自 owner 管理。认证选择不能依赖受保护的 `/api/config`。核对 OIDC 与密码同名 `/api/auth/login` 的 HTTP 方法和现有代理行为，再确定客户端跳转方式。
- **登录后**：在现有 `/api/config` 的已认证响应里增加**小而稳定**的启动能力说明，不增加冷启动往返。已有连接、地址、预设字段的责任不变；不将完整设置、模型/工具清单或全部 RPC 方法元数据塞入启动说明。远端和本地使用同一能力形状，返回权限仍按各入口认证边界；前端从同一次发现结果取得本次实例的地址与能力，防止重连时混用。
- **三种不同概念**：运行级别是启动预设；“实际能力”由已启用服务/方法及配置计算，前端按它开关；连接级 `profile=lite&v=1` 是 MCU 投影，不能与 Web 显示模式或后端运行级别混淆。模型、工具组和用户权限等可变或会话相关信息在对应请求中读取，不靠一个全局布尔值代替。
- **版本与失败**：不编造覆盖所有接口的单一整数版本；只发布必须协商的独立协议版本及最低启动契约。旧后端缺少能力说明、说明格式不支持或必需能力缺失时提示升级/不兼容，不启动业务；未知可选能力按不可用处理。后端对禁用能力的 RPC 必须给稳定错误，不能仅依赖前端隐藏入口。
- **验证边界**：后端数据完整性与增量恢复按[权威时间线](../../shared/architecture/canonical-timeline.md)；Lite 投影按[MCU Lite 协议](../../shared/protocol/profiles/mcu-lite.md)。能力说明的长期事实写入[共享协议](../../shared/protocol/README.md)，本计划不成为第二份正式协议。

## 首批业务能力边界（规划决策）

**顶层恒定能力**：服务发现与选择、公开登录方式、密码/OIDC/本地信任、`/api/auth/me`、经认证的连接说明、能力说明、明确错误及重新选择服务。它们不出现在业务能力数组中，不受业务档开关影响。登录 UI 可按服务实际登录方式决定显示哪种入口；Pocket ID 是当前服务的 OIDC 身份提供方，不是一种额外的业务档位。

首批用“能力集合”驱动两个业务预设，名称只作对人说明；实际启动档由后端配置选定，前端只消费后端**本次实例返回的有效能力**。下表为实现与验收的最小集合，B 批次核实各方法组的闭包并迁入唯一协议 owner；不能因为当前某个方法内部同时调用多个模块就直接拦截它。

| 业务能力（建议标识） | 基础档 | 完整档 | 适用面与必须保留的事实 |
| --- | --- | --- | --- |
| `chat.core` | 开 | 开 | 会话目录、打开/发送/暂停/续接与已提交消息；Agent 必要 registry、canonical 写入及运行恢复始终保留。 |
| `interaction.respond` | 开 | 开 | 待办收件箱、审批和提问的处理；否则运行中的会话可能无法继续。 |
| `timeline.read` | 开 | 开 | 会话历史与基础分页，已有完整记录不因低档清除；包含读回已提交节点的必需路径。 |
| `timeline.graph` | 关 | 开 | 树与审计视图的高级图展示；投影/显示开关不改变后台 canonical 写入。 |
| `task.overview` | 关 | 开 | 任务概览、统计与任务中心专有请求；不能禁止 `chat.core` 所需的目录或活跃会话状态。 |
| `workspace.files` | 关 | 开 | 工作台文件浏览/读取及其 UI；不改变 Agent 本身已有的文件工具执行语义。 |
| `terminal.session` | 关 | 开 | 用户显式创建的终端会话与终端窗；降档前按原有关闭规则结束连接。 |
| `settings.manage` | 关 | 开 | 应用内设置操作；基础档要调整档位时由后端受控配置/管理入口完成并重启，登录与连接本身不依赖设置页面。 |
| `media.attach` | 关 | 开 | 用户上传并附加图片/音视频入口；已提交会话中的历史媒体引用不因降档删除；具体模型/工具仍由原能力检查决定。 |

首批不因为禁用一个展示功能就把整套数据库、canonical 时间线、审批、会话执行或原生工具注册全部关掉。业务方法先梳理为“本档需要的内部依赖”和“只服务可选界面的入口”；在后端启动时跳过可安全独立停用的模块初始化/后台任务，并以方法级拒绝阻止禁用功能的显式调用。不能安全关闭的共用内部模块仍保留，并在资源报告中如实记为未节省。所有业务档保持同一持久事实模型，降低业务档只限制执行入口与对外读取，不丢弃已保存内容。运行档是**后端启动配置**；变更须经已有安全重启/等待活动结束流程生效，不在活跃执行中热切换方法集合。

## 拟定跨端契约与启动状态（B 批次写入权威文档）

以下是本期必须交付的合同约束，而不是声称已有的 wire 字段。正式字段、校验和版本只在[共享协议入口](../../shared/protocol/README.md)的权威目标定稿并由类型和端到端测试共用，不能让前后端各自解析一套随意 JSON。

1. **公开发现**：所选目标 `GET /api/auth/capabilities` 返回实际可用的 `password`、`oidc`；本地是否免登录由同源本地目标及后端策略确认，不能只看用户输入字符串是不是 `localhost`。中转先通过当前同源前端的列表/绑定接口选后端，再在所选后端公开路径取登录方式；手动异源目标先导航到对方的前端 origin，禁止在本页跨源试探认证 API。没有登录方式且非可信本地目标时给明确“服务配置不可登录”错误；公开响应不含内部配置。
2. **认证与目标身份**：目标描述包含本地/直连/中转来源、稳定目标键、公开路径与目标 origin；中转会话只绑定一个 Backend ID。密码仍用 POST challenge/login 的 Bearer token；OIDC 用 GET login/callback 的 HttpOnly Cookie，回调后 GET me 验证；两种身份的 HTTP/WS 地址必须指向同一目标。切换目标先丢弃当前活跃凭据在旧目标上的使用权，保留存储中的旧地址/用户名和用户显式保存的密码偏好，不把旧 token 或 Cookie 主动发给新目标。
3. **受保护的启动说明**：`GET /api/config` 保留现有连接字段，附加一份固定形状的 `bootstrap`；至少含说明版本、后端实例标识、配置/能力修订标记、运行预设名、按能力表得出的有效业务能力集合及需要独立协商的协议版本范围。实例标识不能是凭据，重启后应变化；修订标记在能力变化后变化，避免同一实例的旧缓存误用。HTTP `no-store`；客户端拒绝缺失、未知必需说明版本和缺少 `chat.core`/`interaction.respond`/`timeline.read` 的响应。已有独立协议（如 MCU Lite v1、配置保存 v2）不重新编号为“万能版本”。
4. **能力集合计算**：后端以启动预设为上限，与实际注册/启动成功的服务、依赖闭包及必要配置取交集；不会把尚未启动或配置缺失的功能声明为可用。同一档可以有不同的有效可选能力。权限等会因用户变化的信息由对应请求判定；能力说明不替代后端鉴权。启动前校验必需能力闭包，不满足时拒绝进入业务就绪态或给可诊断启动错误，不能公告不可用组合。
5. **拒绝和版本**：方法根本不存在仍保留 `METHOD_NOT_FOUND`；方法存在但本档停用返回单独、稳定的“功能未启用”协议错误；说明版本不兼容由前端在开 WS/业务读取前展示错误，避免循环连接。权限不足/认证失效单独归类，分别进入登录或重试。重连遇到不兼容不应以固定间隔永远重试。
6. **刷新与恢复**：每次新连接和重连从同一目标重新拿 `/api/config`，比较目标键、实例及修订标记；不依赖向客户端推送尚未实现的“能力改变”通知。能力变化只在后端安全重启或经明确修订时生效；降档清除前端不再允许的订阅和暂存请求，升档按权威 revision 重取历史、详情和待处理交互。旧的已提交数据可补回，未持久化的临时 delta 不做保证。

前端启动的单一控制流程：`selectTarget → discoverLogin → checkExistingIdentity/login → readBootstrap → validate → connect → startAllowedRuntime → ready`。每个异步步骤绑定当前目标和递增代号；用户切目标或登出时作废旧步骤的回写，避免旧响应在新服务上打开页面。`readBootstrap` 可能拿到 401：回登录；拿到网络错误：留选择/重试页；拿到格式或版本错误：提示升级；拿到不含必需能力：显示后端配置问题。只有 `ready` 可以触发业务组件导入和订阅。断线后已有界面可保留最后的已知内容及重试入口，但停止新业务命令；重连成功后先重验身份和能力，再按变化恢复。

前端资源减少分两层验收：浏览器登录前只载入最低限度的框架、目标选择和登录表单；登录后基础档只载入基础会话及审批所需代码和数据；完整档的图形、任务、文件、终端、设置等按打开动作再加载。不能只看页面是否隐藏，还要分别检查静态导入链、网络模块资源、初始 RPC/订阅与卸载后资源清理。Electron 产物移除属于独立计划的验收。

### 实施交接：各批关键入口、步骤与定向检查

**A · 复核**：从[中转协议](../../shared/protocol/relay.md)与[`relay/`](../../../relay/)公开列表/绑定实现核对网页前端是否有真实消费者；记录无服务、OIDC-only、password-only、同时启用两者的现有结果。把现状冲突回填给[中转计划的 H 验证任务](../relay-gateway/README.md)，不擅自把本期未实现的登录优先体验写成它已完成。记录旧地址、token、用户名、记住密码等键及其目标归属：旧单地址可预填新目标；token 只在对应地址经 `/api/auth/me`/认证确认后使用，切换目标不复制凭据；遗失的登录方式不会导致自动退回密码表单。基线从现有可执行的构建文件体积、入口静态导入与测试里的初始 RPC 计数获取；实际下载/内存体验由用户最后验收，不用无权限的浏览器自动化补数据。

**B · 定契约**：在[共享协议](../../shared/protocol/README.md)设唯一权威说明，定义 `bootstrap` 的版本及必需字段、能力标识与内部方法闭包、基本/完整预设、可用性计算、认证方式、错误码、重启变化、旧后端拒绝及历史持久不变量；用 [`packages/protocol/src/`](../../../packages/protocol/src/) 的现有方式定义类型/校验，服务器和客户端共用。校验样例至少覆盖未知可选能力（忽略）、缺必需能力（拒绝）、未知说明版本（拒绝）、同档服务初始化缺失（不宣称功能）、实例重启/修订改变（重取）。与配置保存 v2、Lite v1 的作用域严格隔开。定向验证从现有 `test/protocol-completeness/` 与 Web 协议测试入口添加有语义的契约断言。

**C · 后端**：在[`src/utils/config.ts`](../../../src/utils/config.ts) 的 server 配置定义并校验业务档启动预设（未配置默认完整档，保持现有体验）；在[`src/worker.ts`](../../../src/worker.ts) `bootstrapAgentRuntime()` 前判定档位，把仅服务可选功能的预热/后台任务依赖先找全，再有证据地停止；在[`src/service/index.ts`](../../../src/service/index.ts) 的 `registerAllHandlers`、定时器等启动点建立能力与具体方法的映射。在[`src/service/message/router.ts`](../../../src/service/message/router.ts) 统一拒绝本档未启用的**显式请求**，而不是各 handler 各写不同错误；保护会话、交互、权威写入及运行恢复所需内部依赖不受影响。向[`src/service/http/index.ts`](../../../src/service/http/index.ts) 的认证后 `/api/config` 增添 `bootstrap`，并检查 `OAuth2Auth` 的公开方式计算与远端认证要求。配置改档走启动/安全重启入口；重启改变实例 ID，修订随实际能力变化；若部分可选服务初始化失败则能力公告降级且错误可查，必需服务失败不伪装就绪。定向测试选 [`test/service/`](../../../test/service/) 的 HTTP/远程入口和 router 契约，加基础档禁止可选 RPC、完整档可用、远端 401、公开方式无敏感字段、服务跳过启动、跨重启仍可读已提交数据断言。

**D · 轻量入口/认证**：在[移除计划 R5 自动及必要人工回归](../remove-electron/README.md)完成后，让[`web/src/main.ts`](../../../web/src/main.ts) 不同步引入业务 App/重 CSS/非登录组件；入口先判目标及服务发现，再按登录方式加载表单；真正的业务 [`web/src/App.vue`](../../../web/src/App.vue) 只在认证与能力说明有效后载入。复用[`web/src/services/platform.ts`](../../../web/src/services/platform.ts) 的地址路径构造，目标描述区分同源本地、同源中转路径和手动远端 UI；中转先绑定 Backend ID 后取公开登录方式，手动异源先导航目标公开 UI，不进行本页跨域认证。把[`web/src/stores/auth.ts`](../../../web/src/stores/auth.ts) 和 `ServerLoginDialog` 的地址=远端=密码假设拆开，使用 GET/POST 同名登录端点的正确方法；OIDC 回调验证 Cookie 身份，密码登录沿旧挑战流程；对状态/错误分别显示“选择服务/登录/正在连接/需升级/可用”。旧单地址和用户名安全预填，显式保存的密码偏好不静默删除；旧 token 必须先验证其对应目标。定向测试从[`web/test/auth/`](../../../web/test/auth/) 与[`web/test/services/`](../../../web/test/services/) 扩展，覆盖两种身份、OIDC 回调目标、401、换服务、旧偏好迁移、跨源先导航和中转子路径；真实交互留 G。

**E · 业务门与资源拆分**：定义一个由已验证 `bootstrap` 派生的能力状态，业务视图只消费该状态；在[`web/src/application/runtime/startApplicationRuntime.ts`](../../../web/src/application/runtime/startApplicationRuntime.ts) 将 `configApply.refresh`、`taskOverview.reopen`、`interactions.refresh`、`chats.startup` 等按基础/可选模块和当前 surface 拆分，先固定首次连接的顺序，再处理重连。`App.vue`、`DesktopSurface.vue` 及重型页面只在可用且打开时动态导入；基础档仍展示清楚的会话/历史/待处理入口，禁用的设置/任务/树/终端等界面有明确的“当前服务未启用”说明而不是空白窗口。用户操作前再次读当前能力和连接状态，避免旧 UI 持有的命令绕过门控。定向测试用模块加载记录和 mock WS/RPC 统计断言“登录前无业务模块与业务 RPC”“基础档无可选初始化”“完整档按打开动作才加载”，同时测卸载后无孤立订阅；不把构建成功当资源验证。

**F · 生命周期/恢复**：在[`web/src/services/ws.ts`](../../../web/src/services/ws.ts) 及 [`web/src/stores/connection.ts`](../../../web/src/stores/connection.ts) 区分临时断线、凭据失效、能力说明不兼容和切目标；切目标必须禁止旧 WS 待处理请求向新服务重发。全量清理旧服务的 [`web/src/stores/chats/index.ts`](../../../web/src/stores/chats/index.ts) 订阅/目录、交互状态及其他缓存；同一浏览器页面中的旧请求响应也必须因目标代号变化作废。相同目标重连复用 root revision 和权威快照恢复，实例变更/升档补读 tree、详情及权限允许的历史，降档丢弃仅客户端的可选缓存并停止其订阅，不改数据库；有进行中的命令按已确认结果对账，不复用另一个目标的 `requestId`。定向测试覆盖四类重连、同服务升降档、切 Backend ID、迟到响应、审批收件箱恢复、被精简的已提交详情补读与无法恢复的临时 delta。

上述每批是**可交接的实施方向**，不是对未修改代码的既成声明。每批开始时把当前实际符号、正式协议字段、精确步骤和定向测试路径写到当批未完成小任务文档；变更共享文件要核对仍在执行的其他计划，不覆盖他人工作。

## 验收口径与最终综合验证准备

- **入口**：首次进入可选同源本地/当前中转的在线后端/手动公开前端地址；异源目标先导航其前端，API-only 目标显示需要同源前端或转发；发现失败、离线与认证失败有不同说明；已登录恢复不重复要求输入。登录及能力说明始终可达，不随基础/完整业务档关闭；认证成功但业务连接失败不误报完成。
- **登录**：目标仅支持一种方式时不显示不可用方式；双方式同时支持时均可进入；Pocket ID 沿标准 OIDC；本地免登录仍不向远端继承信任；换目标不带旧 token/Cookie/业务缓存。
- **能力**：首批只有基础/完整两档业务预设，后端报告当前档及真实能力；同档配置缺失时不误开；旧后端缺说明提示升级；后端禁用 RPC 有可断言拒绝；Lite profile、Web 精简展示、业务档互不混用。基础档仍有会话、交互和已提交历史，并允许用户理解为什么看不到设置/图表等可选功能。
- **资源**：自动化对同一场景比较入口静态导入、可重现的首屏模块和 RPC/订阅数量；用户在真实环境按相同条件比较“最小入口、登录后基础/完整首屏、主动打开重功能”的网络资源字节数与内存/运行体验。基线取得方式先由 A 明确，实际数值和可比条件在 G 记录；不能以隐藏按钮、编译通过或主观感觉宣称节约，也不预设安装包会缩小。
- **恢复**：重连/后端重启/能力变化后，已保存事实可重读；缺失的临时文本仍标为未知，权限或能力取消后不能继续发送旧操作。浏览器远端子路径、同页面切目标与本地管理器场景均包含在回归内。
- **自动验证**：定向测试入口在 [`test/`](../../../test/) 与 [`web/test/`](../../../web/test/)；实现结束后综合执行 `pnpm test:backend`、`pnpm test:web`、`pnpm test:protocol`、`pnpm type-check:all`、`pnpm web:build`、`pnpm docs:test`、`pnpm docs:check`；新增中转契约才运行 `pnpm relay:test`。具体命令及关键断言行在 G 创建时按实际文件回填。用户亲自做真实浏览器交互与视觉验收；未经明确允许不启动浏览器或读取图片。
