# 最终手动验证手册

## 前置条件

- 使用最终工作树启动后端、Web 和 Electron。
- 准备至少 20 个根任务和 50 个 Agent，覆盖运行、等待、完成、失败和待用户决定状态。
- 打开可观察 WebSocket 消息与请求次数的开发工具。

## 操作与通过标准

1. 浏览器和 Electron 分别打开任务中心，核对根任务聚合、筛选、状态、待办上下文和详情跳转；内容一致且入口无歧义。
2. 保持 20 根任务/50 Agent 空闲 60 秒；不得出现周期性的 overview、timeline 或 interaction 请求。
3. 依次触发 Agent 状态、关键事件和待办变化；每次只产生与变化相符的有界增量，无全量快照风暴。
4. 模拟断线后恢复，再制造 revision 缺口；界面应自动恢复到一致状态，且订阅在关闭界面后释放。
5. 在窄窗口、长文本和多待办情况下检查浏览器/Electron；内容可读、可滚动，操作控件不被遮挡。

## 记录

在 `verify/out/` 保存版本/提交、日期、数据规模、60 秒请求统计、增量消息摘要和双端结论。失败项返回父计划登记新的修正子计划。
