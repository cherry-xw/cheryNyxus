## 2. 必须覆盖的错误与并发序列

每条是需测试的风险，不表示当前都已复现：

1. 保存 A 配置→编辑成 B→A 的成功结果迟到：不清除 B 草稿，不把 A 的试用成功当 B 成功。
2. 选择图1、图2→图2先上传完成→切会话→图1迟到：保持原插入顺序，不写入新会话。
3. 提交消息→服务端已持久 ACK 丢失→重试：只有一条输入和一次有效执行。
4. 生成远端成功→本地写盘失败→用户重试：只恢复下载/保存，生成调用计数不增加。
5. 取消请求→远端仍返回→父会话已停止：可记录迟到结果，不能恢复父任务或覆盖停止事实。
6. 子完成→主分支切换→重连再次送完成：结果只投递一次且归正确 deliveryChatId。
7. 打开同一文件预览于两窗→关闭一窗：另一窗仍可读，不被错误 revoke 或清理。
8. 删除子任务→主会话持有结果→清理：主成果仍存在；删除只是解除相应引用。
9. AI 配置与 Web 同时保存：共享版本冲突机制，不允许后提交者静默覆盖。
10. 工具只接受图片但执行参数不是理解协议：不能自动前置调用；报告映射未配置。
11. 按张数请求三图但只收到两图→收到重复完成消息→恢复结果：成功资产不重复、数量差异如实记录，不自动补生成；缺失文件只能重试可取得的下载/保存，明确新生成另建请求。只控制最多三图且正常返回两图时不虚构第三图失败。
12. 按正式迁移顺序，在资产/消息/工具任务/配置各阶段中断→重启：按提交边界恢复，不能开放混合协议写入。
13. Gemini混合文字/图片、Images专用输出、Responses图片工具、Imagen与Seedream/MiniMax代表型号：分别解析且输出统一资产，不用一家响应样例代表全部协议。
14. 原图适配参数修改后回看旧消息：旧版本及请求事实不改变，新增适配结果有新版本ID。
15. 服务删除或凭据撤销后操作重试：使用原操作参数，但重新验证有效权限和凭据；不偷换另一服务。

## 3. 开发检查入口与时机

- 实施期间每项完成只做必要最小校验。功能、文档与旧消费者全部落实后，先逐项填写“需求完成核对”，再启动集中类型检查、测试与构建。
- 使用仓库现有 `pnpm type-check`、`pnpm web:type-check`、后端/Web/协议测试及受影响插件构建；根据实际改动选择测试文件，不以空测试/实现镜像测试充数。
- 自动覆盖配置保存/采用、能力选择、资产授权、parts 顺序、任务结果、迁移与失败恢复；UI 的异步状态可测纯 model/controller，但不启动浏览器、不用 DOM/CSS 结果冒充视觉验收。
- 文档检查直接入口为 `node --test scripts/docs/tests/*.test.mjs` 与 `node scripts/docs/check.mjs`，等价于根 scripts 中对应命令；包管理器可能触发环境初始化时采用直接入口，避免并行初始化冲突。
- 真实接口使用隔离测试资产、授权凭据和明确请求数量；记录请求身份、模型、参数、响应状态、保存结果及用量，不保存密钥。离线 mock 通过不能声明服务商已验证。

## 6. 尚需补齐的外部证据

本次必须分别验收Google Gemini图像输出、Imagen、OpenAI Images、Responses图片工具、豆包/Seedream、MiniMax及已支持协议的自定义地址。每条接口选官方可用代表型号，按实际操作检查输入、生成/编辑、输出保存、错误和后续引用。尚未实现与尚未授权实测分别列出，不以一家通过宣称全部支持、不静默缩小范围。覆盖混合文字+图片、多图、专用接口及支持的流式/异步方式。新型号沿既有协议接入不应重写Web、文件或角色分工。

各厂商协议依据、代表模型及配置限制统一见[模型能力说明](../../backend/agent/model-capabilities.md)的“文件服务与适配器契约”一节。用户举出的型号用于说明范围，不直接作为已验证的 API 值；协议资料和模拟请求测试不能替代真实账号、地区及中转服务的可用性验证。

本批批准包含连续产品开发，不包含具体付费测试调用授权。准备好模型、请求数量、资产与预算后获取调用授权；没有账号的项目记录实测阻塞，不能伪造通过。

OpenAI Images 与 Responses 图片工具的实现入口为 `service/fileServices/adapters/`；实际生成/编辑格式、参数、输出保存及中转差异仍需用选定型号验收，不将适配器登记等同于真实调用通过。

MiniMax 文生图/图生图官方正文已读取并用于设计参数，真实端点与中转兼容性尚未调用。已有 `verify/minimax-image-e2e.mjs` 仅是待核对资产，不能直接视为适配新协议的验证结果。
