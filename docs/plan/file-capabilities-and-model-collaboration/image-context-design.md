**文档创建时间：** 2026-10-16T17:25:46+08:00

**用途：** cheryNyxus 图片上下文的已确认功能、UI 与 UX 设计及验收条件。代码与验证进度由总任务维护；不授权真实识图、生成、浏览器操作或生产变更。

当前恢复信息只在[总任务入口](README.md#当前恢复检查点)维护。现行规则见[模型能力与媒体处理](../../backend/agent/model-capabilities.md#全局文件与上下文策略files)，设置保存规则见[设置中心](../../frontend/settings.md#保存与生效状态)。本文独占新增图片保留方案及其交互定义；原任务的通用上传、版本、交付规则继续引用[前端交互](frontend-ux.md)和[UI 适配](ui-adaptation.md)。

## 1. 目标、范围与结论

目标是让用户能设置图片在几轮之后不再自动发送给模型；图片退出时留下可辨识的文字，后续确实需要视觉细节时能够重新读取原来的固定版本。

推荐组合：**按用户轮数保留 + 到期用描述替换 + 明确重新读图 + 文件大小与上下文限制**。原件、持久消息、发给模型的本次内容分别管理。

- 用户要求：允许自定义退出时机，已确认默认按含首次发送的 3 轮过滤。
- 推荐默认：3 轮，包含首次发送轮；可改为 5、10 等。默认复用已有描述，不为补描述自动新增模型调用。
- 推荐范围：图片独立配置；不顺带改变 PDF、音频、视频等文件的携带策略。
- 输入图片、被重新引用的生成图片、工具返回且明确选中读取的图片，都使用同一套固定版本与权限规则。
- 本文不实施聊天模型原生图片输出。该路径尚未完成的事实必须保留；未来接通时应复用本方案，不能将“能管理图片”写成“已能原生生成图片”。
- 不增加新的一级设置 Tab、独立图片管理工作台、后台全库识图或永久钉住图片功能。

实施复杂度 4/5：跨消息、配置、权限、文件处理、压缩与前端状态；适合沿用已确认的当前模型，需有跨模块设计和失败恢复分析能力。本次文档整理复杂度 2/5。

## 4. 功能规则复盘

### 4.1 存储、请求与理解分开

| 对象 | 处理方式 |
| --- | --- |
| 原始文件和消息 parts | 到期不删除、不改写；原有生命周期与权限规则继续适用 |
| 请求内图片 | 根据轮数、当前明确选择、能力与预算决定是否携带 |
| 图片描述 | 按固定版本保存有来源的文字；随本次请求独立选取和计量 |
| 理解结果 | 记录实际观察对象、问题、处理来源和局限，不等同模型每次都能看到原图 |
| 生成状态 | 生成、保存、是否检查分别存在；保存的图不自动视为看过 |

普通请求有三种展示结果：“携带图片”“仅有描述”“未包含”。这些是每个请求的决定，不是资产永久状态。同一图片在不同会话和不同模型下可有不同决定。

### 4.2 轮数与重新计数

- 推荐按实际进入当前会话处理的用户消息计数；工具循环、助手消息、系统指令、自动重试、状态查询不计数。
- 排队尚未开始的消息不提前推进当前运行的图片年龄；未被模型采用的撤回消息不计数。不能事后因为隐藏一条已采用消息而把其他图片重新变年轻。
- 配置 N 轮包含首次采用图片的一轮；N=3 时第 1、2、3 轮携带，第 4 轮改描述。N=5 时第 6 轮改描述。
- 用户仅预览、下载或把图片加入草稿不重置轮数；提交并实际采用新的内容引用后重置。
- AI 明确重新读图成功，并将图片纳入接下来的模型请求后，以所在用户轮为新起点。同轮再次读取同版本不继续延长。
- 自动重复携带、查看描述、压缩或重启不重置。计数依据要持久化，不能仅扫描压缩后剩下的消息。
- 发送前失败不标为已发送；请求发出但响应失败不能标为已有理解结果。记录请求阶段，避免混同。
- 原图与适配图的读取记录需记录实际采用版本；新生成或编辑版本不能继承旧版本“已看过”的结论。
- 分支与子会话使用各自采用的消息和明确授予的版本；不能因另一分支继续聊天，消耗当前分支的保留轮数。

时间在本文指“何时退出”，以轮数为推荐单位；按分钟/小时退出尚未纳入，若需要需另行确认。长期暂停对话不会仅因钟表时间经过而改变下一次携带规则。

### 4.3 配置设计与迁移建议

下表维护交互语义；正式键名及范围见唯一[配置说明](../../backend/agent/model-capabilities.md#全局文件与上下文策略files)。

| 控件 | 推荐值 | 约束 |
| --- | --- | --- |
| 图片自动携带方式 | 最近若干轮 | 可选“仅当前轮 / 最近若干轮 / 不按轮数过滤”；后者仍受预算和整体压缩限制 |
| 图片保留轮数（含首次发送轮） | 3 | 最近若干轮模式展示；正整数，1 规范化为仅当前轮；5、10 等均可自定义 |
| 到期后的文字 | 简短描述与关键词 | 可选“简短描述与关键词 / 仅关键词”；两者都保留可定位的固定版本标识和未携带说明 |
| 缺少描述时 | 只使用已有信息 | 可选“只使用已有信息 / 自动调用指定识图服务补充”；没有关键词时不得猜测 |
| 补描述服务 | 未选择 | 仅开启自动补充时出现；必须指定可用且获准的图片理解对象，不在多个服务间猜选 |

默认 3 的理由是延续现有成本预期，不代表行业标准或已证明优于 5。用户可调整。模式使用明确选项，不再让 0 同时表达不携带、无限或默认。

推荐迁移：已有 `recentUserTurns` 显式值带入图片策略；0 和 1 映射为仅当前轮，其他正值映射为对应轮数；缺省采用确认后的默认。既有全文件字段改为明确只负责其他文件的规则，界面同步改名。图片运行时只读图片策略，不留两套规则叠加。一次迁移保留会话、文件、账号及凭据，重复迁移不覆盖已迁移后的修改；具体键名与迁移版本需在实施前确认。

### 4.4 描述来源与真实性

| 来源 | 可表达的内容 | 限制 |
| --- | --- | --- |
| 已有图片理解记录 | 先前观察到的主体、布局、文字或针对问题的结果 | 标记问题与范围，不能把局部问答当全图描述；多图比较不能随意拆成独立图片事实 |
| 用户说明 | 用户对图片的说明 | 标签为“用户说明”，不代表系统验证 |
| 生成提示词 | 用户希望生成什么 | 标签为“生成要求”，不能作为实际成图描述 |
| 文件信息 | 文件名、格式、尺寸、固定版本 | 不从文件名猜内容 |
| 无可用视觉文字 | “暂无视觉描述，可重新读取” | 不为了有关键词而编造 |

建议保存：会话与所有者、资产及实际观察版本、文字类别、描述、关键词、来源操作/消息、问题范围、生成时间及描述规则版本。复用前重新验证权限和来源；不同用户不因文件哈希相同共享私人会话描述。

描述是外部观察或用户内容，不是系统指令。截图中的命令、提示词和网页文字只作为被观察内容，不能提升为执行要求。与当前问题不相关的敏感文字不为“完整记忆”而额外提取。

自动补充为可选功能：开启后优先复用合适记录；没有记录时，在需要替换且图片确有内容读取授权的准备阶段，最多发起一次对应版本/规则的补充操作。先校验来源、权限、服务和输入预算，再发请求；不扫描全部历史。请求未知结果不自动重复计费，失败保留基本信息，不阻断普通聊天。明确恢复重试前核对现有操作状态。开关关闭后停止新任务；已发出的请求不能保证撤销远程费用，晚到结果不能改写新版本或已固定的请求。

描述与关键词要有单图及总文字预算，进入普通文本计量；实施前确定具体上限并记录在唯一配置说明。当前 20000/80000 字符的文件提取上限不能直接当成图片短描述长度。描述被压缩后仍需按授权检索，不能把所有旧图描述永久塞回每次请求。

### 4.5 本次请求选择顺序

1. 取得已采用配置快照和当前会话权限；排除撤回、不可访问及本次仅附文件的内容读取。
2. 收集当前显式内容引用和明确重新读图的结果，优先满足它们。
3. 对历史图片按持久轮数判断是否到期；到期选择可用描述。
4. 对未到期图片检查模型能力、图片格式、不同版本数量、文件字节及实际请求大小。历史图片超限时从较早且未明确选中的开始改为描述。
5. 选择已授权的理解工具时，明确这是工具观察而非当前模型直接看图；没有工具且原生不支持时不能假装执行。
6. 当前明确选择的图仍无法满足请求限制时，指出具体图片和原因，允许改用已有适配版、分批或仅附文件，不静默省略。
7. 生成本次请求明细，保留图片/描述决定、原因、实际版本、配置版本和请求标识；发出与失败阶段分别更新。

文件数量按不同固定版本去重；同图多处引用保留位置关系，但不得让重复字节无限增加请求。多图比较需保留全部明确选择的图片及顺序，不能悄悄用一张图的描述代替原图完成精细对照。轮数不是在这几轮内必定携带的保证。

### 4.6 重新读取、生成图及委派

```text
用户继续问旧图 → 从描述/历史定位候选固定版本
  → 唯一明确对象：请求读图；多个不明确对象：请用户选择
  → 权限、能力、格式、预算检查
  → 原生模型接收图片，或获授权的理解工具给出观察
  → 后续模型请求实际采用 → 更新该会话读取记录与轮数
```

- 查找、描述查询与读取分开。描述查询不下载图片、不增加阅读次数、不重置计数。
- 对本次仅附文件的引用，不因自动描述或预算处理触发识图；后续用户明确要求读取，可按新内容请求重新校验。
- 图片编辑始终取得选定版本的实际内容；旧描述、关键词或服务商响应 ID 不能单独代替图片输入。多轮服务商续接只能在原服务及协议允许的范围使用。
- AI 无工具调用能力时，不能承诺自主检索旧图；用户显式重新引用仍可直接输入，或走已明确配置的前置理解。
- 工具生成、子角色交付的图先保存并显示“尚未检查”。只有明确要求读取、检查或重新引用才进入图片上下文，不因生成成功自动补一次收费识图。
- 子角色获得明确文件授权，读图记录归其会话；回传可包含有来源的观察和授权成果，但不能据此把主角色标为直接看过原图。主角色需要细节时重新读取。
- 服务不可用、模型切为纯文本、文件失效时保留描述及真实限制；授权被撤销时，描述同样不得继续向无权主体提供。

## 5. UI 信息结构与文案

### 5.1 设置位置与布局

入口保持“设置 → 全局 → 文件与上下文”。沿用现有散卡画布、卡内纵向滚动与父级草稿，不把整个全局页改为新表单，也不新增平行保存按钮。

卡内按职责分组：上传与保存、图片上下文、其他文件上下文、请求大小、图片适配。图片上下文默认展开，自动补描述的服务选择只在开启时出现。长内容通过卡内滚动与折叠辅助区处理，不能通过缩小字号塞满。

文字结构示意，非像素稿：

```text
图片上下文
自动携带       [最近若干轮 ▾]
保留轮数       [3] 轮  ⓘ
到期后的文字   [简短描述与关键词 ▾]
缺少描述时     [只使用已有信息 ▾]
```

- 轮数 tip：“含首次发送轮。设为 3 时，第 4 轮起改用文字说明；仍可重新引用图片。不会删除历史文件。”触屏可点击信息图标，键盘聚焦可阅读；不依赖原生 title。
- “不按轮数过滤”旁说明其仍受大小和整体压缩限制，不能写“永久记住图片”。
- 自动补描述开启时，在服务选择附近直接提示“需要时会调用所选识图服务，费用以服务方为准”；这是决策必需信息，不藏在 tip 中，也不重复弹审批框。
- 仅保存策略不调用识图。选择服务时展示实际可用性，不把“支持图片输入”的普通配置自动视为已获准的独立识图服务。
- 非法数字显示字段错误；清空是使用默认，不转为 0；默认值显示实际采用值及“默认”标识，不只用 placeholder 暗示。

### 5.2 历史图片卡与预览

保留“预览 / 下载 / 用于下一条消息”三个已存在动作。历史卡主要展示文件，不给每张图常驻一串轮数、关键词和费用标记。

- 不将最近请求的“已转描述”贴成图片永久状态；详情须注明会话和请求时间。原卡继续能预览或下载。
- “用于下一条消息”只加入明确目标草稿；反馈说明目标会话，不立即发给模型。已在草稿中的同版本定位已有项，不重复插入。
- 不增加与“用于下一条消息”含义重复的“恢复图片”按钮。AI 读图动作在执行过程显示，用户重新发送沿用现有草稿入口。
- 图片详情可展开“文字说明与来源”：先显示短描述，关键词作为一行辅助文字，来源与固定版本折叠；无描述直写“尚无视觉描述”。不把关键词铺成大量彩色标签。
- 用户打开预览只是自己查看，不触发模型读取、补描述或重置轮数。预览保持完整比例，不改变历史版本；关闭返回原卡焦点。

### 5.3 输入区、执行过程与上下文详情

| 区域 | 显示内容 | 不应混淆 |
| --- | --- | --- |
| 输入草稿 | 所选文件、固定版本、内容/仅附文件、可处理性 | “已加入草稿”不是已发送；不显示最终请求已携带 |
| AI 执行过程 | “查找历史图片”“重新读取图片”“补充图片描述”等真实操作 | 本地读取不等于服务响应；无进度信息不造百分比 |
| 最近文件请求详情 | 请求标识/时间、准备或发送阶段、采用配置、各图处理方式与原因 | 原实现只存最近记录；不新增未经实现的任意请求回看控件 |
| 图片说明详情 | 描述来源、范围、固定版本及重新引用入口 | 有描述不代表当前模型看到了原图 |

最近请求明细推荐显示：文件名、原始/适配版本、处理方式、原因；详情展开才显示完整 ID、描述、服务、字符量与字节量。轮数仅在到期原因或策略详情中出现，不额外制造持续倒计时。

处理方式文案为“携带图片 / 通过工具理解 / 仅携带文字说明 / 未包含”。发送阶段独立为“准备中 / 已准备 / 已发出 / 发送前失败 / 已发出但结果未确认”。没有证据时不显示“模型已理解”；官方预检成功也不代表正式请求已经发出。

当前记录被新请求覆盖时明确更新为最近请求，不继续将旧明细挂在某条历史回答上。若后续需要逐请求审计，应另行扩展持久记录和接口，本方案不让 UI 模拟不存在的历史。

## 6. UX 操作流程与异常恢复

| 场景与触发 | 即时反馈与结果 | 中断、失败及恢复 |
| --- | --- | --- |
| 修改 3 为 5 | 草稿标未保存，说明示例随值变化；保存后显示实际采用状态 | 切页保留草稿；失败保留输入；不立即读取历史图 |
| 保存时继续编辑 | 提交点击时快照，后续输入仍是未保存草稿 | 晚到响应不覆盖新输入；外部修改按已有冲突流程处理 |
| 运行中改策略 | 已发请求不变；后续请求采用当时已生效版本 | 不简单承诺点击保存立即生效；等待采用时显示原因 |
| 首次发送图片 | 上传/发送反馈与现有规则一致；模型准备采用内容 | 上传成功不宣称看过；接口拒绝保留消息和文件 |
| 第 N+1 轮到期 | 模型请求改描述，历史卡仍保留原图 | 不每图弹 toast、不自动滚动到历史图；详情可查原因 |
| 到期后追问细节 | AI 确认对象并重新读图，执行行给出反馈 | 找到多个候选时请求选择，不以关键词相近盲选；失败明确无法确认细节 |
| 用户从旧消息重新引用 | 加入源视图明确的目标草稿并定位引用；用户发送后才读取 | 目标关闭或身份切换则失效，不写入另一个窗口；取消选择不改草稿 |
| 两张图对比 | 当前明确选中的两图按原顺序联合输入 | 一图不可读时说明限制，不暗中只比较剩下一图 |
| 修改刚生成的图 | 选中确切成果版本后交给编辑服务 | 生成服务未提供编辑能力时说明缺项；不自动再生成相似图冒充编辑 |
| 原图切适配版 | 草稿标明实际版本及转换；预览与提交选择区分 | 转换失败保留原图；不默认放宽大小限制 |
| 自动补描述 | 需要时显示服务和阶段，成功保存来源并用于后续请求 | 失败留基本信息；不阻断普通聊天、不重复计费；关闭详情不取消任务 |
| 停止读图/补描述 | 显示正在停止或已停止等待 | 不承诺撤销服务商操作；晚到结果不可覆盖新选择，不重置未采用图片轮数 |
| 模型切换或服务关闭 | 重新计算下次请求能否直接输入或经工具理解 | 原图和描述仍保存；不用旧“可用”缓存掩盖能力变化 |
| 压缩、重启、断线重连 | 复用持久图像引用、计数和描述；读取最新服务端状态 | 不重复补描述，不因内存清空把历史图重新设为新图 |
| 文件不存在或无权限 | 行内说明不可读，允许选择其他合法文件 | 权限未满足时不显示旧描述泄漏内容；“重试”不等于恢复权限 |
| QQ 等非 Web 入口 | 共享后端规则；歧义时用图片序号/原消息引用让用户选择 | 不把 Web URL 或本地路径作为唯一恢复方式；不擅自发真实渠道测试 |

### 6.1 空态与反馈归属

- 没有图片：不显示空描述列表；上下文入口说明尚无文件请求。
- 没有历史候选：说明未找到可访问图片，可重新上传或引用已有消息；不是生成一张替代图。
- 暂无描述：基本信息与重新引用入口正常可用，不显示红色失败。
- 明细加载失败：错误位于明细区，可重试查询；不把查询重试变成识图重试。
- 描述服务失败：显示在对应操作及描述详情中，不让短暂 toast 成为唯一可查位置。
- 切换账号、后端、会话时清理旧视图数据并丢弃过期响应；不能让上一身份的描述残留。各窗口共享后端事实但保持各自草稿。

### 6.2 键盘、窄窗与视觉约束

- 遵循[前端设计语言](../../standards/frontend/design-language.md)及[现有 UI 适配](ui-adaptation.md#4-颜色字体与几何)：主题语义色、清晰字重、直角新增控件；不新增装饰动画或另一套窗口皮肤。
- 设置普通文字按现有 14px 基线，工作台内容按现有可读性要求；不缩小文字解决溢出。重要状态用文字配合图标，不单靠颜色。
- 标签关联真实控件；条件字段隐藏后不保留无效焦点；字段错误可定位。tip 可聚焦和触屏打开，核心费用与阻塞原因行内可见。
- 预览/详情 Esc 只关闭最上层，返回触发处；不停止后端任务。草稿关闭沿现有确认流程，Enter 不干扰中文输入法。
- 多图、长文件名、长中文错误可换行；固定版本可复制，完整内容可展开；不靠裁切、缩字或巨大横向表格容纳。
- 窄卡使用单列，辅助说明按需展开；保存和发送入口可到达。控件操作不能触发散卡拖动，卡片拖动不能更改数字值。
- 预览按需读取，查询上下文不批量下载原图；列表与描述分页/限量，关闭视图释放本视图资源。
- 主题、200% 缩放、键盘、触屏、最小工作台窗口由用户实际验收；源码检查不冒充已验证渲染。

## 7. 实施方式、依赖与待确认项

### 7.1 存量调整的两种方式

| 维度 | 破坏性修改（推荐） | 直接更新 |
| --- | --- | --- |
| 界面体验 | 一套图片策略，旧全文件设置明确转为其他文件策略 | 新旧入口暂存，必须说明优先级，易混淆 |
| 实现成本 | 一次迁移并替换图片处理规则，不保留兜底分支 | 双规则并存，测试与维护成本较高 |
| 数据配置 | 一次性迁移已有值；保留文件、消息、账号和凭据 | 原配置保留，新策略叠加 |
| 长期演进 | 后续只扩展一套请求准备逻辑 | 仅适合需要对照运行；必须定兼容退出条件和清理时间 |

用户已确认按推荐实施；保留文件、会话和凭据，不保留图片旧判断分支。授权不包含收费调用、生产操作或 AI 查看图片。

| IC-D2 | 图片独立配置，默认最近 1 轮，包含首次发送轮，按轮数而非分钟 | 已确认 |

### 7.2 后续工作顺序

以下是已授权的工作分解，实际完成与验证以总任务恢复点为准。

下列是验收要求，实际自动验证结果及人工边界只在总任务恢复点维护；文档检查不证明功能或视觉效果。

| 编号 | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| IC-V01 | 保留 3 / 5 轮 | 分别第 4 / 6 轮改文字；当前明确输入优先 |

| IC-V03 | 自动携带、工具循环、重试 | 不重置期限、不增加用户轮；同版本不重复累计实际发送字节 |
