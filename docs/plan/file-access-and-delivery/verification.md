# 文件权限与交付的验收准备

本文是 FA01—FA03 的接手检查说明，状态、处理人和授权统一见[任务台账](README.md#小任务与恢复条件)。缺少条件时不交付用户操作卡，不把准备说明当成可立即测试的指令。

## FA01 业务身份与文件隔离

执行者在用户提供业务登录及第二账号后，先核对这两个账号的实际所有权和会话权限，选择经授权的既有固定版本；不把库中其他所有者的资产当测试文件。登录凭据不写文档、日志或提交。

按正式 `AssetStore`/HTTP 入口逐项检查：上传者读取、获授权会话引用、未授权账号访问、授权撤回后访问，以及 `original/adapted` 固定版本预览/下载。成功项核对内容摘要、Range、MIME 与文件名；拒绝项不能返回字节、私人描述或内部路径。保存权限另走实际已登录模块 HTTP，避免用机器管理 `PUT files` 的通过替代。

人工界面由用户操作，执行者提前准备最小可执行步骤与预期，然后在允许范围内关联后台请求、身份与拒绝结果；只保留脱敏字段，不让用户自行排查 Cookie、协议或数据库。发现与已确认权限不符时先登记修正，再安排受影响最小复验。

## FA02 QQ 输入、发送与恢复

先取得具体授权的账号/群、消息类型、输入及发送数量、可否短时中断和重试范围。当前旧纯文字剩余次数不能用于文件。执行者核对插件配套、连接身份、活跃任务与发送未知项，准备有权固定版本，不要求用户自己试发文件。

分别组织并关联：文字+文件有序入站、图片/文档混合、纯文件完成、普通文本 `qq.reply.part`、平台原生文件送达。每项至少保留入站来源、后端任务/请求、固定版本、平台回执与必要用户收件反馈；不保存无关群内容。

故障场景需另获具体范围：发送请求已发回执丢失、明确发送失败、断线后原回执重放、完成重复通知和停止后迟到。先查询已有发送身份，不能自动再发；后端完成和文件保存不能当平台送达。已确认引用文字收发不重做，“不调用工具”未通过仍保持原结论，不通过隐藏实际工具把它改成通过。

## FA03 工作区导入导出

用户先决定目录及配置修改范围；执行者核对当前预设的 workspace 和权限，不自动创建业务目录。选择经授权的普通文本作为最小输入，明确源路径、快照资产和导出目的地，不使用秘密文件。

检查路径引用按需读当前文件；快照导入生成固定版本后源文件修改不改历史。目录不能作为文件快照上传，越界、符号链接逃逸和无权限路径拒绝且不泄露绝对路径。导出按目标工作区权限写入，对已存在文件不得未经授权覆盖。

失败时原文件、草稿与既有资产保留，恢复只重试被确认未执行或可安全去重的步骤。工作区实际配置保存与文件写入不在本次移交授权内。
