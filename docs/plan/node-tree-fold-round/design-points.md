# 四档必要性调研与后续阅读导航设计点

## 四档保留理由

| 档位 | 收纳程度 | 当前价值 | 是否保留 |
| --- | --- | --- | --- |
| 完整展示 | 不收纳，所有消息、执行与交接都单独显示 | 作为核对真实执行顺序、连线和分支关系的基准 | 必须 |
| 局部收纳 | 只把同一参与者连续完成的步骤收为过程组 | 只减少重复执行细节，不隐藏参与者交接结构 | 保留 |
| 按参与者收纳 | 每位参与者内部收纳，但保留委派、返回和分支关系 | 用于理解多 Agent 任务如何拆分、返回和汇合 | 保留；与第二档侧重点不同 |
| 轮次档位 | 已结束的一轮整体收为一个轮次节点，详情中保留提问、内部步骤与主 Agent 结论 | 最大限度缩短长会话的 Signal 横向链条 | 替换原第四档“只看每轮主线” |

## 二档与三档必要性核对

探针实跑结果显示：在所核对的委派轮次中，第二档和第三档均没有建立过程组，节点及拓扑关系保持展开；原第四档会将委派、子 Agent 工作和结果返回压入过程组。由此可见，第三档不是“更强的第二档”：它的目标是保留参与者交接和返回关系，同时收起各参与者内部过程。它与第二档面向的任务结构不同，当前不应合并。

第三档在本次样本中的画面差异较弱，且主要在参与者内部有足够连续完成步骤时才会出现。后续可以继续收集更长、更多层级的协作样本，评估它是否足以支撑独立入口；本次不改变第二、三档。

## 后续阅读导航需求

这些是后续分析和实现的候选设计点，本次没有实现：

- **缩略图**：讨论是否需要小型全局概览、它代表完整树还是当前可见投影、密集分支如何提示，以及点击后如何定位；不能用不可辨认的小字缩放代替导航。
- **按轮跳转**：确认轮次编号规则、当前/最新轮的初始选择、跨分支时的顺序，以及跳转是否只移动视口还是同时打开详情。
- **搜索定位**：确认搜索范围（用户消息、结论、工具结果或全部内容）、结果如何显示所属轮次/分支，以及选中结果后如何定位并打开对应详情。

每项能力都应复用节点树的真实拓扑和详情入口，不复制另一套会话事实；交互说明应让首次使用者看懂搜索或跳转将影响什么。
