## 目标

让万象台、任务中心和工作台读取同一份运行事实。

## 输入材料与事实核对

先读[完整设计记录](design-and-history.md) §2～§10 的有效方案，再读下列入口。标为前置产物的文件由前置任务创建；其他列出的入口用于定位现有实现，不代表本任务必须修改所有文件。

- `src/service/chat/overview.ts`
- `src/service/chat/currentState.ts`
- `web/src/stores/taskOverview.ts`
- `web/src/stores/interactions.ts`

## 范围与非目标

允许承担的修改范围：

- 后端万象台 overview 与事件投影
- web/src/stores/、domain/、services/、application/ 下对应唯一状态 owner
- 任务中心必要的团队归属扩展

非目标：不顺手重构无关功能、不提前实现下游展示、不改用户项目原始文件来验证计划。具体物理文件可遵循仓库归属规范拆分，但若扩大共享写入范围，先由总负责人重新分配。不得将任务文档内算法建议升级为全局规范；需要形成规范时落入 docs/standards/。

## 执行步骤

- [ ] 1. 定义任务、团队、实例、工作区状态的优先级与原因，分离执行状态、显示位置和生命周期；以持久业务事实投影，不从动画推断运行。
- [ ] 2. 扩展 overview 的团队/实例关联及打开万象台的信息；复用已有 chatId/rootChatId 待办来源，不新建重复审批队列。
- [ ] 3. 实现打开快照、版本递增补丁、订阅释放和断档重开；共同操作使用同一业务入口，限定只对订阅者发送相关任务事件。
- [ ] 4. 验证重复/乱序事件、断线、多标签页和 Electron 并存、任务中心定位；检查无新增周期全量轮询、无双份可写事实。

## 定向测试

- 一个视图处理待办后其余视图同步，不允许重复操作产生新副作用。
- 状态 needs_user/waiting/failed 不能被普通 idle 覆盖。
- 状态载荷有界，不把完整会话和所有文件清单放入高频事件。

新增定向测试入口：`test/wanxiangtai/state-projection.test.ts`。使用现有 Vitest，不另引入测试框架。该文件为实施目标，目前尚未创建。

```text
pnpm exec vitest run test/wanxiangtai/state-projection.test.ts
pnpm type-check
```



定向测试必须验证对外行为及失败后果，不只复写实现细节。全量检查由批次与最终回归统一记录，不把局部通过当综合通过。

## 完成标准

- 任务中心和万象台不形成两个执行控制源。
- 事件断档可恢复到服务端真实状态。
- 四步均已完成，定向验证有真实结果；产物与模块文档一致。
- 交接实际文件、接口/数据版本、运行命令、已知限制和受影响下游。
- 失败时保留可追溯证据，不通过默认成功或忽略错误掩盖问题。

## 协作与变更边界

- 执行前核对前置任务已完成且契约版本一致；当前状态“未开始”，未解锁不等于发生故障。
- 本次落盘不是实现批准或验收。遵循总文档的已确认需求；新增技术方案以“补全建议”提供，执行时不得冒充用户原话。
- 先更新对应模块文档，再实现代码。不得修改本总计划以外无关需求、不得代用户审批。
- 共享文件由总负责人分配；遇到权限、状态或契约变更需求提交给核心负责人，不同时覆盖他人文件。
- 每完成一个步骤更新本任务；由总负责人同步总计划的步骤统计，避免多 Agent 同写总文件。
- 最终回归发现问题时重新打开本任务，不能保留虚假的“已完成”。
