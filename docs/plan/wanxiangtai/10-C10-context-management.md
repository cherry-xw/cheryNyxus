允许承担的修改范围：

## 执行步骤

- [ ] 1. 建立完整历史、有效任务记录和当前上下文三层；按角色、议题依赖和决策版本取材，调度者默认接收摘要与证据入口。
- [ ] 2. 在最终消息及工具定义组装后、每次请求前检查输入/输出/安全预算；使用匹配模型计量或保守估算并校准 usage，不以字符数/4 作可靠硬上限。
- [ ] 3. 接入提前压缩、有界工具结果、证据分页、不可丢失记录重载及显式交接；压缩保留实例身份，接替保留待办、基线和已消费事件位置。
- [ ] 4. 验证中文代码混合、巨大工具结果、连续三次压缩、根/成员分别压缩、会议唤醒绕过 send 的路径、提供商超限以及重启后恢复。

## 定向测试

- 压缩请求自身也要满足预算；已超限不得把原文原封不动送去总结。
- 强约束和议题必需证据仍放不下时，明确拆分或阻塞，不能静默裁剪。
- 子会话回忆不能仅依赖根会话已有压缩代际。

新增定向测试入口：`test/wanxiangtai/context-management.test.ts`。使用现有 Vitest，不另引入测试框架。该文件为实施目标，目前尚未创建。

```text
pnpm exec vitest run test/wanxiangtai/context-management.test.ts
pnpm type-check
```

定向测试必须验证对外行为及失败后果，不只复写实现细节。全量检查由批次与最终回归统一记录，不把局部通过当综合通过。

## 完成标准

- 系统能在预算内持续推进，而不把决策正确性寄托于一段摘要。
- 无未处理消息或交付版本因压缩丢失。
- 四步均已完成，定向验证有真实结果；产物与模块文档一致。
- 交接实际文件、接口/数据版本、运行命令、已知限制和受影响下游。
- 失败时保留可追溯证据，不通过默认成功或忽略错误掩盖问题。

## 协作与变更边界

- 执行前核对前置任务已完成且契约版本一致；当前状态“未开始”，未解锁不等于发生故障。
- 本次落盘不是实现批准或验收。遵循总文档的已确认需求；新增技术方案以“补全建议”提供，执行时不得冒充用户原话。
- 先更新对应模块文档，再实现代码。不得修改本总计划以外无关需求、不得代用户审批。
- 共享文件由总负责人分配；遇到权限、状态或契约变更需求提交给核心负责人，不同时覆盖他人文件。
- 每完成一个步骤更新本任务；由总负责人同步总计划的步骤统计，避免多 Agent 同写总文件。
- 最终回归发现问题时重新打开本任务，不能保留虚假的“已完成”。
