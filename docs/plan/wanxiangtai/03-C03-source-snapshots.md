## 目标

对启动时实际文件生成可验证、可恢复的不可变基线。

## 输入材料与事实核对

先读[完整设计记录](design-and-history.md) §2～§10 的有效方案，再读下列入口。标为前置产物的文件由前置任务创建；其他列出的入口用于定位现有实现，不代表本任务必须修改所有文件。

- `src/db/index.ts`
- `src/service/wanxiangtai/project.ts（C02 产物）`

## 范围与非目标

允许承担的修改范围：

- src/service/wanxiangtai/snapshots.ts
- 相应 snapshot 持久模型与测试
- docs/ 下快照与恢复说明

非目标：不顺手重构无关功能、不提前实现下游展示、不改用户项目原始文件来验证计划。具体物理文件可遵循仓库归属规范拆分，但若扩大共享写入范围，先由总负责人重新分配。不得将任务文档内算法建议升级为全局规范；需要形成规范时落入 docs/standards/。

## 执行步骤

- [ ] 1. 实现 Git 当前文件与普通目录枚举：包含纳入范围的未提交修改、新文件及删除状态；排除运行目录和派生文件，保留 sourceId＋相对路径。
- [ ] 2. 实现 preparing 操作、临时目录复制、逐文件内容哈希、大小/类型/属性清单；预检内部链接、外部链接、子模块、二进制与平台能力。
- [ ] 3. 实现复制前后变化检测、最多两轮自动重试、校验后发布及 ready 登记；恢复未完成操作，源持续变化时阻止发布，不宣称跨文件瞬时原子快照。
- [ ] 4. 验证快照发布后源变化不影响读取、复制中变化被发现、创建失败不暴露半成品、重复发布幂等，并记录大文件与大量小文件基准。

## 定向测试

- Git HEAD 内容与当前未提交内容不同，快照必须包含已选择的当前内容。
- 实例运行目录不会递归进入新快照。
- 普通目录、空文件、删除、非 ASCII 路径、链接失败均有明确结果。

新增定向测试入口：`test/wanxiangtai/snapshots.test.ts`。使用现有 Vitest，不另引入测试框架。该文件为实施目标，目前尚未创建。

```text
pnpm exec vitest run test/wanxiangtai/snapshots.test.ts
pnpm type-check
```



定向测试必须验证对外行为及失败后果，不只复写实现细节。全量检查由批次与最终回归统一记录，不把局部通过当综合通过。

## 完成标准

- 快照不可原地更新且内容与清单一致。
- 失败与重启不会产生伪 ready 快照。
- 四步均已完成，定向验证有真实结果；产物与模块文档一致。
- 交接实际文件、接口/数据版本、运行命令、已知限制和受影响下游。
- 失败时保留可追溯证据，不通过默认成功或忽略错误掩盖问题。

## 协作与变更边界

- 执行前核对前置任务已完成且契约版本一致；当前状态“未开始”，未解锁不等于发生故障。
- 本次落盘不是实现批准或验收。遵循总文档的已确认需求；新增技术方案以“补全建议”提供，执行时不得冒充用户原话。
- 先更新对应模块文档，再实现代码。不得修改本总计划以外无关需求、不得代用户审批。
- 共享文件由总负责人分配；遇到权限、状态或契约变更需求提交给核心负责人，不同时覆盖他人文件。
- 每完成一个步骤更新本任务；由总负责人同步总计划的步骤统计，避免多 Agent 同写总文件。
- 最终回归发现问题时重新打开本任务，不能保留虚假的“已完成”。
