允许承担的修改范围：

- src/service/wanxiangtai/snapshots.ts

## 执行步骤

- [ ] 1. 实现 Git 当前文件与普通目录枚举：包含纳入范围的未提交修改、新文件及删除状态；排除运行目录和派生文件，保留 sourceId＋相对路径。
- [ ] 2. 实现 preparing 操作、临时目录复制、逐文件内容哈希、大小/类型/属性清单；预检内部链接、外部链接、子模块、二进制与平台能力。
- [ ] 3. 实现复制前后变化检测、最多两轮自动重试、校验后发布及 ready 登记；恢复未完成操作，源持续变化时阻止发布，不宣称跨文件瞬时原子快照。
- [ ] 4. 验证快照发布后源变化不影响读取、复制中变化被发现、创建失败不暴露半成品、重复发布幂等，并记录大文件与大量小文件基准。

## 定向测试

- Git HEAD 内容与当前未提交内容不同，快照必须包含已选择的当前内容。
- 实例运行目录不会递归进入新快照。
- 普通目录、空文件、删除、非 ASCII 路径、链接失败均有明确结果。

新增定向测试入口：`test/wanxiangtai/snapshots.test.ts`。使用现有 Vitest，不另引入测试框架。该文件为实施目标，目前尚未创建。

```text
pnpm exec vitest run test/wanxiangtai/snapshots.test.ts
pnpm type-check
```

定向测试必须验证对外行为及失败后果，不只复写实现细节。全量检查由批次与最终回归统一记录，不把局部通过当综合通过。

## 完成标准

- 快照不可原地更新且内容与清单一致。
- 失败与重启不会产生伪 ready 快照。
- 四步均已完成，定向验证有真实结果；产物与模块文档一致。
- 交接实际文件、接口/数据版本、运行命令、已知限制和受影响下游。
- 失败时保留可追溯证据，不通过默认成功或忽略错误掩盖问题。

## 评审调研结论（2026-09-12 整体评审落位）

> 来源：[整体评审与强化方案](review/design-review.md)、[可行性缺陷分析](review/feasibility-findings.md)、[技术栈调研](review/tech-stack-research.md)、[渲染栈聚焦调研](review/rendering-stack-research.md)。本节是评审产出的执行提示，只补充信息，不修改本任务既有范围、步骤与验收标准；标注 U-xx 的事项未经用户裁定前不得视为已确认需求。

### 1. 方案建议与调研结论建议
- 一期维持原案：普通复制＋manifest＋逐文件哈希（t2 领域 2：无现成栈可整体套用）；工程要点为复制/哈希流水线化——异步并发 4–8、排除规则先行、进度可取消（t2 §2.2e）。
- 普通复制应实现为「复制策略接口」的默认实现类，二期 COW/CAS 以新实现接入、不动调用方（增-08；design-review §4 领域 2）。

### 2. 可能存在的问题点
- F-07：快照创建窗口内源头持续变化，两轮自动重试在活跃项目上仍可能难产。
- 性能瓶颈（t2 领域 2）：海量小文件（前端项目动辄数万文件）＋逐文件 SHA-256，是本任务步骤 4 基准测试的主要观测对象。

### 3. 优化建议
- 增-13：清单预检先行（冻结配置后先枚举＋估时提示预计窗口）；失败引导「暂存外部修改后重试」一键操作；二次校验允许抽样代替全量复制重来。
- 二期演进（t2 领域 2）：全局 CAS（restic 式内容哈希 blob 池＋引用清单），多实例磁盘成本从 N×项目降到 ≈1×项目＋增量。
