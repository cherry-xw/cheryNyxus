## 目标

保留议题与讨论历史，并保证可恢复的消息投递和来源追溯。

## 输入材料与事实核对

先读[完整设计记录](design-and-history.md) §2～§10 的有效方案，再读下列入口。标为前置产物的文件由前置任务创建；其他列出的入口用于定位现有实现，不代表本任务必须修改所有文件。

- `src/service/chat/wake.ts`
- `src/db/delivery.ts`
- `src/db/chat.ts`
- `src/core/middleware/messageJournal.ts`

## 范围与非目标

允许承担的修改范围：

- src/service/wanxiangtai/discussions.ts 与 delivery worker
- 讨论记录、待投递记录及关联消息持久模型
- 相关历史与事件协议接线

非目标：不顺手重构无关功能、不提前实现下游展示、不改用户项目原始文件来验证计划。具体物理文件可遵循仓库归属规范拆分，但若扩大共享写入范围，先由总负责人重新分配。不得将任务文档内算法建议升级为全局规范；需要形成规范时落入 docs/standards/。

## 执行步骤

- [ ] 1. 建立议题、讨论、参与者、轮次、输入快照/决策版本和关闭原因；明确小组关联消息与正式会议公共流。
- [ ] 2. 实现业务事件与待投递记录在系统库同事务落盘，会话正文以 deliveryId 幂等写入；不假设跨月份消息库天然原子。
- [ ] 3. 复用运行入口和 journal 单写者原则投递本轮所需内容，记录实例/轮次/来源；正式公共历史不自动全量注入每位参与者。
- [ ] 4. 验证业务落库后崩溃、消息写入后确认前崩溃、重放、重复回复、离线参与者及完整历史查询。

## 定向测试

- 恢复投递后业务效果只被消费一次。
- 晚到旧轮回复保持可审计，但不计入新轮。
- 失败不能通过创建假 child_return 来掩盖。

新增定向测试入口：`test/wanxiangtai/discussion-storage.test.ts`。使用现有 Vitest，不另引入测试框架。该文件为实施目标，目前尚未创建。

```text
pnpm exec vitest run test/wanxiangtai/discussion-storage.test.ts
pnpm type-check
```

定向测试必须验证对外行为及失败后果，不只复写实现细节。全量检查由批次与最终回归统一记录，不把局部通过当综合通过。

## 完成标准

- 原文、来源和控制状态均可追溯。
- 讨论消息不会因前端关闭丢失。
- 四步均已完成，定向验证有真实结果；产物与模块文档一致。
- 交接实际文件、接口/数据版本、运行命令、已知限制和受影响下游。
- 失败时保留可追溯证据，不通过默认成功或忽略错误掩盖问题。
