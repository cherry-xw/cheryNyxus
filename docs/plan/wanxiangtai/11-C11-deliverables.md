## 目标

将每次实例修改冻结成带基线、依据和验证记录的交付。

先读[完整设计记录](design-and-history.md) §2～§10 的有效方案，再读下列入口。标为前置产物的文件由前置任务创建；其他列出的入口用于定位现有实现，不代表本任务必须修改所有文件。

- `src/db/chat.ts`
- `src/service/wanxiangtai/workspaces.ts（C04 产物）`

## 范围与非目标

允许承担的修改范围：

- src/service/wanxiangtai/deliverables.ts
- 文件差异清单、冻结产物和交付状态记录
- 交付查询协议

非目标：不顺手重构无关功能、不提前实现下游展示、不改用户项目原始文件来验证计划。具体物理文件可遵循仓库归属规范拆分，但若扩大共享写入范围，先由总负责人重新分配。不得将任务文档内算法建议升级为全局规范；需要形成规范时落入 docs/standards/。

## 执行步骤

- [ ] 1. 比较实例 work 与绑定快照，按 sourceId＋相对路径识别新增/修改/删除；文本、二进制、空文件分别处理，重命名可规范化为删除＋新增。
- [ ] 2. 在安全边界暂停该实例写入，创建不可变交付内容与哈希；记录基线、决策版本、验证命令/环境/结果及未解决问题。
- [ ] 3. 实现交付版本、接收方、撤回/替代和查询；后续修改产生新交付，不修改已冻结产物。
- [ ] 4. 验证交付冻结期间写入、同路径不同来源、生成物过滤、二进制、删除、重试和重复交付。

## 定向测试

- 交付创建成功后内容与清单可独立核验。
- 没有运行验证的交付显示未验证，不伪造通过。
- 实例无法编辑他人或已冻结的交付。

新增定向测试入口：`test/wanxiangtai/deliverables.test.ts`。使用现有 Vitest，不另引入测试框架。该文件为实施目标，目前尚未创建。

```text
pnpm exec vitest run test/wanxiangtai/deliverables.test.ts
pnpm type-check
```



定向测试必须验证对外行为及失败后果，不只复写实现细节。全量检查由批次与最终回归统一记录，不把局部通过当综合通过。

## 完成标准

- 集成者能够确定改了什么、基于何物、为什么修改及是否验证。
- 四步均已完成，定向验证有真实结果；产物与模块文档一致。
- 交接实际文件、接口/数据版本、运行命令、已知限制和受影响下游。
- 失败时保留可追溯证据，不通过默认成功或忽略错误掩盖问题。

## 协作与变更边界

- 执行前核对前置任务已完成且契约版本一致；当前状态“未开始”，未解锁不等于发生故障。
- 本次落盘不是实现批准或验收。遵循总文档的已确认需求；新增技术方案以“补全建议”提供，执行时不得冒充用户原话。
- 先更新对应模块文档，再实现代码。不得修改本总计划以外无关需求、不得代用户审批。
- 共享文件由总负责人分配；遇到权限、状态或契约变更需求提交给核心负责人，不同时覆盖他人文件。
- 每完成一个步骤更新本任务；由总负责人同步总计划的步骤统计，避免多 Agent 同写总文件。
- 最终回归发现问题时重新打开本任务，不能保留虚假的“已完成”。
