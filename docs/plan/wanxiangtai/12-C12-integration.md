## 执行步骤

- [ ] 1. 由调度者指定唯一集成团队，建立指定基线的集成工作目录；同一集成目标串行接纳冻结交付，记录幂等操作。
- [ ] 2. 比较交付基线、交付变更与当前集成内容；独立路径应用，文本三方合并，二进制及删除冲突明确交人工/集成团队裁定，不采用最后写入覆盖。
- [ ] 3. 执行关联验证后发布 S1；旧实例需要更新时先保存自己的变更，在候选目录以旧基线/自身修改/S1 三方更新，成功后安全切换并通知影响。
- [ ] 4. 验证语义测试失败不发布、冲突保留、重复接纳、旧决策版本交付、更新中断和运行/审批期间禁止换目录。

## 定向测试

- 可文本合并不等于可发布，必需验证失败时阻止采用。
- 更新失败保持原实例目录和变更完整。
- 新实例与旧实例的快照选择均可追溯。

新增定向测试入口：`test/wanxiangtai/integration.test.ts`。使用现有 Vitest，不另引入测试框架。该文件为实施目标，目前尚未创建。

```text
pnpm exec vitest run test/wanxiangtai/integration.test.ts
pnpm type-check
```

定向测试必须验证对外行为及失败后果，不只复写实现细节。全量检查由批次与最终回归统一记录，不把局部通过当综合通过。

## 完成标准

- 集成快照不会被后续工作原地改写。
- 实例基线只在明确阶段边界改变。
- 四步均已完成，定向验证有真实结果；产物与模块文档一致。
- 交接实际文件、接口/数据版本、运行命令、已知限制和受影响下游。
- 失败时保留可追溯证据，不通过默认成功或忽略错误掩盖问题。

## 协作与变更边界

- 执行前核对前置任务已完成且契约版本一致；当前状态“未开始”，未解锁不等于发生故障。
- 本次落盘不是实现批准或验收。遵循总文档的已确认需求；新增技术方案以“补全建议”提供，执行时不得冒充用户原话。
- 先更新对应模块文档，再实现代码。不得修改本总计划以外无关需求、不得代用户审批。
- 共享文件由总负责人分配；遇到权限、状态或契约变更需求提交给核心负责人，不同时覆盖他人文件。
- 每完成一个步骤更新本任务；由总负责人同步总计划的步骤统计，避免多 Agent 同写总文件。
- 最终回归发现问题时重新打开本任务，不能保留虚假的“已完成”。
