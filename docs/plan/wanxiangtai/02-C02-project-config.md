## 范围与非目标

允许承担的修改范围：

- src/service/wanxiangtai/project.ts 及其项目配置校验
- src/core/security/ 与 src/utils/pathGuard.ts 中必要的项目范围接线
- docs/ 下项目配置说明

非目标：不顺手重构无关功能、不提前实现下游展示、不改用户项目原始文件来验证计划。具体物理文件可遵循仓库归属规范拆分，但若扩大共享写入范围，先由总负责人重新分配。不得将任务文档内算法建议升级为全局规范；需要形成规范时落入 docs/standards/。

## 执行步骤

- [ ] 1. 定义 .agent/project.yaml 的 version、sources、include/exclude、validation、prepare、budget、presetScope 和指引字段；模型凭据及角色定义仍由系统管理。
- [ ] 2. 实现项目根与来源绝对路径解析、配置读取和校验；检测已有 .agent 内容、同路径来源、路径大小写/别名和超长路径，不覆盖未知文件。
- [ ] 3. 实现预检结果：文件选择说明、排除原因、验证命令、缺失资源、容量估算、Git 忽略规则建议；任务冻结配置版本，并以稳定项目身份读取项目记忆。
- [ ] 4. 验证配置格式、系统与项目隔离、恶意路径、普通目录与多来源、缺失命令、已有 .agent、运行中配置变化；冻结 C02-v1 并交 S02 编写配置样例。

## 定向测试

- 目录名 .agent 本身不授予权限；配置不能扩大系统工具授权。
- 项目运行目录、凭据和原系统 .chery 不被自动复制。
- 切换实例 work 路径不产生互相割裂的项目记忆空间。

新增定向测试入口：`test/wanxiangtai/project-config.test.ts`。使用现有 Vitest，不另引入测试框架。该文件为实施目标，目前尚未创建。

```text
pnpm exec vitest run test/wanxiangtai/project-config.test.ts
pnpm type-check
```



定向测试必须验证对外行为及失败后果，不只复写实现细节。全量检查由批次与最终回归统一记录，不把局部通过当综合通过。
