## 范围与非目标

允许承担的修改范围：

- src/service/wanxiangtai/discussionScheduler.ts
- 万象台执行队列、等待关系与恢复记录
- 调度与等待事件投影

非目标：不顺手重构无关功能、不提前实现下游展示、不改用户项目原始文件来验证计划。具体物理文件可遵循仓库归属规范拆分，但若扩大共享写入范围，先由总负责人重新分配。不得将任务文档内算法建议升级为全局规范；需要形成规范时落入 docs/standards/。

## 执行步骤

- [ ] 1. 实现单组长单活动讨论、邀请队列与全部参与者原子占用；未占齐不部分锁定成员，按入队顺序处理并显式取消失效邀请。
- [ ] 2. 实现回合响应集合、重复响应去重、轮数上限、邀请拒绝/取消和参与者失效；等待回合不占模型执行槽位。
- [ ] 3. 实现有类型的等待关系检查；组长等成员时仍可在安全边界处理相关澄清，用户取消走确定性控制路径，检测环后拒绝新增阻塞边并上报。
- [ ] 4. 验证 A↔B 交叉邀请、三方等待环、父等子且子问父、连续会议、参与者退役及人工审批长期等待。

## 定向测试

- 轮数上限不被当作死锁检测器。
- 角色参与会议仍不会把后台未完成工作错误标为完成。
- 同一 chat 不并发启动两个模型运行。
