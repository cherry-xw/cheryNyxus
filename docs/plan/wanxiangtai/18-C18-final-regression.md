## 范围与非目标

允许承担的修改范围：

- test/wanxiangtai/ 和 web/test/wanxiangtai/ 端到端场景
- 必要的回归修复（须重新打开所属任务）
- 总计划验收证据与模块验收说明

非目标：不顺手重构无关功能、不提前实现下游展示、不改用户项目原始文件来验证计划。具体物理文件可遵循仓库归属规范拆分，但若扩大共享写入范围，先由总负责人重新分配。不得将任务文档内算法建议升级为全局规范；需要形成规范时落入 docs/standards/。

## 执行步骤

- [ ] 1. 建立可确定回放的产品/UI/开发团队任务，覆盖协作、并行实例、快照版本、审批和完整交付；固定模型响应与失败注入点。
- [ ] 2. 执行后端、Web、协议测试、类型检查、构建及静态检查，分类记录已有失败与新增失败；修复时重新打开对应任务并回归依赖。
- [ ] 3. 通过自动测试或可重复脚本执行 20 任务/50 实例投影、4 团队并行、三次压缩、大文件/大量小文件、磁盘限额、断线、重启、投递中断及回写中断验证，记录测试主机和数据规模。
- [ ] 4. 按 [最终手动验证手册](verify/manual-final.md) 完成浏览器/Electron 流程、视觉和真实设备性能验收，归集证据；全部满足后进入待用户审批。

## 定向测试

- S 系列全部通过不代替核心闭环验证。
- 并发、数据完整性、等待/权限和恢复失败必须解决。
- 当前任务中心遗留问题重新核实，不能沿用历史测试数当本次结果。

新增定向测试入口：`test/wanxiangtai/full-workflow.test.ts`。使用现有 Vitest，不另引入测试框架。该文件为实施目标，目前尚未创建。

```text
pnpm exec vitest run test/wanxiangtai/full-workflow.test.ts
pnpm type-check
```

另外执行总文档列出的全量后端/Web/协议测试、双端类型、构建与静态检查。
定向测试必须验证对外行为及失败后果，不只复写实现细节。全量检查由批次与最终回归统一记录，不把局部通过当综合通过。

## 完成标准

- 自动与手动验证清单均有真实证据，未通过项目无伪完成状态。
- 四步均已完成，定向验证有真实结果；产物与模块文档一致。
- 交接实际文件、接口/数据版本、运行命令、已知限制和受影响下游。
- 失败时保留可追溯证据，不通过默认成功或忽略错误掩盖问题。

## 协作与变更边界

- 执行前核对前置任务已完成且契约版本一致；当前状态“未开始”，未解锁不等于发生故障。
- 本次落盘不是实现批准或验收。遵循总文档的已确认需求；新增技术方案以“补全建议”提供，执行时不得冒充用户原话。
- 先更新对应模块文档，再实现代码。不得修改本总计划以外无关需求、不得代用户审批。
- 共享文件由总负责人分配；遇到权限、状态或契约变更需求提交给核心负责人，不同时覆盖他人文件。
- 每完成一个步骤更新本任务；由总负责人同步总计划的步骤统计，避免多 Agent 同写总文件。
- 最终回归发现问题时在父计划登记并新建对应修正子计划，不能恢复已删除任务或保留虚假的“已完成”。
