# 最终手动验证手册

本手册只由 C18“综合验证与用户验收”使用。实现子计划不得复制这些步骤，也不得等待本手册执行后才完成。

## 前置条件

- 其余 27 个子任务均已完成，结果和自动验证结论已写回总计划，独立子计划文档已删除。
- 使用最终候选版本启动后端、Web 和 Electron；准备可覆盖产品/UI/开发团队的固定测试任务和账号。
- 准备桌面与窄窗口、多种皮肤、长文本、多个待办和交付、失败及恢复场景。

## 业务流程

1. 在浏览器和 Electron 分别创建任务，确认来源路径、文件范围、空间预估、验收条件及准备进度完整可见。
2. 完成团队创建、并行实例、会议、澄清、提案版本更新、审批/裁定和跨层协调；权限、等待原因与下一步均可理解。
3. 完成交付冻结、冲突处理、候选验证、用户确认、原项目回写和结束；失败或外部变化不会被静默覆盖。
4. 模拟断线、重启、投递中断和回写中断；恢复后的状态、历史、待办和可继续操作入口一致。

## 界面与性能

1. 检查四类场景、四类皮肤、人物移动、详情、工作区准备、决策和交付界面；状态含义清楚，无重叠、截断或不可达操作。
2. 检查空数据、长文本、等待、失败、多窗口和窄窗口；界面提供足够上下文，用户无需猜测系统影响。
3. 使用 20 个任务、50 个实例和至少 4 个团队观察双端状态更新；不可见桌面不持续运行装饰动画，也不出现新增全量轮询。
4. 对大量小文件和大文件数据集记录测试设备、规模、快照耗时和磁盘放大，不写脱离测试主机的性能承诺。

## 记录

在 `verify/out/` 保存候选版本/提交、测试设备、日期、执行人、各步骤结论及必要截图或文字证据。任何失败都必须返回总计划登记新的修正子计划，不得将 C18 标记完成。
