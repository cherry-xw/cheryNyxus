## 范围与非目标

允许承担的修改范围：

- src/service/wanxiangtai/workspaces.ts
- 文件工具、命令沙箱及运行时工作区绑定的必要接线
- docs/ 下执行隔离和资源说明

非目标：不顺手重构无关功能、不提前实现下游展示、不改用户项目原始文件来验证计划。具体物理文件可遵循仓库归属规范拆分，但若扩大共享写入范围，先由总负责人重新分配。不得将任务文档内算法建议升级为全局规范；需要形成规范时落入 docs/standards/。

## 执行步骤

- [ ] 1. 实现按任务/实例唯一分配 work 与 deliverables，状态 requested/queued/preparing/ready/failed/updating/archived；在开始前原子预留磁盘预算及准备槽位。
- [ ] 2. 从指定快照普通复制选定源码；纯讨论实例不创建完整项目；执行实例按锁文件和项目命令准备依赖，缓存使用遵循现有权限。
- [ ] 3. 绑定文件读写、搜索、命令 cwd 与可访问范围；禁止实时原项目回读和跨实例写入，不共享可写硬链接、依赖目录或构建产物。
- [ ] 4. 验证两个实例同路径修改互不影响、外部与内部链接边界、绝对路径绕过、磁盘不足排队、取消/崩溃释放预留及实例独立构建。

## 定向测试

- 准备未完成时不允许启动执行工具。
- 只改 cwd 不视为隔离完成：文件工具与 shell 中的绝对路径都要验证。
- 无 Git 历史的复制环境遇到依赖仓库元数据的验证命令，预检或执行明确阻塞。

新增定向测试入口：`test/wanxiangtai/workspaces.test.ts`。使用现有 Vitest，不另引入测试框架。该文件为实施目标，目前尚未创建。

```text
pnpm exec vitest run test/wanxiangtai/workspaces.test.ts
pnpm type-check
```

定向测试必须验证对外行为及失败后果，不只复写实现细节。全量检查由批次与最终回归统一记录，不把局部通过当综合通过。

## 完成标准

- 执行实例读取固定基线加自身修改。
- 容量不足可见、可取消、可调整，不悄悄降级隔离。
- 四步均已完成，定向验证有真实结果；产物与模块文档一致。
- 交接实际文件、接口/数据版本、运行命令、已知限制和受影响下游。
- 失败时保留可追溯证据，不通过默认成功或忽略错误掩盖问题。

## 协作与变更边界

- 执行前核对前置任务已完成且契约版本一致；当前状态“未开始”，未解锁不等于发生故障。
- 本次落盘不是实现批准或验收。遵循总文档的已确认需求；新增技术方案以“补全建议”提供，执行时不得冒充用户原话。
- 先更新对应模块文档，再实现代码。不得修改本总计划以外无关需求、不得代用户审批。
- 共享文件由总负责人分配；遇到权限、状态或契约变更需求提交给核心负责人，不同时覆盖他人文件。
- 每完成一个步骤更新本任务；由总负责人同步总计划的步骤统计，避免多 Agent 同写总文件。
- 最终回归发现问题时在父计划登记新的修正小任务，不恢复已删除任务，也不改写原完成摘要。

## 评审调研结论（2026-09-12 整体评审落位）

> 来源：[整体评审与强化方案](review/design-review.md)、[可行性缺陷分析](review/feasibility-findings.md)、[技术栈调研](review/tech-stack-research.md)、[渲染栈聚焦调研](review/rendering-stack-research.md)。本节是评审产出的执行提示，只补充信息，不修改本任务既有范围、步骤与验收标准；标注 U-xx 的事项未经用户裁定前不得视为已确认需求。

### 1. 方案建议与调研结论建议
- 隔离强度按 U-01 的裁定结果落 §5.4 条款与本任务验收口径；评审组建议②「写隔离＋读审计」：写路径严格限制在实例 work 及授权目录，快照基线（manifest 登记范围）之外路径的读事件记录审计日志并在桌面可见，对原项目目录与其他实例 work 的读取产生显式告警（F-01／增-01；design-review §6 U-01）。

### 2. 可能存在的问题点
- F-01（高）：读边界现有沙箱原语不可达——macOS profile 全局放行读、Linux bwrap `--ro-bind / /` 全局读、Windows ACL 仅写边界；「固定基线＋自身修改」只在文件工具层成立，shell 层不可达。
- F-09：spawn 现状继承父 workspace，per-instance work 的接线面广（metadata、沙箱入参、文件工具、pathGuard），任一遗漏即共享工作区。
- F-12：pathGuard 仅拦 `.chery` 路径段，实例可经文件工具/命令写快照与 manifest，破坏「manifest 不是第二套业务状态」（§4.2）。

### 3. 优化建议
- 增-11：建立实例 workspace 接线清单核对表——`metadata.workspace` 覆盖、沙箱 spawn 入参 workspaceRoot、read/search/execute 四工具基线、pathGuard 基准全部指向实例 work；定向测试含绝对路径逃逸用例。
- 增-11：pathGuard 扩展 `.agent` 拦截段（服务自身通道豁免），防止实例改写快照与 manifest，纳入定向测试。
- 增-08：普通复制实现为复制策略接口的默认实现，预留二期 COW 接入（探测失败回退），不动调用方。
- 增-12：纯讨论实例的产出写入「讨论型交付目录」：仅进入集成评审、不声明验证结果，冻结规则与执行交付一致。
