## 目标

在具体差异获得用户确认后，把成果可恢复地应用到原项目。

## 输入材料与事实核对

先读[完整设计记录](design-and-history.md) §2～§10 的有效方案，再读下列入口。标为前置产物的文件由前置任务创建；其他列出的入口用于定位现有实现，不代表本任务必须修改所有文件。

- `src/service/interaction/handler.ts`
- `src/service/wanxiangtai/integration.ts（C12 产物）`

## 范围与非目标

允许承担的修改范围：

- src/service/wanxiangtai/publish.ts
- 回写候选、用户确认版本、备份与操作日志
- 回写预览及恢复协议

非目标：不顺手重构无关功能、不提前实现下游展示、不改用户项目原始文件来验证计划。具体物理文件可遵循仓库归属规范拆分，但若扩大共享写入范围，先由总负责人重新分配。不得将任务文档内算法建议升级为全局规范；需要形成规范时落入 docs/standards/。

## 执行步骤

- [ ] 1. 比较初始快照、最终集成成果和当前原项目；保留无关用户修改，将冲突形成可审核候选，不直接覆盖。
- [ ] 2. 生成新增/修改/删除差异和验证说明，用户确认绑定候选版本与目标文件预期哈希；应用前重新校验。
- [ ] 3. 实现逐文件备份、临时写入/替换及操作日志；恢复根据预期前态/后态判定，不覆盖在中断后被用户再次修改的文件。
- [ ] 4. 验证确认后源变化、文件删除、磁盘失败、多来源部分成功、中断恢复及同一确认重复提交。

## 定向测试

- 已失效确认不得应用到改变后的文件。
- 不声称跨多个目录、文件有一个原子事务。
- 确认回写不自动授权结束任务或删除实例文件。

新增定向测试入口：`test/wanxiangtai/publish.test.ts`。使用现有 Vitest，不另引入测试框架。该文件为实施目标，目前尚未创建。

```text
pnpm exec vitest run test/wanxiangtai/publish.test.ts
pnpm type-check
```

定向测试必须验证对外行为及失败后果，不只复写实现细节。全量检查由批次与最终回归统一记录，不把局部通过当综合通过。

## 完成标准

- 回写可追溯、可中止、可恢复，并保护无关用户修改。
- 四步均已完成，定向验证有真实结果；产物与模块文档一致。
- 交接实际文件、接口/数据版本、运行命令、已知限制和受影响下游。
- 失败时保留可追溯证据，不通过默认成功或忽略错误掩盖问题。

## 协作与变更边界

- 执行前核对前置任务已完成且契约版本一致；当前状态“未开始”，未解锁不等于发生故障。
- 本次落盘不是实现批准或验收。遵循总文档的已确认需求；新增技术方案以“补全建议”提供，执行时不得冒充用户原话。
- 先更新对应模块文档，再实现代码。不得修改本总计划以外无关需求、不得代用户审批。
- 共享文件由总负责人分配；遇到权限、状态或契约变更需求提交给核心负责人，不同时覆盖他人文件。
- 每完成一个步骤更新本任务；由总负责人同步总计划的步骤统计，避免多 Agent 同写总文件。
- 最终回归发现问题时重新打开本任务，不能保留虚假的“已完成”。
