## 执行步骤

- [ ] 1. 补充调度者预设：创建团队、编排、会议和集成分派；引用现有可用模型配置，不硬编码提供商，不把用户化身建成模型实例。
- [ ] 2. 复用预设解析与会话创建，建立 root 调度者→团队组长→成员的关系；创建时一次写入 teamId/instanceId/角色身份及工作区关联。
- [ ] 3. 实现任务候选预设快照、团队嵌套上限、成员不能继续派发及同角色实例限制；普通工作台保持现有规则，新增团队不刷新角色 roster 为预设列表。
- [ ] 4. 验证同预设多团队、同角色多实例、越权/超深派发、空白会话误复用、失败回收及断线后启动责任；冻结团队工具输入与结果。

## 定向测试

- 用户限定范围之外的预设不能被调度者创建。
- 实例恢复与新建有不同身份，不因同角色名误投结果。
- 成员缺少工作区或准备失败时保持可见阻塞。

新增定向测试入口：`test/wanxiangtai/team-creation.test.ts`。使用现有 Vitest，不另引入测试框架。该文件为实施目标，目前尚未创建。

```text
pnpm exec vitest run test/wanxiangtai/team-creation.test.ts
pnpm type-check
```

定向测试必须验证对外行为及失败后果，不只复写实现细节。全量检查由批次与最终回归统一记录，不把局部通过当综合通过。

## 完成标准

- 团队是记录加组长会话，不额外创建空容器会话。
- 创建团队不要求修改系统预设或重启配置。
- 四步均已完成，定向验证有真实结果；产物与模块文档一致。
- 交接实际文件、接口/数据版本、运行命令、已知限制和受影响下游。
- 失败时保留可追溯证据，不通过默认成功或忽略错误掩盖问题。
