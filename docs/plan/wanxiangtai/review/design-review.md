## 1. 评审结论摘要

**结论：有条件可行**（承 t1 §7；t2 的技术栈结论不改变该判断）。

三句判定依据：

1. 设计对现状的认知准确——t1 对 §3「现状事实」13 项逐条只读核对全部相符，未发现基于错误代码假设的方案。
2. 业务闭环 12 步无不可逾越断链——主链机制（快照、投递幂等、回合调度、决策版本、恢复顺序）均有算法、错误处理与定向测试入口；15 条缺陷全部「经调整可解」，无致命级。
3. 主要风险不在「能不能做」，而在三个跨模块交互缝隙（执行读边界 F-01、审批×看门狗×等待链 F-02、阶段更新边界 F-03）必须在对应子任务开工前钉死规格，叠加 28 个子任务的工程量；t2 确认六领域均无现成栈可整体套用，全部为「自研＋借鉴思想」，与设计「一期普通复制、不引入重依赖」的取向一致。

## 2. 模块解构

按职责把万象台解构为 14 个子系统。解构是职责聚类而非新增模块：每个子系统横跨设计章节、已确认决策与若干子任务；一条缺陷可能涉及多个子系统，下表标注其主归属，§3 给出唯一落点。S 类（数据／组件／帮助）任务随所属子系统归类。

## 4. 技术栈评估结论

**问一：业界是否已有对应技术栈？**

六领域均无**可整体套用**的现成栈。万象台的核心形态（回合制停等会议＋组织树逐级裁定＋快照／工作区／回写＋三层上下文）是「团队协作语义」与「文件安全语义」的组合，业界框架各覆盖一角（贴合度最高的是 Claude Code Agent Teams 的邮箱／回合／attempt 所有权语义，但它是产品内建 harness，不可嵌入复用）。两处例外方向上，设计已与业界标准模式**对齐**：

- **领域5 协议一致性**：operationId＋期望版本＝乐观并发控制（ETag/If-Match 同构）；业务状态＋待投递同事务＋deliveryId 幂等＝Transactional Outbox＋Idempotent Consumer 的教科书组合；桌面「快照＋增量订阅」＝事件溯源投影读模型。按标准模式自研即可，单机形态下不引入消息中间件。
- **领域3 的计量方案**：「本地估算＋服务商 usage 回报校准」正是业界通行做法；「字符数/4 不可靠」的判断与第三方基准一致（中文低估 2～4 倍）。

真正的工程缺口只有两个：**等待关系图环检测**（领域1，业界无现成实现，必须自写）与**跨平台 COW 能力探测**（领域2 二期，无统一 API）。

## 5. 强化后的方案增量（修订建议清单）

**增-01 执行隔离读边界条款（F-01）** — 性质：需用户裁定（U-01）

**增-02 阶段更新安全边界五项清单（F-03）** — 性质：补全建议

- 要点：「纯讨论实例的产出文档写入实例 deliverables 的『讨论型交付』分区：仅进入集成评审、不声明验证结果；冻结规则（版本、哈希、接收责任方）与执行交付一致。」

**增-13 快照清单预检先行（F-07）** — 性质：补全建议
- 落入章节：§5.3 算法步骤 1 后；C03 落实。
- 要点：「冻结配置后先做清单预检：枚举文件、估计时长与空间并向用户提示预计窗口；两轮重试仍失败时提供『暂存外部修改后重试』一键引导；二次校验允许抽样代替全量复制重来。」不改变 §5.3「持续变化时停止发布」的已声明限制。

**增-14 投影身份判定（F-13）** — 性质：补全建议
- 落入章节：§9 补充；[C06](../06-C06-state-projection.md) 落实。
- 要点：「三视图投影按 teamId／instanceId 判定身份与层级，不以 `metadata.type` 推断；组长预设子会话不得回落为普通『子 Agent』投影，避免组织层级误读。」

**增-15 渲染栈逐元素选库（渲染栈聚焦调研）** — 性质：补全建议（氛围层路线需 U-07；二期角色动效路线记录为 U-08）
- 落入章节：§9 补充与 [C15](../15-C15-desktop-foundation.md)／[C16](../16-C16-scenes-and-skins.md) 实现规范；不改变 D14/D15 分层架构与"业务不等待动画"约束。
- 要点：①人物移动（离席制动画）引入 **GSAP timeline**（≈28.1k stars）：状态机只产出"目标位置＋移动意图"、GSAP 仅做投影动画，`pause()/resume()/timeScale()` 支持会议打断与快速归位；②锚点拖拽引入 **moveable＋vue3-moveable**（≈10.8k，对齐线/边界约束/吸附），最薄替代 `@vueuse/useDraggable`；自动移动只读目标坐标、锚点仅由拖拽写入（D15 读写分离不变）；③气泡/详情浮层定位引入官方 **@floating-ui/vue**（≈32.7k，`useFloating`＋`arrow` middleware），样式仍复用 pet 组件；④平移缩放采用 CSS transform 统一 zoom 因子＋@vueuse 手势 composable（零新依赖），panzoom（≈7k）为备选；⑤氛围层（连线/粒子/涟漪/光效）与连线端点同步一期自写：场景图引擎属"交互画布"品类，对无交互纯装饰层过重，端点同步约 100～200 行（U-07）；⑥角色动效一期复用 CSS pet，二期 **lottie-web 首选**、Rive 备选，Live2D（专有许可：免费限年收入<1000 万日元、发布须显示商标、2025 许可费改定）与 Spine（编辑器付费）明确排除（U-08）。
- 依赖与体积：一期新增依赖合计 gzip 约 40～60KB（GSAP 核心约 23KB、floating-ui 约 3-6KB、moveable 约 20KB+）；仍需自写 5 个 composable（氛围层循环、端点同步、状态机↔timeline 编排、场景模板落位、zoom 重排）合计约 600～1000 行，均在 C15/C16 既有职责内。GSAP 为商业闭源产品（2024-11 Webflow 收购后全部插件免费商用，现行 Standard License no-charge 2025 版），采购锁版本、实施前复核官方许可页。

F-14、F-15 不产生新的修订建议：维持 t1 结论（C05 step4 既有测试、C04 step4／C14 既有释放验证项）。

## 6. 待用户裁定事项

每条含背景、候选项与评审组建议；裁定结果回填 §5 对应增量后，才修订正式文档。

**U-01 执行隔离强度（F-01，最高优先）**
- 背景：R24「固定基线」为已确认需求，缺口仅在读取保证的强度口径——现有沙箱原语无法阻止 shell 读基线外路径（t1 §1 核对 10 实证）。
- 候选项：① 新增沙箱 deny-read 读边界原语（需各平台能力调研，跨平台一致性存疑、工程量最大）；② 写隔离＋读审计（损失严格性但诚实可验证）；③ 把 work 目录移出原项目可达路径（不彻底，shell 绝对路径仍可达）。
- 评审组建议：**②**，并同步修改 §5.4 表述与 C04 验收口径；对原项目目录与其他实例 work 的读取记录审计事件并在桌面可见；残余的基线认知漂移由集成验证兜底（t1 建议）。
- 影响落点：增-01、C04。

**U-02 上帝位离线时效阈值与任务转 paused 策略（F-02／F-08）**
- 背景：D18／R13 语义下上帝位无代答者，长时间离线会使多层等待链静止；§10 仅有「合法等待独立于看门狗」原则，无机制条目。
- 候选项——阈值：A 15 分钟／B 30 分钟／C 60 分钟（均可按任务配置）；到点行为：A 仅升级提醒、任务保持等待态；B 存在等待用户事项的任务显式转 paused；C 按等待类型分级（安全审批转 paused，普通等待仅提醒）。
- 评审组建议：**默认 30 分钟＋分级（C）**：安全审批（R13）到阈值转 paused 并在桌面明示「等待用户处理」，普通等待仅升级提醒；转 paused 属确定性控制、不视为失败；恢复后既有审批继续有效。
- 影响落点：增-05、C09、C14。

**U-03 审批超时语义（F-08）**
- 背景：现状审批每条独立 deadline、超时自动拒绝（「审批超时，工具未执行」）；§10 表述「审批沿用既有期限规则，过期不转为允许」。多团队并发下用户离线→批量静默拒绝→任务大面积失败／阻塞。
- 候选项：A 维持现状（超时自动拒绝）；B 超时不自动拒绝，转「升级提醒＋保持挂起」，配合 U-02 的离线转 paused；C 分级：部分期限刚性的审批维持自动拒绝，其余转升级提醒。
- 评审组建议：**B**；任何候选项均保持「过期不转为允许」与 R13「上级不得代答」不稀释。选 B／C 需同步把 §10 该句修订为「审批沿用用户审批通道；过期不转为允许，超时处置按本条裁定执行」。
- 影响落点：增-05、C09、C17。

**U-04 三方合并原语选型（F-04）**
- 背景：§6.2 要求三方合并但未指定原语；Git 项目与普通目录需统一行为。
- 候选项：A node-diff3 为统一后端（纯 JS、普通目录可用、输出冲突块列表）；B 仅 `git merge-file`（质量最高、经过最充分实战，但普通目录不可用）；C 自研 diff3。
- 评审组建议：**A 为主，Git 来源路径可选 B 作加速后端**；合并结果归一化（换行／编码）纳入选型验收；S03 增冲突样例。isomorphic-git 与 nodegit 不推荐（t2 §2.2d）。
- 影响落点：增-10、C12、S03。

**U-05 LLMLingua 引入时点（t2 §3）**
- 背景：LLMLingua 做提示压缩是有损操作，高压缩率下强约束、异议可能被删，与设计「禁止静默丢约束」（§7.4）直接冲突；t2 定位为仅可作用于低风险大块（工具原始输出、已归档历史正文的回忆副本）。
- 候选项：A 一期不引入（白名单字段级保留已满足设计要求）；B 一期即作为「工具结果有界化」的备选引入；C 二期在专项下评估。
- 评审组建议：**A（一期不做，与 C 实质等价）**；若二期引入，决策／约束／待办白名单永不压缩。
- 影响落点：C10 二期范围备注。

**U-06 token 计量实现路径（F-05）**
- 背景：`estimateTokens`＝字符数/4 对中文系统性低估，C10 需落每请求计量；跨厂商模型 tokenizer 各异。
- 候选项：A 一期引入 tokenizer 映射（tiktoken／js-tiktoken 精确 OpenAI 系，国产模型用官方计数），依赖增加；B 保守系数上修（中文≥1.5×/字）＋usage 校准，tokenizer 留二期；C 每模型混合（OpenAI 系用 tokenizer、其余用系数）。
- 评审组建议：**A**（t2 一期建议采用「tokenizer 映射＋usage 滚动校准」）；若需控制一期依赖，C 为折中；无论何者，usage 滚动校准必做、压缩请求自身也过预算检查。
- 影响落点：增-09、C10。

**U-07 氛围层一期实现路线（渲染栈聚焦调研）**
- 背景：用户诉求"优先复用热门库、拒绝小众项目"；调研结论为氛围层（无交互、纯装饰、业务不等待动画）没有 Vue Flow 级即用库——Konva（≈14.7k）/PixiJS（≈48.1k）属"交互画布"品类，命中/事件/序列化能力本层用不上，引入即"为不需要的能力付包体税"。
- 候选项：**A** 一期维持原生 Canvas 2D＋单 rAF 自写（零依赖）；**B** 一期即引入 Konva＋vue-konva（官方 Vue 3 绑定、场景图＋Tween、MIT，是"Vue Flow 级"升级路径中最顺的复用选项）；**C** 一期引入 PixiJS（WebGL 性能天花板，体积/上下文开销最大）。
- 评审组建议：**A**；若您偏好"能复用就不手写"的取向，**B** 为最顺的复用选项（实施前复核 vue-konva 维护活跃度）。无论如何 PixiJS 保留二期特效演进位。
- 影响落点：增-15、C16。

**U-08 二期角色动效路线（记录备查，不阻塞一期）**
- 背景：D14 一期人物层复用 CSS pet；角色动效属二期增强，但许可证陷阱与美术管线成本需提前知晓。
- 候选项：**A** lottie-web（≈32.1k、MIT、AE 资产生态最大、与皮肤"词表＋模板"数据驱动契合）；**B** Rive（状态机与"运行状态绑定动画"最契合，但 stars≈5k 边缘＋编辑器订阅 $9/月）；**C** Live2D／Spine（许可证陷阱／美术管线成本，明确排除）。
- 评审组建议：**A**，B 备选。
- 影响落点：二期皮肤动效专项。
