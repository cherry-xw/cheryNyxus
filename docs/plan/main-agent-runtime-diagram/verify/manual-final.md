# 完整头部与 Vue Flow 结果树最终实机验收手册

对应[最终验收清单](../07-final-verification.md)，由用户在真实浏览器或 Electron 执行。目标以[展示契约](../../../frontend/runtime-diagram.md)为准；不沿用上次被否定的界面结论。

## 前置条件

- T23 完成且最终自动检查通过；记录同一构建的提交/工作区标识、设备、系统与浏览器/Electron 版本。
- 准备无外部副作用的可丢弃任务：单轮文本、同名多工具、审批通过/拒绝、失败重试、并发子任务/返回、continuation/detail、压缩与长图。
- 难触发场景可用确定性 fixture 驱动真实产品图组件；标明来源，不能用独立假演示替代产品接线。
- 准备深浅主题、宽窄窗口、system/full/reduced、后台/最小化及可恢复断线。官网比较在正常图、full、高质量下执行。
- 卡牌对照本轮开发前当前行为；T07 A07 重登记基线检查冻结范围，实际选择和阅读仍需验收。
- 用户手动打开 [Animation and Layout](https://vueflow.dev/examples/layout/animated.html) 与 [Transition](https://vueflow.dev/examples/transition.html) 比较；自动 Agent 不操作这些页面。

## 1. 完整头部静态流程

1. 打开活动主干并定位头部，切 reduced 检查不依赖动画的结构。
2. 沿接入、请求、模型、分流、工具、记录、继续/等待/结束逐条查看箭头。
3. 检查重试、条件审批/拒绝、工具失败、Loop 回边、协作派发/回传/接收/唤醒、压缩生成/采用。
4. 检查上下文供给和模型输出通道，无细粒度记录项目明确说明；查看长中文、状态、端口与分组。
5. 平移阅读完整图，不把全图强压成小字；检查其他分支内容不被头部覆盖。
6. 切换运行、轮次和尝试，确认完成槽位保留且下一轮重置；读取“未归属运行的记录”，确认接收、回传、唤醒不被混成同一事实。打开节点说明后按 Escape 或关闭按钮，焦点返回原步骤。
7. 总览先确认只见封装芯片与接口；逐层进入 Loop → 内容记录 → 工具 → 重试 → 模型。每层只出现直接元件，Loop 为调度器，后四项为中间件；检查输入资源、模型内压缩和工具内协作。
8. 检查每张板无交叉、重叠或穿元件线路，主路径优先短连；P 编号端子可查看完整关系及条件并定位两端，不被误读为执行步骤。详见第 8 节。

通过标准：递归封装准确表达层级，执行关系可逐层追踪；各层共存且布局紧凑，连线连续且无交叉，展开与收起入口清楚。

## 2. 新绘制结果树与增长

1. 提交单轮消息，观察输入、流式产物与最终结果逐步进入树。
2. 执行工具与子任务，查看工具、派发、返回、分支和过程组。
3. 切换现有折叠档位，检查内容、计数和因果；同名调用仍可分别定位。
4. 让头部发生多次校验/重试，检查结果树不因此逐步增加内部历史节点。
5. 运行结束后结果留下、头部保留终态；下一运行重置头部而旧结果仍可读。
6. 在空白画布上连续移动鼠标，检查高亮块平滑跟随且只在运行图区域内出现；依次移入不同尺寸的结果节点和头部节点，检查高亮块连续形变并精确贴合当前节点的可见包围盒，整个节点同步高亮，移出后恢复跟随状态。
7. 高亮存在时反复执行节点点击、键盘聚焦、拖动画布、拖动节点和滚轮缩放，检查选择、平移、拖动、缩放及 tooltip 均正常，高亮层不拦截指针或焦点，也不滞留在上一节点。
8. 切到 reduced，确认取消跟随与形变，仅保留清晰的静态 hover/focus；在触摸设备或粗指针模拟环境重复进入画布，确认不创建鼠标跟随块，节点仍可选择和操作。

通过标准：新的 Vue Flow 节点/边与当前新版逻辑；不是旧 Pixi 外观恢复，也不是步骤 journal 平铺。无重复结果、虚构边或等待整轮结束才补树。正常鼠标环境下高亮块跟随流畅，进入节点时完整覆盖并贴合节点边界，离开时自然恢复；它不影响点击、拖动、平移、缩放、键盘或 tooltip。reduced、触摸和粗指针环境按上述规则降级且不残留动画。

## 3. 官网参照动效逐项比较

在正常图/full 档逐项记录通过或失败：

| 参照效果 | 操作 | 产品必须出现的效果 |
| --- | --- | --- |
| AnimationEdge 沿边传递 | 连续步骤和工具调用 | 可辨执行标记沿完整路径行进并经过转折，非瞬移或仅虚线滚动 |
| ProcessNode 状态联动 | 等待、完成、拒绝/失败 | 运行图标及终态外观切换，状态文字同时正确，不只变色 |
| 多分支推进 | 至少两个并发子任务 | 各分支独立路径反馈，不串状态 |
| 回路反馈 | 重试与下一轮继续 | 反馈沿对应回边推进，失败 attempt 不被新成功覆盖 |
| 结果生长 | 新消息/工具结果 | 新节点平滑出现、新入边反馈；有 anchor 时表达头部产物到结果的关系 |
| Transition 路径定位 | 显式定位关联结果，再手动拖动 | 路径光点移动且相机平滑跟随；用户操作立即打断 |
| 快速事件 | 快速完成或取消 | 真实状态即时显示，旧动画可取消，无排队延迟与重复可选节点 |

6. 逐类查看输入、上下文、模型、工具、控制、协作、压缩和结果节点，确认图标、能力色与边框结构可在不读内部 ID 的情况下区分；切换运行、等待、成功、失败、拒绝和中断，确认 Morphicons 图标连续过渡，文字立即更新，颜色不是唯一线索。
7. 让模型进入流式响应，确认对应模型节点下方出现紧凑 CRT，正文与可用思考持续打印并自动跟随；手动上滚后不强制拉回底部。运行结束后 CRT 立即移除、不保留空闲占位；断线遮罩可覆盖 CRT，切 root 和进入回放不混入旧实时内容，结果树只保留一个真实结果节点。
8. 在 reduced 与低质量档重复图标、连线和 CRT 场景，确认空间移动、弹性 morph 和装饰循环关闭，最新状态、文字、语义色与静态路径仍清楚。
9. 只把鼠标移到每个步骤的 Info 图标或用键盘聚焦该图标，确认简要说明在节点上方立即出现；移出或失焦即关闭，移到节点其他区域不出现。点击或触摸点按 Info 不打开、不固定也不切换说明。普通节点主体点击打开完整实例详情；存在当前根待处理事项时，等待审批节点主体点击只聚焦节点下方的操作面板。各入口不会互相抢行为或触发画布平移。

通过标准：官网沿边传递、节点状态和流程推进的效果实际出现在产品中，不能用少量淡入替代。节点能力和状态均可辨、Morph 图标过渡可中断，模型 CRT 能实时呈现且正确收束。允许主题图标代替卡车与项目直角外观；不要求复制官网业务内容。暂停跟随后实时执行不抢相机，动画完成不控制业务执行。

## 4. 当前卡牌冻结回归

1. 用现有开关打开/关闭卡牌，刷新检查原偏好。
2. 从消息、工具、过程组及头部显式内容锚点选择，检查准确调用页签。
3. 阅读长正文、换行、参数/结果，操作滚动、复制和原有详情动作。
4. 在宽窄窗口检查布局和关闭行为；选历史后响应当前审批/提问。
5. 检查没有新卡牌外观、旧模式回滚、新方向/布局开关或强制卡牌入图。

通过标准：当前卡牌外观、交互、开关、偏好、阅读能力无本轮变化；新图适配准确，无错选与相机跳动。

## 5. 工具、分支与步骤详情

1. 检查完整工具清单，选非当前 call，更新不抢查看对象且可返回当前调用。
2. 审批拒绝/失败后，未发生的槽位中性；等待说明对象。
3. 历史选择保持时响应当前请求，检查操作对象及影响。
4. 选择 original/continuation/detail/子孙 Agent，只有实际活动主干完整，选择不自动激活。
5. 打开步骤详情，查看重复实例、attempt 和分页；有 anchor 可定位内容，无 anchor 有说明，步骤不展开进结果树。

通过标准：身份、状态、步骤与任务产物界限清楚；既有命令语义正确。

## 6. 恢复、回放、相机与可访问性

1. 冷打开、断线重连、旧代/历史读取，内容和卡牌可读且不补播。
2. 回放中播放/暂停/seek/调速，新实时内容不混入，操作不发送/审批/唤醒/激活。
3. 返回实时显示最新状态；无 journal/gap 明确说明，空回放 0/0。
4. 使用缩放、100%、适配与定位；正文增量与暂停跟随后状态更新不抢相机。
5. 用键盘访问节点、清单、步骤详情、卡牌、待处理入口；深浅主题、宽窄窗口重复操作，多窗口关一个不影响另一个。

通过标准：内容可读、操作可达、焦点清晰，无副作用、遮挡或非预期视角变化。

## 7. 生命周期与性能

1. full 场景依次切后台、最小化、断线、root、回放；停用时持续效果停止，恢复不补播。
2. reduced 与 system 跟随系统偏好生效；质量降级保留静态状态。
3. 正常图和至少 2,000 业务节点的压力 fixture 分别测试：先执行 `__CHERY_PERF__.reset()`，连续至少 30 秒平移/缩放、选择、结果增量、路径动画后读取 `__CHERY_PERF__.snapshot().frames`。
4. 每组记录 sampleCount、p95Ms、maxMs、图规模、动效/质量档和设备信息；至少 300 个有效样本，不足则重测。
5. 多次开关工作台和 root，检查残留动画、持续冻结或明显输入滞后。

通过标准：正常 p95 ≤20ms、压力 p95 ≤33ms；压力可减少装饰，正常 full 不得省略第 3 节效果。不可见即停、关闭清理，不用最后一帧或主观观感代替 p95。

## 记录与证据

各节记录执行人、日期、环境、通过/失败及复现，第 3 节逐效果记录。核心头部、结果树、官网动效、当前卡牌不能标不适用；先补足可丢弃测试数据。

用户自行保存的文字/证据可放本目录 out/（不纳入 Git）；向 Agent 返回文字结论即可，不要求其读取图片。长期证据按项目政策迁入 docs/quality/verification/。任一核心项失败必须修正，不以自动检查通过结束任务。

## 8. 紧凑嵌套、完整引脚与运行跟随

前置：准备包含模型、工具审批、重试、协作和压缩的可丢弃会话；打开工作台节点树，分别在深浅主题与宽窄窗口检查。

1. 默认总览的封装紧凑；逐层展开到模型时，确认循环、记录、工具、重试、模型同时存在，外围步骤始终保留。展开其他兄弟封装，先前展开的层不消失。
2. 检查大封装不会把外围每一排拉宽；内层在父层边界内，同排节点不重叠，文字至少 12px。尝试拖动元器件，位置保持锁定，空白画布仍可平移。
3. 全部展开所有层，从外部线沿封装引脚追踪至内部步骤；四向引脚按相邻节点位置合理选择，边界内外连线连续，收起时只剩单颗芯片和对外引脚。条件、回路、失败和返回路径完整；交叉、跨线桥、共线重叠、无关接触或穿元器件不得出现。确认上下文资源位于模型层并连接请求准备；响应分流位于大模型响应正下方，模型层无多余底部空白；本轮入口与消费记录水平直连，消费/指令节点上下排列；工具结果、内容记录、继续判断竖直对齐；运行图不再显示“工具调用 · N 项”重复面板，协作四节点保持单行水平直连。重点沿工具主链、五类失败出口、续接和协作逐条追踪；相邻步骤线路简短，没有无意义的小台阶或反复折返。
4. 节点主体只显示名称与状态图标/颜色，没有“尚未发生”和重复摘要；Info 在上方展示说明，不依赖原生 title。仅鼠标悬浮或键盘聚焦显示，移出或失焦关闭；点击和触摸点按无动作。普通节点主体仍可打开实例详情，等待审批节点按当前根入口规则处理。
5. 开启“跟随运行”，执行模型、工具、重试：全部层保持展开，视野定位当前步骤，并发活动层同时保留；结束后保持展开，模型节点下响应面板随流式结束立即移除（不保留占位）。正文增量不反复移动相机。
6. 手动平移/缩放、展开/收起、查看历史或步骤详情后跟随暂停，后续执行不抢阅读对象。点击“跟随运行”恢复最新状态；全部展开、全部收起与单层收起的作用范围准确。
7. 快速切换步骤、展开/收起、root、回放、断线和最小化：无旧相机覆盖新选择、无排队动画；回放允许手动浏览但不自动跟随。reduced 保留即时布局和短淡入。
8. 全过程确认结果历史、卡牌和审批接口不变。重复进入返回时焦点可见，条件标签不遮字，模型面板不压住下一排。

通过标准：紧凑、多层共存、连续引脚、信息简洁、运行跟随与手动查看可控。记录执行人、日期、设备、窗口尺寸及失败复现；证据由用户留存到 `verify/out/`。自动几何检查不替代本节视觉和交互验收。

## T25 验证更新

旧自动结论仅为 T24 基线，T25 后重跑几何、阅读、状态、动画、类型和构建。人工补验：层级色系、响应向下出线、info 不重复开侧栏、全文悬浮窗及双页切换、点击卡片和拖宽/键盘调宽、工具栏可点击、运行 loading/定向脉冲、CRT 累积滚动和独立工具/审批信息。按现有手册环境与证据方式记录；未执行不计通过。

最终补充验收：悬浮 info 必须仍为原248px提示框，在头部全展开及其他板遮挡位置仍处最高层，移出关闭，点击不固定。打开历史回放不再出现 DataCloneError；回放时实时新增内容不改变固定快照。用户检查深/浅主题、阅读区拖宽/键盘调整及左侧历史按钮可点击，记录环境、日期、执行人和结果。


## T27 验证范围

旧自动结论不作为本轮通过证据。重跑图投影、256种展开布局、状态/边证据、跟随导航、动效及跨根交互隔离；类型、ESLint、全量 Web 测试及构建通过后登记结果。

前置条件：前端加载本轮修改；新运行同时需要后端加载修改。旧历史回放无需重新运行，使用有序步骤、身份和锚点恢复可确定的链路，不补造缺失的真实步骤。沿用前文环境、账号及证据保存规则。

1. 从用户输入触发模型输出、工具审批/通过/拒绝、结果返回及下一轮。沿线确认整次 run 已走过的路径持续高亮，跨层不断开；下一轮不能擦掉上一轮，未走分支不亮。
2. 确认只有正在运行的具体节点有强光框动效；已结束节点仅静态亮起，等待节点显示静态警示，外层封装不强调。切换回放/后台/断线/精简动效后停止循环但保留路径。
3. 当前流程出现待处理事项后，操作面板自动显示在审批节点正下方并水平居中，不先点击摘要、不打开左下角窗口。点击审批节点主体只把焦点移入面板，不控制显示或关闭；点击 Info 也不得打开该面板。确认无额外标题与关闭按钮，内容较宽，长表单提交按钮可达。
4. 分别使用 35%、50%、100%、180% 缩放并平移画布；审批与 CRT 保持固定可读尺寸，锚点跟随各自节点移动。输入、选择、内部滚动不触发画布交互。
5. 未提交时依次收起工具处理、内容记录、循环调度和整个头部；不自动展开任何层，审批面板依次迁移到最近可见祖先，全部收起时位于头部下方且草稿保留。CRT 按模型调用、重试控制、工具处理、内容记录、循环调度、头部的相同规则迁移。两者落到同一锚点时审批在上、CRT 间隔 12px 在下。
6. 处理完最后一项后审批面板自动消失，CRT 生命周期不受影响。切换根会话不显示原根请求；右侧入口的计数、列表和左下角浮层只含其他根会话，不重复当前根事项。检查工具调用选择、阅读区和原审批提交/失败行为兼容。
7. 选择修复前的历史记录，分别查看文本、工具审批、失败重试及多轮执行；已记录阶段之间有连续静态高亮，前后 seek 只显示截点内路径。对比新记录回放，均不得只剩零星节点；记录缺失步骤或身份歧义时保留不完整提示。

以上 UI 项均待用户实机执行，记录日期、执行人、运行身份、结果和必要证据。

## T29 审批与 CRT 最近可见祖先操作卡

入口：准备一个当前根待审批任务并让 CRT 显示实时输出，打开运行图。

1. 保持目标节点可见，确认审批贴在“等待审批”正下方，CRT 贴在“模型请求”正下方；拖动画布时二者与节点同步移动。
2. 依次收起模型调用、重试控制、工具处理、内容记录、循环调度，确认两个窗口各自迁移到最近可见祖先下方，过程中不自动展开节点，输入草稿不丢失。
3. 收起整个头部，确认审批在头部下方，CRT 与其同锚点时位于审批下方 12px；在 35% 与 180% 缩放下窗口尺寸不变且不被钳制到页面边缘。
4. 完成全部审批，确认审批窗口消失；CRT 仅在模型节点流式活动时显示，结束后立即移除、不保留空闲占位。断线遮罩仍可覆盖两个窗口。

期望现象：锚点、顺序、移动、缩放、折叠与生命周期均符合[交互入口规范](../../../standards/modules/agent/runtime-diagram-interactions.md)，无页面固定居中入口。

结论：待执行（记录日期、执行人、环境及失败复现）。

## T28 最终流程补充

以下场景只使用更新后生成的可丢弃 run；旧测试数据无需兼容，可清空后重新生成。

1. 提交第一条用户消息，确认“输入接收”立即成为当前强高亮，并依次经过“输入排队 → 本轮入口 → 消费与输入记录 → 请求准备 → 模型请求 → 大模型响应 → 响应分流”；上下文构建/恢复同时以供给线连入请求准备，未经过的分支保持暗色。
2. 分别执行纯文本、单/多工具、审批等待与通过、拒绝、失败重试、多 iteration；当前节点有强实时强调，所有已经执行的节点与跨层线段保持静态高亮，工具返回后的下一次模型调用仍属于同一条连续 run 路径。
3. 触发用户确认或等待输入，确认等待节点表达真实等待原因；恢复后只沿实际唤醒/消费路径继续，不点亮未发生的审批、执行、失败或重试分支。
4. 模型给出最终结果后，确认头部显示“等待用户输入”，已完成路径不熄灭、不收起；再发送一条新消息，头部切换到新 run 的独立路径，上一 run 与新 run 之间没有因果连线。
5. 打开上述 run 的历史回放并前后 seek，确认与实时使用同一节点和连线投影、只显示截点内已发生路径且没有动画；返回实时后显示最新 run，不混入旧 run 高亮。

通过标准：每个新 run 从输入到最终结果可连续追踪；循环、工具、审批、等待和重试只按真实事实点亮；当前强高亮、完成静态高亮、结束等待态、新 run 隔离及回放静态投影全部符合上述规则。
