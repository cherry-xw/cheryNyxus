# T08 统一生长图设计与契约

**文档创建时间：** 2026-09-10T14:43:17+08:00

状态：进行中（仅文档规划）。所属[总任务](README.md)。复杂度 5/5：消息图与执行观察融合。依赖：既有基础。当前不修改代码、依赖或权威现状说明。

## 已确认的产品结构

- 同一张持续生长的执行图融合历史与当前头部，不再保留“独立流程面板＋旧节点树”的双画布结构。
- 主 Agent 采用展开式多层回路：核心流程清楚、诸多细节节点共同构成完整头部；全细节骨架常驻，含 Loop。
- 多工具调用共用头部处理链，每次调用独立身份与状态；共用展示不等于合并历史。
- 子 Agent 仅显示简略头部，不复制完整主头部；其全部实际阶段与细节仍保留历史。
- 步骤实例完成后向后沉淀，模板保留；重复执行形成不同历史实例，各分支独立增长。
- Vue Flow 为拟采用的画布基础，不照搬默认样式。Mermaid 不作运行/动画引擎；OpenFlowKit 的 React/React Flow 栈不直接引入，可参考分组与布局设计。

## 主头部草图与层次

下面是区域关系，不是底层函数顺序；暂按历史在左、向右生长示意，方向属于建议默认值。

```text
                         身份 / 当前阶段 / 轮次 / 等待原因
                        上下文与资源供给区
                                 │
历史 ─ 接续口 ─ 本轮接入 → 请求准备 → 模型交互 → 结果分流
                  ↑                    ↕            │
                  │                 近端重试         ├─ 无工具 ─┐
                  │                                 ↓          │
                  │                              工具处理区    │
                  └────── 继续下一轮 ─── 循环判断 ←──┴──────────┘
                                            │
                                      等待 / 本轮结束
记录带：连接输入、响应和工具结果的实际记录位置
协作接口：任务派发 → 子分支；结果接收 ← 子分支；继续运行独立表达
```

| 层次 | 信息 | 建议形态 |
| --- | --- | --- |
| 核心节点 | 环节名称、短状态，例如模型请求、循环判断 | 较大直角节点 |
| 细节节点 | 具体执行步骤，例如消息转换、参数校验、结果处理 | 紧凑矩形，有中文名称 |
| 附属信息 | 资源数量、条件说明、Hook 挂载、所属执行层 | 端口、标签、轻量括线，不冒充执行步骤 |

区域用留白、浅底与细括线组织，不做层层厚边框。连线区分顺序、条件、回路、资源供给与协作关系；静态箭头始终存在，动效不能成为唯一方向提示。

## 区域细节候选

| 区域 | 拟展示内容 | 必须保持的语义 |
| --- | --- | --- |
| 上下文与资源 | 构建/恢复，角色指令、环境、记忆索引、技能发现、有效历史 | 资源不是执行步骤；完整构建不每轮重演；发现元信息不是加载正文 |
| 本轮接入 | 新输入合入、指令注入、返回结果接入、工具续接 | 运行中输入进入队列，不另外制造主执行链；工具续接可跳过模型 |
| 请求准备 | 媒体准备、请求选项、消息转换、上下文检查 | 细节来源需真实边界；不会为视觉填满而补记未发生阶段 |
| 模型交互 | 请求、等待响应、接收响应及文本/可用思考摘要/调用组装通道 | 通道可交错，不画成“思考完→文本完→工具”的固定串行链 |
| 工具处理 | 调用清单、参数校验、授权、条件审批、执行前检查、执行、结果处理 | 审批/前置检查通过后才是真正执行；列表顺序不冒充执行并行 |
| 重试 | 本次尝试失败、部分输出撤回、退避、下一次请求 | 重试是模型近端支路，不重启完整上下文；失败尝试仍留历史 |
| 记录 | 输入保存、响应保存、调用/结果记录 | 贯穿执行而非最后统一保存；记录完成不等于任务完成 |
| 循环与协作 | 继续、等待、结束、派发、返回接收、唤醒/继续 | 派发成功不等于子任务完成；返回接收不等于主模型开始 |
| 压缩 | 请求、摘要生成、实际采用、阶段边界 | 只在采用后切有效上下文；历史图保留，代际仍可访问 |

本表是目标清单，真实可观察位置与数据缺口由 T12 逐项论证。Hook 先保留已接线的条件挂点，不把 stub 或配置存在画成实际执行历史。

## 共用工具链

调用清单保留每个 call 的名称、身份与状态，处理链默认呈现当前调用。建议允许选中其他调用查看其记录，并明确标记“正在查看”，提供返回当前入口。多次同名调用不合并；列表溢出仍能访问全部调用，不挤压主路径。拒绝/失败停在有证据的位置，未发生的后续节点保持骨架。

## 子头部

两三行：角色名称、当前具体环节、等待或异常状态。它位于自身分支末端，与详细历史、派发来源和回传目标连接。子 Agent 派发下级时，继续使用简略头部，不升级为完整主头部。历史保留策略与主 Agent 一致。

活动主干切换及用户创建的 continuation/detail 分支不是子 Agent 血缘；其完整头部身份规则仍需单独收敛，不能依据角色名称猜测。

## 模板、实例与历史

模板位置稳定，实际实例有独立 ID。未开始时整个可用结构以弱化骨架显示；启动后只突出有证据的实际步骤。模板节点不因完成被永久移走，每次执行另形成历史实例。

实例结束状态必须区分成功、失败、拒绝、取消与中断；暂停和等待不是成功。历史按主干/分支组织，内部细节可折叠，不跨派发、返回、汇合、用户入口等因果边界合并。旧历史没有证据时明确缺失，不生成推测步骤。

新实例如何逐项脱离或短时间成组沉淀，属于动效默认方案；它不能改变历史粒度、事件顺序或真实运行速度。

## 建议默认值（尚非视觉验收结论）

- 先以横向展开式头部验证：核心节点约 144×64，细节节点约 128×52；间距按文字、端口与路由预算确定。主题 token、直角、中文≥12px、正文 400、标题≤600。
- 头部占完整工作台图形区域，与历史共用相机，不再限制于 232–300px 的顶部条带。窄窗平移查看，不把整个图自动缩成无法阅读的小字。
- 支持空白拖动、缩放、100%、适配图、定位头部；默认不持续跟随，普通状态更新不抢用户相机。节点不能拖动改变业务流程，不能编辑连线或删除执行事实。
- 复用现有消息详情、工具页签、审批/提问、折叠、分支和代际读取；只替换图形呈现不能丢失这些操作。
- Vue Flow 管理外层定位和相机，GSAP 只处理内层视觉；动画允许取消并立即落到最新状态。
- 首次恢复直接显示现状，实时新增实例才产生生长动效；后台、最小化、断线与回放暂停停止持续动画，reduced 保留静态可读反馈。
