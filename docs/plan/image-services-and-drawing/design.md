# 会话绘图的已确认设计与剩余验收

本文维护仍用于图片服务与绘图接手工作的已确认要求，不表示全部已实现或可用。当前授权、小任务和唯一恢复点见[任务入口](README.md)；通用存储、配置保存及图片上下文以正式模块说明为准。

## 1. 能力、数量与请求

### 1.1 D21—D22 的能力归属

能力属于实际图片模型、接口和操作，不属于主/子 Agent 的聊天模型。`image.generate / image.reference / image.edit` 分别声明，输入参考图和输出上限分开。目录推荐、用户覆盖、适配器实际实现、连接已验证状态不得混淆。

| 已批准字段 | 含义与约束 |
| --- | --- |
| 目录 `imageOutput[operation]` | 具体型号与适配器的推荐限制；仅匹配实际 adapter 时采用 |
| 连接 `capabilities.imageOutput[operation]` | 用户覆盖；专用图片模型在文件服务模型配置中编辑，真正原生输出才放大脑配置，不在角色另存一份 |
| `nativeMultiImage` | `supported / unsupported / unknown`，单次原生图片操作能否返回多张最终图 |
| `maxImagesPerRequest` | 正的安全整数，单次输出上限而非默认张数；未知不编造 |
| `countControl` | `requested / maximum / uncontrolled / unknown`，按张数请求、最多几张、不可可靠控制、未核实；按张数请求也不保证全部成功 |
| `maxInputAndOutputImages` | 可选的参考图与输出合计限制；无此约束时不填 |
| `files.imageGeneration.defaultCount` | 唯一全局默认，正的安全整数，默认 1；本次模型限制不回写它 |

解析按用户覆盖→匹配型号/接口的目录→未知，同时受适配器真实实现限制。查询返回来源、依据、有效上限及不可用原因；单图声明却上限大于 1、支持多图却缺上限等矛盾保存时拒绝。未知可保存，但不开放可控多图。手动覆盖标为尚未验证，不能解除官方不允许或尚未实现的参数。

Responses 顶层是对话模型，实际图片型号来自 `image_model`；`ep-*` 接入点不能用字符串猜实际型号。不借同厂商或聊天模型上限。已确认可调用但张数不可控的接口保留单次入口、无数字调节并说明返回张数不可控，不能伪装固定单图；单次操作也未确认时不得放行。

### 1.2 期望值、有效值与配置迁移

1. 新绘图草稿读全局默认作为期望张数，用户可调整；能力查询不调用服务。
2. 有效上限取实际模型、接口、操作和本次输入条件中最严格者；合计限制按真实参考图数量扣减，小于 1 则拒绝，不把 0 改 1 或丢参考图。
3. 可控接口的有效张数为 `min(期望张数, 当前上限)`。超限编辑完成时立即回显上限并解释；空值、0、负数、小数、非有限值报错，不四舍五入。确认单图固定 1，不发送不支持的数量参数。
4. 切模型、接口、操作或参考后重算；低上限→高上限可恢复原期望值，用户主动编辑后以新期望为准，不读取别窗临时选择。收小不改全局默认。
5. 全局默认只初始化新草稿，不覆盖已编辑或已提交轮；主动恢复默认使用当前已保存全局值。试用使用本次试用草稿，不改全局配置；普通工具数量也用同一计算并记原值与收小原因。
6. 已选择破坏性替换旧服务数量默认，移除 `defaults.n / sampleCount / sequential_image_generation_options.max_images` 及读取兜底，不保留双重默认或兼容期。已有全局显式值保留，首次引入设 1，不从多个旧服务猜选。实际运行迁移另获授权并先一致备份，只清旧数量默认，不改其他参数、会话、文件、凭据或历史操作事实；中断按版本化边界恢复。
7. 厂商当次 `n / sampleCount / max_images` 仍可合法发出。张数收小是已批准特例，不扩展为自动改尺寸、比例、质量、格式、操作或参考图。自然语言张数/指代由模型理解，与明确参数冲突时说明并确认，不用程序关键词规则猜测。

### 1.3 单次生成、委派与排队

- 同一候选批次仅一次原生生成操作，多张图来自该响应；不循环单图、不并发单图、不派多个子 Agent 凑数，不用失败补偿补图。关联组图可保留，但不承诺是多个独立方案。
- A 直调或委派 B 传递同一绘图请求、固定参数、选定输入和来源；B 不拆给多个子 Agent 绕限制。角色能力和工具权限、禁用操作继续有效，绑定服务不增加权限。
- 返回候选后等待用户选择或反馈；只有用户明确提交新生成/修改才建新批次。其他任务的自动改图授权不能解释为补齐张数。
- 后端在远端调用前复核，归一参数参与去重；同一标识不同参数冲突，ACK 重试、刷新和重复子完成不得多建轮或生成。
- 发送时固定配置版本、真实型号/接口/操作、期望与有效张数、其他参数及有序输入版本。排队期间影响结果的连接/型号/限制变化应中止未执行操作并提示重新确认；不悄换模型、再次收小后执行。启动后的快照保持原事实。

### 1.4 厂商依据与未解决前置

资料核对日期 2026-10-18，非当前服务可用性证明。MiniMax/Seedream 已取得正文，OpenAI 主要是官方搜索摘录，Google 正文当时超时。恢复按同接口和有效版本补证据，不能用新接口指南替代当前适配器定义。

| 图片接口 | 数量映射与当前证据边界 |
| --- | --- |
| MiniMax `image-01` | [文生图](https://platform.minimax.io/docs/api-reference/image-generation-t2i.md) `n=1–9`，缺省 1；其他型号/参考操作单独核实。人物参考不等于通用编辑 |
| OpenAI Images 的已确认 GPT Image 型号 | [生成](https://developers.openai.com/api/reference/resources/images/methods/generate)、[编辑](https://developers.openai.com/api/reference/resources/images/methods/edit)摘录为 `n=1–10`，具体型号/兼容站另验；当前适配器不支持 DALL·E 参数模式 |
| Responses 图片工具 | [指南](https://developers.openai.com/api/docs/guides/tools-image-generation)的 `partial_images` 是同图预览；多个图片工具调用不等于单次原生多图。尚无等同 Images `n` 的明确依据，不开放可控多图 |
| Gemini `generateContent` | [图像指南](https://ai.google.dev/gemini-api/docs/image-generation.md.txt)不保证按要求返回张数；`candidateCount` 不等于图片数，14 张参考图也非输出上限。保留各 candidate 最终图，多 candidate 不造共用私有续接；单次控制与上限仍需补证据 |
| Seedream 5.0 pro/flash | [官方 API](https://ark.volcengine.com/docs/image-generation-api.md)固定单图，不发送组图字段。图层拆分不是候选图，当前不支持图层结果契约 |
| Seedream 5.0 lite/4.5/4.0 | `auto + max_images=1–15` 控制最多几张，参考与输出合计 ≤15；`disabled` 仅 1。仅为数量依据，型号 ID 与其他参数/实际可用性另核 |
| Imagen | [Gemini 入口](https://ai.google.dev/gemini-api/docs/imagen)摘录显示已关闭；[Vertex Imagen 4](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/models/imagen/4-0-generate)摘录列最多 4，同时 001 标注 2026-06-30 停用。`sampleCount` schema 1–4 不能证明 Ultra 上限，本地仍限 1；必须核实有效项目、地区、型号和完整端点，不推荐停用型号或用 Gemini 替代 |

完整多轮必须有真实参考/编辑方式，不能用 MiniMax 人物参考或 Imagen 文生图冒充通用修改。用户允许 Imagen 单独阻塞，其他已确认产品代码与离线验证先实施；实际迁移、生成、部署和界面权限仍分别核对。

### 1.5 收到、保存与失败分开

保存期望张数、有效请求张数、最终收到数、成功保存数和厂商明确报告的失败数；局部预览、私有思考图、蒙版、输入参考不算最终输出。

- `requested` 少返回时保留成果、报告部分产出；没有单项错误就写未提供原因，不用差值编造失败项。
- `maximum` 正常少返回时报告“最多 N 张，实际 M 张”，不是少出的每张失败；任务是否满足单独判断。
- 部分下载/保存失败只重试仍可取得结果的保存，不重生成；响应从未可靠取得且无查询接口时，不保证可恢复。
- 多出的有效成果保留并提示参数与结果不符，不悄丢；不可控接口不能保证费用上限等于界面张数。
- 不足、审核阻止、未知、重启或检查未通过不自动补图；新生成必须新请求，不能叫重试保存。生成/保存/检查/任务完成/父接收/渠道送达分别判断。

## 2. D23 的轮次、候选与定稿

复用统一资产、文件操作与任务结果，不建另一套文件存储。固定资产版本、权限、有序 parts、原图不可变及来源规则仍有效。

| 对象 | 记录与关系 |
| --- | --- |
| 绘图任务 | 所有者、会话/分支、来源消息、任务标识及各轮关联，不是会话最后一张图 |
| 绘图轮 | 稳定请求标识、上一轮/选定图、反馈、有序输入版本、真实服务/型号/接口/操作、固定配置参数与数量事实、`operationId` 及可选委派任务 |
| 候选图 | 绘图轮、输出位置、`assetId + assetVersionId`；图号只为展示，不是数组下标或文件名身份 |
| 修改对象 | 明确选中的固定版本，只进入下一草稿，不反改已提交轮 |
| 用户定稿 | 选择版本、任务及选择记录版本；独立于子任务成果与自动采用，不因子任务结束自动产生 |

`chat.input.submit` 在有序 parts 外传结构化绘图意图，包含服务/角色、操作、期望/有效参数、能力配置版本、任务/来源轮及选定资产。不拼隐藏提示词后丢事实。后端保存最终快照，ACK 关联可查询任务/轮次；断线查询原记录，不重建。普通聊天无需这些字段，不按关键词强制切绘图。

绘图模型只影响下个草稿，不修改聊天大脑或在途图片请求。队列、分支、协议投影、历史/导出和 AI 工具保留关联；旧消息只能普通重新引用，不伪造绘图轮。

候选保存后本轮已结束，展示等待用户选择/反馈，不继续转圈。选图仅更新目标草稿；提交反馈才建新轮；定稿只登记用户选择，不生成、检查、外发或删除其他候选。定稿后再改建立新轮，已有定稿不自动换成新结果。

自然语言指代由模型结合消息理解；程序仅校验明确资产的权限和归属，不用最后一图、唯一候选或时间窗口替用户选择。不明沿现有提问；用户明确点击则直接用该身份，不重复确认。

私有续接关联产生它的操作与候选。选中单图不自动发送整批；供应商要求完整历史时按官方方式保留并明确目标，不裁签名/思考，不借别图续接。必要历史计输入数量、字节与上下文预算；不能可靠指定分支时改用支持的本地固定版本参考/编辑，不支持则报限制，不能纯文字重画冒充编辑。跨模型、连接或身份不复用不兼容私有块。

选图/定稿校验身份、任务、版本、已保存可读；无权/缺失时拒绝、不自动改选。重复动作返回已有结果、不生成；双窗定稿按选择版本冲突检查，不静默覆盖。草稿按后端/窗口/会话隔离，轮次/候选/定稿持久且保护引用；刷新、归档及子任务清理不丢有效文件。失败新轮不清旧候选或定稿，等待选择不等于生成失败。

## 3. 界面与异常交互

### 入口与发送

- 树、对话、精简和快速发送共用草稿；明确绘图入口，进入/退出不发送或请求服务，保留文字及合法引用。
- 先展示实际服务/图片型号和操作，再展示合法张数、比例/尺寸；高级质量/格式按需展开，不新增凭据入口。指定角色时显示它真实图片模型，多服务未选时提示先选；缺权限/型号未知/不支持编辑如实说明并提供已有配置入口。
- 收小后的数值立即可见，字段旁必要原因只写一次，详细依据放 info tip；`maximum` 写“最多生成 N 张”，不可控显示“单次生成，返回张数由模型决定”，无数字调节。
- 参考区标明修改对象及其他参考的固定版本。发送前可读服务、型号、操作、数量含义与参考，按钮依任务为生成/提交修改，不再加无意义重复审批。
- 空提示、缺服务/编辑输入、非法参数或不可执行时就近解释并阻止提交；输入法组合期间 Enter 不发送，控件可键盘操作，不仅靠拖拽/hover。

### 候选、反馈与返回

| 动作 / 状态 | 反馈与恢复 |
| --- | --- |
| 提交/ACK | 防重复、显示排队或生成；采用快照属本轮，后续编辑属新草稿，失败不清新输入 |
| 生成中 | 真实阶段/输出，无证据不造百分比；关闭窗口不停止，重连读原操作，预览不当候选 |
| 已保存候选 | 按轮/图展示完整预览、下载、基于此图修改、定为最终稿；使用固定版本，等待选择不转圈 |
| 基于此图修改 | 标目标草稿、定位反馈输入；不发送不生成，反馈提交后才下一轮 |
| 用户定稿 | 保存后显示用户已定稿，不写模型检查通过；失败保留选择和错误 |
| 定稿后继续改 | 旧定稿仍可查，新候选不自动替换；子 Agent 系统采用不能标用户定稿 |
| 新轮失败/无图 | 原因与可用恢复动作可查，保留成功历史，不自动换服务、重画或补齐 |
| 换不支持编辑的模型 | 保留图和反馈，明确限制，让用户选支持服务，不退回文字重画；续接失效按第 2 节处理 |
| 冲突/返回 | 定稿冲突回读后由用户决定，不覆盖别窗；草稿本地隔离、已提交记录服务端恢复。归档只读，继续修改先选活动目标；迟到不改新草稿或唤醒停止任务 |

错误、部分成功和未知分别显示；只有厂商给证据才写失败 N 张。查询重试不是生成重试，超时不自动发第二次。窄窗先换行/折叠高级项，保留模型、数量、修改对象与发送入口；候选保持完整比例，触屏能发现动作。沿[前端设计语言](../../standards/frontend/design-language.md)，不缩字裁图或复制旧皮肤来掩盖布局问题。键盘、触屏、主题和 200% 缩放的实际渲染由用户验收，不用源码或 DOM 检查代替。

## 4. 剩余验收矩阵

以下均为要求，不是全部已通过；已有离线证据和人工通过范围见[文件能力验证](../../quality/verification/file-capabilities.md)，不重复执行已通过的常规文件批次。

| 编号 | 操作与必须观察到的结果 | 验证方式 |
| --- | --- | --- |
| IM01 | 同型号换接口、按生成/参考/编辑改限制、手动覆盖/恢复推荐和未知接入：来源正确，不借聊天上限，不解除未实现参数 | 自动 + 人工 |
| IM02 | 初始全局 1、保存与刷新、旧服务数量迁移：唯一默认、无双轨兜底，本次值不回写；其他参数、数据与凭据保持 | 自动 + 人工；实际迁移另授权 |
| IM03 | 示例期望 6/上限 4、编辑 9、换单图：显示有效 4 和原因，单图固定 1；示例不是默认 | 自动 + 人工 |
| IM04 | 高→低→高、主动改数、变操作/参考、别窗改全局：按期望重算，不盖已编辑草稿，合计不足 1 阻止且不丢输入 | 自动 + 人工 |
| IM05 | A 直调或委派 B 同批多图：同参数/来源，每批仅一次生成，不反复单图或派多个子角色凑数 | 自动拦截 + 授权真实任务 |
| IM06 | requested/maximum 少返回、审核阻止、多返回：收到/保存/明确失败分开，不编造、不丢有效成果、不补图 | 自动 + 授权真实接口 |
| IM07 | Responses 局部预览/多工具调用、Gemini 多 part/candidate、私有思考图、Seedream 组图/不可控：仅最终图计候选，不混淆独立候选与关联组图，不可控无数字调节 | 自动 + 授权真实接口 |
| IM08 | 发后改模型/全局，排队限制改变，ACK 同 ID 重试：在途不变，排队变更阻止远端，只有一轮一次生成 | 自动 |
| IM09 | 首轮多图→选图→反馈→新候选→定稿→继续改：输入和参数可追溯，提交才生成，旧候选/定稿保留，用户定稿不等同自动交付 | 自动 + 授权编辑 + 人工 |
| IM10 | 选早轮/同批别图、私有历史含别图、跨连接编辑：命中选定版本，不错用续接或裁签名，无合法方式明确阻塞 | 自动 + 授权真实接口 |
| IM11 | 打开、改参、预览、选图、定稿逐动作核对调用数：均不生成，无要求不额外识图，不用关键词/最后图选目标 | 自动 + 人工 |
| IM12 | 双窗选图/定稿、切会话/后端迟到、刷新/归档：草稿隔离，轮次定稿恢复，冲突可见，不续写归档 | 自动 + 人工 |
| IM13 | 远端成功本地部分失败、未知、取消迟到、重启：保留成功图，只恢复下载保存，不重发、不唤醒停止任务 | 自动 + 授权真实接口 |

## 5. 共享流程与恢复要求

文件理解逐资产规划，同一比较问题联合处理；支持的原生图片/PDF、文本读取与工具提取分别确认，不能仅凭格式或能力勾选说已理解。仅附文件不前置读取；无工具模型只有显式系统前置理解，不假装可自主委派。只发图无问题默认描述，不自动生图。

理解缓存包含有序固定版本、问题/必要语境、处理对象/配置及范围，仅复用成功记录；新问题不能直接套旧问答，批观察不重复注入。角色与预设覆盖、工具组授权和关闭操作必须一致，不能按注册先后选服务或自动失败换付费对象。

生成结果先登记再交付；子任务明确成果或各独立链最后成功批次回主会话，同批多图保留，中间稿可查，用户定稿独立。后台执行不依赖窗口，回写归正确交付会话，重复终态只消费一次。用户明确要求检查时有真实检查来源与状态；默认不额外视觉检查，不能看图的角色不能声称检查过。

远端任务 ID 与响应尽早持久，查询/取消按实际接口能力；审批、排队、执行期限分开，取消未确认和结果未知不标成功/已取消。迟到成果可保存但不恢复已停止父任务。服务删除保留查询所需非敏感快照，重试仍校验当前权限/凭据，不偷换服务；撤销凭据不能借旧引用继续调用。

这些跨角色、保存重试与引用清理的组合由[文件权限与交付验收](../file-access-and-delivery/README.md#必须保留的行为与组合检查)共同承担；职责各自明确，不产生第二份配置或文件存储。完整需求核对后才集中测试；离线、真实服务、生产依赖和用户交互分别有结论。

## 6. 首次查询异常的取证准备

ID05 缺少首次 400 的原始请求/响应和同次后端记录，不能重建猜测请求作为原因证明。后续正常使用如复现，由执行者在获准范围内保存时间、请求路径、调用目的、脱敏请求体、认证是否存在、状态码、错误 code/字段与关联标识，再匹配后端日志和当时固定源码；不保存 Cookie、令牌、文件字节或无关业务正文。

区分空列表查询、带过滤查询与创建绘图轮，不因都是 POST 就认为触发了生成。先核对实际入口及参数校验，再查身份/会话权限；空列表没有服务不是拒绝理由。当前失败后停止重复只能证明请求控制行为，不能证明首次拒绝修复。需要额外请求、配置写入、生成或服务操作时先取得具体授权，不以取证准备自动执行。
