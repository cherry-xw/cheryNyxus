## 已证实问题与定位

### 续期日期回复

- 测试应用 `accept-ledger-20261028` 的续期请求 `2c3661e6-2ad4-41f4-b1d2-578862dfe4ce` completed，原生回复已确认发送。工具返回 `state=stopped`、`leaseVersion=2`、`leaseExpiresAt=1793870317058`，对应北京时间 `2026-11-05 17:18:37.058`；QQ 文字却为 `2026-11-04 20:38`。续期实际成功且没有启动服务，错误发生在结果到文字之间；目前不能认定模型为何得出该日期。
- 发布来源的 [`managedApp.ts`](../../../apps/backend/src/agent/sense/managedApp.ts) 中，`publicResult` 过滤控制器内部字段后直接返回 JSON，`renew` 结果保留毫秒数字。没有已确认的“程序负责日期转换”新规则，不擅自用固定文案或额外程序判断代替模型职责。
- 证据在发布目录 `verification/m03-renewal-tool-result.json`、`m03-initial-lease-tool-results.json`、`m03-renewed.json`，仅含所需期限、状态和发送确认，不保存凭据。正式原始请求仍按既有数据库访问权限查询，不读取 root 状态文件。
- 下一步：接手执行者只读核对本次工具输入、输出和回复使用过程，比较可行修正方式及影响，提交明确方案。方案与部署范围获准后再安排最小复验，不重复停止、启动或新增记录。

### 实时响应缓存

- 新应用 `accept-public-20261028` 源码与发布模板一致，两个入口均能匿名取得实时 `connected` 事件，但响应为 `Cache-Control: no-cache, no-transform, no-transform`，缺少正式约定的 `no-store`。连接成功和缓存断言失败分别保留，不宣称前后端不通。
- [`template/server/index.mjs`](../../../apps/backend/src/service/managedApp/runtime-image/template/server/index.mjs) 的 `/events` 路由覆盖统一中间件的缓存头；[`gateway.ts`](../../../apps/backend/src/service/managedApp/gateway.ts) 保留上游值并附加 no-transform。旧模板探针对 SSE 没有禁止缓存断言。
- 证据在发布目录 `verification/m04-public-checks.json`、`m04-events-cache.json`。旧报告 24 项中 22 项通过、2 项缓存断言失败，不改写原报告。
- 下一步：先确定模板、测试、运行镜像、宿主模板及已建应用各自是否纳入修正；不得自动覆盖既有用户源码。补充缺失断言的方案与生效方式确认后，再实施和定向复验。
