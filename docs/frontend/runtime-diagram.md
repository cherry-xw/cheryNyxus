## 当前交互规则（替代下文旧展示位置与收起策略）

- 默认跟随运行时全部层始终展开，结束后不自动收起；手动浏览暂停相机跟随。
- 分类底色始终常驻，包括未参与和历史回放。已参与节点使用较显眼的静态边框、名称与引脚；只有正在运行的节点叠加呼吸光框，等待节点保留静态等待提示。展开的外层封装不做执行高亮。默认保留本次 run 的完整已执行路径，跨层、跨轮次和重试接续均不断开；显式历史/调用选择才收窄范围。仅有证据的连线点亮并沿方向脉冲，回放、后台、断线和精简动效停止循环。
- 实时响应面板（CRT）属于**大模型响应**节点，挂在节点正下方：存在正在返回数据的模型 turn 时随流式增量就地累积思考与正文，turn 结束或节点空闲后自动移除，不保留空闲占位。**实时输出期间“模型请求”与“大模型响应”两个节点一并点亮**（同一 live turn 驱动 running 态，不伪造 occurrence）；提交后由响应 occurrence 承接 succeeded。折叠隐藏大模型响应时，CRT 改挂到运行图投影给出的最近可见祖先下方；一次模型 occurrence 依次证明“模型请求 → 大模型响应 → 响应分流”，工具调用仍由工具清单节点与审批交互展示，不在模型面板或运行图中额外重复调用选择面板。
- 当前根会话的审批与提问在事项出现时显示于节点树工作台左下角，并作为唯一直接操作入口；事项完成后自动移除。窗口可经右侧铃铛收起/展开（角标显示当前根待处理数量；收起后新事项到达不自动展开，由角标计数与标题栏/任务栏闪烁提示）。任务中心聚合其他根事项，不得产生同一事项的第二个可提交面；流程图侧栏不承载审批或 CRT 覆盖层。精简（lite）模式下铃铛切换的是提问面板自身的折叠/展开，不隐藏 lite 视图。**对话模式（2026-09）**下浮窗照常渲染；**待处理提问可直接在消息列表内作答**——`QuestionRenderer` 在等待中且命中 pending 提问批（`call.id`=questionId）时切换可交互形态（选项点选/补充/提交，走 `interactions.answer`，草稿与浮窗共享），提交后自动回退只读展示。
- 新记录由真实执行边界写入既有 `causeOccurrenceId`，显式关系优先。同一 run 内的 exact 上下文和请求事实证明资源供给边，不占用请求的单一执行前驱。回放与实时使用相同 occurrence 和连线投影，回放只停止循环动效。本轮不迁移或兼容既有测试数据，可清空后重新生成。

## 1. 结构与边界

采用 XY 平面内原位伸展的递归芯片封装：展开后父层、外围步骤和子层同时存在，内层撑开父封装，形成洋葱圈式包裹；收起后恢复单颗元器件与对外引脚。禁止以切换单板或 Z 轴叠片替代多层共存。层级为 Loop 调度器 → 内容记录（checkpoint）→ 工具（sense）→ 重试（retry）→ 模型（chat）；后四项才是 defaultHandlers 中的四层中间件。输入与唤醒在总览封装，上下文资源与压缩属于模型封装，协作属于工具封装，展示归属不改后端执行身份。上下文就近放入模型层，避免资源供给与输入/唤醒共同封装后形成非平面连接；原有资源供给关系完整保留。中文至少 12px，正文 400、标题至多 600。

唯一 activeBranchId 的主分支展示完整节点树；其他分支与子 Agent 使用标准简略节点。节点树主视图使用 canonical timeline 与 Pixi execution renderer，保留横向 Signal 排版、纯图标节点、稳定 lane、hover 详情、CRT 与运行/连线动画。流程图使用独立 workflow journal 投影和 Vue Flow 相机，仅在侧栏可见时运行；结果历史和阅读器不改变节点树主渲染底座。流程图只渲染主 Agent 流程：头部流程图只覆盖根会话及其分支（完整头部 + 分支简略头部），子 Agent 不渲染头部流程图，其内容节点仍保留在流程图结果树中。

## 2. 全部连接关系

下表的连续箭头表示独立关系；条件和供给不表示必然执行。层边界端口不是执行步骤，不新增后端事件。

| 区域 | 关系 |
| --- | --- |
| 接入 | 输入接收 → 排队 → 本轮入口 → 消费；有指令时消费 → 指令注入；消费或注入后进入内层 |
| 请求 | 上下文构建/恢复 → 请求准备（并行供给）；消费或指令 → 请求准备；请求准备 → 模型请求 → 大模型响应 → 响应分流 |
| 返回 | 响应分流 → 内容记录（文本/摘要）或调用清单（工具）；内容记录 → 继续判断 |
| Loop | 判断 → 本轮入口（下一轮）、等待或结束；等待 → 实际唤醒 → 本轮入口；暂停/取消/中断只读控制事实 |
| 重试 | 模型 → 错误判断；可恢复 → 退避 → 请求准备；耗尽/不可恢复 → 失败终态；不重新执行整个 Loop |
| 工具 | 清单 → 参数校验 → 权限校验 → 审批判断；需要 → 审批，无需 → 预检；通过 → 预检 → 执行 → 结果 → 内容记录 |
| 异常 | 参数/权限/审批拒绝/预检/执行失败 → 拒绝或失败结果 → 工具结果；共享结果收集通道不表示等待所有来源 |
| 续接 | 工具续接 → 重建清单及适用校验/授权/审批链，跳过模型；已失效工具 → 工具结果，不直接跳过授权到预检 |
| 协作 | 执行 → 派发 → 子执行摘要 → 回传 → 父接收；父接收仅凭明确关系连接唤醒或实际消费，不强制进入等待 |
| 压缩 | 请求准备 → 压缩请求 → 摘要生成 → 实际采用 → 请求准备；未采用不强调返回路径 |
| 结果树 | canonical 的 sequence/continue/spawn/dispatch/return/return-continuation/fork-continuation/fork-detail 及现有展示连接保留；结果末端 → 对应头部 |
| 选择 | 步骤 → 内容仅在显式锚点定位时临时显示，不长期重复铺线 |

模型流式内容可在调用未结束时向外归集。“大模型响应”和“响应分流”由同一模型 occurrence 的响应阶段及终态证明，不伪造额外后端事件。工具清单按 callId 区分同名调用，共用一套处理链；清单顺序不制造因果。没有独立事件的节点保持中性，详情说明未单独记录；状态只按 kind/reason/waitReason 与显式 anchor 匹配，不匹配自由文本。运行、轮次、尝试和调用隔离，终态保留；祖先仅显示内层活动，不伪造自身执行。局部失败不推导 run 失败。

## 3. 递归折叠与路由

封装按独立展开集合控制；展开父层不会隐藏其他层或兄弟节点。递归先测量内部尺寸，再按固定拓扑位置和布线间距向外排版，节点拖拽保持锁定。外部线路接芯片边缘引脚，内板对应引脚与内部线路在同一坐标接续，保留完整原始关系。CRT 与审批面板都使用原始目标节点的最近可见代表作为屏幕覆盖层锚点，整个头部收起时使用头部。本轮入口与消费记录的中心高度对齐，入边水平直连；消费与输入记录、指令注入上下排列。模型层中响应分流位于大模型响应正下方，封装底部只保留布线与标签所需间距。工具结果、内容记录与继续判断在跨层同一中心线上竖直排列；任务协作四节点保持单行水平直连。

原始节点映射到自身或最近的可见封装。每条关系在经过的层内各有一个线段，跨层引脚共点连接，保留原始关系 ID、方向、条件与独立执行证据；点击引脚可追踪两端，不新增执行事件。收起层内关系记账，不能丢边或伪造自环。

按完整连接拓扑安排紧凑节点位置，展开尺寸逐层向外传播，不把大芯片列宽传播给外围各排。节点与封装允许左、右、上、下四向引脚；引脚位置和环绕次序由内外线路共同决定，不固定左入右出或按关系数组顺序堆排。线路必须无交叉、无共线重叠、无无关接触，并避开元器件、实时面板及说明标签；同一关系跨层接续允许共点。不得用跨线桥、断线、隐藏边或分散跳接端子代替完整无交叉连接。在这些硬约束下优化线长与转弯次数；无可用路径时先调整节点位置、引脚或通道，不以交叉兜底。布局缓存有界，正文增量不触发重新布线。工具主链纵向排列，审批位于失败汇入区内侧；五个失败来源接同一语义结果节点的独立引脚，续接走外圈。

默认跟随运行时全部层保持展开，结束后不自动收起。只有活动身份或展开几何改变才调整视野，正文流式增量不触发相机。手动展开、收起、选择历史或移动画布暂停跟随，显式恢复跟随重新读取当前事实。回放、断线、后台、切 root 和卸载取消待执行相机任务；手动展开集合按 root/header 隔离。缩放阈值只展开或收起一层，外围始终保留。

## 4. 信息、相机与动画

节点主体显示名称与状态图标，工具环节补充实际调用名称；层级分类色与执行路径色分别表达归属和参与状态。去掉“尚未发生”、覆盖率和重复轮次等摘要。说明由明显的信息按钮在节点上方展开，不用原生 title 承载说明；完整参数/结果/错误和实例历史由现有阅读器或只读步骤详情读取。无锚点不按时间猜关联。轮次与尝试在头部选择器呈现。CRT 在屏幕覆盖层锚定模型请求或其最近可见代表，按 root 权威实时态读取当前 run 的思考与正文；仅在该节点活动（存在正在返回数据的 live turn）时显示，turn 结束或空闲即移除，不保留占位；正文内滚动并提供通道切换和回到最新，折叠不改变生命周期。

折叠布局一次计算代表节点、端口与新路由，再由 GSAP 统一过渡。子图在封装与内部板之间缩放收拢；展开与收起过渡期间隐藏线路，元件到位后恢复嵌套布局的已验证线路，避免中间帧穿透或交叉。约 280ms、可中断反向、无排队；reduced 即时布局与短淡入。生命周期按 [动效规范](motion-standard.md)，后台/断线/切 root/回放/卸载清理。执行标记仅按有因果证据的 live 增量沿真实路径移动；hydrate 不补播。Morphicons 沿现有例外仅负责图标形变。

相机按 root/header/板保留；首次显式展开定位到对应封装并保持可读缩放，返回恢复原视野，普通增量不自动 fit、不重排结果历史。窄窗口平移与显式定位，不缩小字号。图内按钮、滚动和详情阻止画布串扰；标题、进入、返回、接口追踪与详情具有键盘路径和焦点恢复。

## 5. 实现与验证入口

[RuntimeDiagram.vue](../../web/src/features/agent/workbench/runtime-diagram/RuntimeDiagram.vue) 连接 controller 与选择；[graphModel.ts](../../web/src/features/agent/workbench/runtime-diagram/graphModel.ts) 的 projectWorkflowGraph 适配同一 Vue Flow。纯模板与状态通过 headerTemplate/headerState 定义，headerGraph 构建头部，纯层级/可见关系/布局计算在组件外完成。数据流为语义图 → 展开集合及封装代表 → 递归测量与紧凑布局 → 内外引脚与连续布线 → 展示；不在组件里临时删除边或猜端点。

[headerEdgeEvidence.ts](../../web/src/features/agent/workbench/runtime-diagram/headerEdgeEvidence.ts) 的 `projectHeaderEdgeEvidence` 统一维护直接因果、结构中继与别名分流的连线证据；对应回归为 `web/test/agent/workflowEdgeEvidence.test.ts`。

内部展示接口维护层父子关系、展开集合、可见代表、关系成员、引脚、端口、路径和模板版本；RPC/schema/journal 不变。布局由 `headerLayout.layoutHeader` 与 [headerNestedLayout.ts](../../web/src/features/agent/workbench/runtime-diagram/headerNestedLayout.ts) 的 `buildNestedHeader` 维护；[headerCircuitPlacement.ts](../../web/src/features/agent/workbench/runtime-diagram/headerCircuitPlacement.ts) 的 `placeCircuit` 维护各层位置、四向端口和边界次序。`headerBoardRouting.routeBoardEdges` 先按短距离试布，受阻时撤回并优先重布该关系；[headerCircuitRouting.ts](../../web/src/features/agent/workbench/runtime-diagram/headerCircuitRouting.ts) 的 `circuitRoute` 包含进入方向与转弯代价，交叉及接触不可用。条件标签在全部线路完成后避让放置；固定模板缺少完整路线或标签位置时显式报错，由全组合回归阻止交付。`useHeaderBoardNavigation` 持有展开导航、可暂停运行跟随、相机和接口追踪。扩展节点时同步层归属、位置与引脚约束、关系表、证据匹配和全部展开组合验证。

定向 Vitest 覆盖全部 256 种展开组合的关系守恒、封装边界映射、逐层进入/返回和 root 隔离、路由穿透/标签/端口、工具异常/续接、重试/Loop、交错协作、压缩、gap、root/回放及动画清理。验证入口：pnpm test:web、pnpm web:type-check、受影响 ESLint、pnpm web:build。最终自动与人工清单唯一维护在活动计划，旧通过不能替代新契约验收。浏览器/Electron 操作及视觉验收由用户执行，正常 p95 ≤20ms、压力 p95 ≤33ms。

## 运行反馈与阅读交互

层级使用 `--workflow-layer-color` 分类色，复用 `workflowVisuals` 现有模块调色板，包内节点沿用所属层色系；运行路径统一使用主题强调色，已完成节点不改变外框。真实因果与结构中继投影驱动脉冲方向，运行节点有 loading，停用/回放/隐藏/精简动效时停止循环。Info 只在鼠标悬浮或键盘聚焦图标时显示节点简介，移出或失焦即关闭；点击或触摸点按 Info 无动作，不得打开或固定说明。说明 teleport 到 body，并使用共享 `OVERLAY_Z_INDEX.tooltip` 最高提示层，避免被任何嵌套板遮挡。

结果节点悬浮显示可交互全文窗口，思考与正文分开切换；点击打开现有内容卡片。工作台卡牌、流程图与阅读器统一为右侧抽屉打开（历史对话抽屉同款：半透明遮罩 + 标题栏 + 关闭按钮），覆盖节点树但不压缩画布（画布保持全宽），抽屉默认 50% 宽、最小 300px 或 24% 容器宽、最大 88%，左缘拖拽手柄及键盘调整（← 变宽 / → 变窄 / Home / End），点遮罩或 ✕ 关闭；关闭抽屉后画布完整可见。对话模式按钮有独立空间，不被卡片遮挡。模型 CRT 挂于模型请求或其最近可见代表下方，仅在模型节点活动（live turn 正在返回数据）时出现，按当前 run 展示流式累积，直接绘制实际增量，流式结束或空闲后自动隐藏；最新 6000 字符与累计字符数避免长输出冻结，全文在阅读卡片查看；工具环节按 call 身份挂载名称和状态，审批仍通过既有入口处理。

当前根会话表单由 `WorkbenchDialog` 直接传入 `RuntimeDiagram` 的 attention 插槽；审批和 CRT 的目标节点经 `WorkflowGraphProjection.representatives` 解析为最近可见代表，节点展示及覆盖层定位由 `useWorkflowNodePresentation` 维护，世界坐标到画布宿主像素的换算由 `headerAttentionPosition` 维护。覆盖层在锚点下方居中，不参与相机缩放；事项出现即显示，点击审批节点主体只聚焦面板内首个操作控件。内部滚动、按键和选择不触发画布操作。切根以根身份隔离表单。左下角窗口只展示当前根会话事项，由右侧铃铛收起/展开；其他根事项由任务中心聚合，不再提供工作台内独立入口。问题按请求分组、逐题排列、每组独立提交，提交失败保留草稿。

决策窗口（`WorkbenchAttentionSurface` + `WorkspaceSessionBrowser` stepper 模式）**单卡逐批次**：批次 = 卡片，每批次一张卡（一次 LLM 响应含多个问题即一个批次），同一时刻只完整展示一张卡，不做多卡堆叠。标题栏 `← 批次 n/N →` 切换批次卡（仅多批次时显示）；卡内一次只显示一道题，题目切换 `← 题目 n/N →` 固定在窗口底部操作栏左侧（与提交按钮同一行，提问批次始终显示，单题时按钮禁用）；该批全部题目答完才能提交，提交后卡片淡出消失；单个批次整批一次性提交。窗口宽度 600px；标题栏无关闭按钮（收起/展开走右侧铃铛入口），`提交回答`/`接受`/`拒绝` 固定在窗口底部单独一行（提交前置禁用：全部题目完成前显示「请完成全部问题」）；事项属于当前节点树（`rootChatId` 等于当前根）时不显示「在节点树中查看」。选项交互：选中选项不再自动展开补充输入，改由选项按钮**内部末尾**的「补充」tag（无边框纯文字标签，高亮只变文本色）展开；「其他补充」**直接就是输入框**（单选模式下获得焦点即取消选项选中态，多选可与多选共存）。所有已输入内容（选项补充与其他补充）跨展开/收起、切换选中、切题、切卡一律保留，提交时仅收集选中选项的补充。

## 头部运行编排

头部以真实执行事实驱动运行演示，静态拓扑只定义可走路径。节点分为未参与、正在执行、等待、已结束；层封装只说明内部活动。只有正在执行的具体节点有呼吸高亮，等待保持原因与警示色，已结束节点保留静态参与标记。节点当前状态与 run 累积轨迹分别投影，不能因节点已经结束而撤掉整段连线。

| 场景 | 运行表现 |
| --- | --- |
| 输入进入 | 接收、排队与实际消费之间，沿已证明的关系跨封装传递；本轮入口只是中继，不伪造执行事件 |
| 模型输出 | 模型请求保持活动；CRT 就地累积思考、正文、已发布工具参数/结果；进入响应阶段后依次点亮大模型响应，token 增量不重置动画和相机 |
| 响应分流 | 模型响应终态点亮响应分流；明确消息/工具事实只点亮实际返回分支，不要求不存在的额外事件 |
| 工具与审批 | 共享处理链展示选中 call；条件中继按后续真实因果证明路径，审批等待保持静态提示，不假装正在执行工具 |
| 失败与重试 | 失败来源到失败汇入节点可共享同一实例；退避、再次请求各自读取记录，不能用整轮重新亮起来代替重试 |
| 返回与下一轮 | 归集、判断和实际入口按因果接续；下一轮开始时，上一轮已运行的链（工具链、内容记录、继续判断等）整体回到灰色 idle（确定性"不在本轮"事实），再随新 loop 的实时事件重新点亮；输入/排队/上下文等 run 级事实保持常驻，不参与逐轮重置 |
| 并发与折叠 | 所有活动层可同时展开；收起时保留跨层线路的参与状态，子执行仍有独立身份 |
| 完成与恢复 | run 完成后已执行路径静态保留，头部回到等待用户输入；新 run 开始后切换到新路径。暂停、回放、断线、后台及精简偏好停止循环，保留静态证据 |

连线证据由纯投影统一计算：直接因果、同一事实的分流/失败别名，以及仅穿过无独立事件中继的唯一有向路径。歧义路径不高亮；不跨越无证据的真实执行步骤。按 run、轮次、尝试、call 隔离，并保留当前范围内较早因果，避免只看最新槽位而丢失已走线路。跨层线段以共享路径长度和相位持续传递，活动更亮更快、历史更弱更慢；瞬时事件反馈与持续参与反馈各自可回收。

内容记录（checkpoint）的入边：后端只建立一个 checkpoint occurrence（边界建立时挂接工具结果关系锚点，消息提交复用），前端投影同时证明两条入边——模型响应→响应分流→内容记录（cause=模型）与 工具结果→内容记录（通过 checkpoint 的消息锚点 callId 匹配工具结果 occurrence），两条边指向同一 targetOccurrenceId，在同一帧点亮。
