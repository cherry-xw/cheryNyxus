# 工作台 Lite 极简 UI（交互设计）

本文维护浏览器工作台精简视图的当前入口、数据流和交互要求。源码存在与实际验收分别核对；未确认偏差明确列为待核实，不由临时开发阶段或版本记录决定业务规则。

## 当前实现入口

精简视图由 `apps/web/src/features/lite/LiteView.vue` 承载，工具详情由 `LiteToolCallDetail.vue` 与 `DetailDrawer.vue` 组织；待处理审批和提问在工具详情内通过 `LiteInteractionView.vue` 操作。功能说明以对应当前章节及实际源码为准，不保留版本修订台账。

## 1. 目标与定位

**一句话**：在工作台窗口内，用一条 ?profile=lite&v=1&maxFrameBytes=2048 的独立 WS 连接，渲染一套纯文本、极低流量、可完整交互的对话 UI，与现有富 UI（节点树/拓扑/角色编制/消息气泡）互为可切换的「双子界面」。

**核心叙事（展示优势）**：
- **紧凑展示**：用户消息与最终回复直接显示，中间节点以摘要和详情入口组织。展示简化不证明传输被裁剪；低流量要求与当前接线的差异见 §3。
- **操作交互便捷**：极简但完整——发送 / 审批 / 提问 / 停止 / 查看详情，全部可在 lite 视图内完成。
- **按需详情**：中间节点默认折叠为状态行，点按才通过 chat.timeline.node.get 按需拉全文。

**与现有UI的关系**：同一工作台窗口通过标题栏在树、对话、精简三视图间切换，见 [工作台说明](workbench-multi-window.md)。精简视图是共享工作台会话的展示方式，独立的是窗口/根会话界面状态，不是另一个WebSocket连接。

## 2. 切换入口与布局

### 2.1 切换位置（用户已拍板）
- **工作台窗口标题栏**放一个**三档分段切换钮 `WorkbenchViewToggle`**（树 / 对话 / 精简）；同一窗口共用 `useWorkbenchViewMode`。
- 每个工作台窗独立（windowId=presetId 维度），互不影响。
- 切换状态**按窗口持久化**（localStorage key `cherynyxus:workbench-view-mode:<windowId>`，旧两档键 `cherynyxus:workbench-lite-view` 读取时迁移；沿用 useWorkbenchWindow 的 per-window key 模式），刷新后保持。
- 不提供全局默认值开关（保持每个窗口独立，符合工作台「每预设一窗」模型）。

### 2.2 lite 视图布局（自上而下）
- 标题栏由工作台窗口承载，精简内容在窗口内容区渲染；不描述不存在的原生窗口挂载方式。
- 状态条显示连接/运行状态、加载提示、节点数、会话信息及链路切换；多链路标签仅在 `laneTabs.length > 1` 时显示。流量统计接线见 §3.4。
- 对话流（可滚动）
  - [用户] 消息 A（用户消息全文）
  - ⟳ 运行中…（中间节点=状态行，无内容）
  - [agent] 最终回复摘要
- 审批/提问入口：点击对应工具调用进入详情抽屉，由工具卡内的交互区处理，不提供常驻审批/提问页签行。
- 输入区（自适应多行输入 + 发送，Enter 发送 / Shift+Enter 换行，）
- 底栏（分页/更多 / 节点详情抽屉入口）
- 阅读区和输入区使用各自主题样式。审批/提问属于工具详情抽屉，不将常驻交互面板的底色、页签和布局要求用于当前主视图。具体外观以现行设计规范和用户视觉验收为准。

## 3. 数据来源与连接

### 3.1 当前连接归属

浏览器精简视图通过 `useLiteCanonicalView.ts` 读取工作台共享的会话、连接与交互store，不自行创建socket、订阅、加载或重放状态。`liteStore.ts` 只保存按窗口和根会话隔离的界面状态，不保存连接、时间线或交互收件箱。

因此不能把浏览器精简视图写成独立 `profile=lite` WebSocket客户端。协议侧低流量profile是否提供、固件是否使用，与浏览器视图实际采用的连接是不同问题，不能互相推导。

### 3.2 当前会话读取

`useLiteCanonicalView` 优先读取根会话的 `conversation` 时间线，其次 `tree`、`audit`；执行态读取 `executionReadModel`，交互读取共享交互store。命令通过共享接口执行，不由精简视图再建立一套加载和重放流程。

这里不再把单独的 `chat.list → chat.open → interaction.list` 顺序描述成Lite自行执行的初始化链。实际连接、加载、重连与权限边界由工作台的公共层维护。

### 3.3 展示模型与待确认要求

`toLeanNode` 在客户端将共享时间线转换为展示节点：用户消息和面向用户的Agent消息保留正文，中间工具节点以工具名或节点类型提供摘要。展示摘要不等于服务端没有传输完整内容，不能由紧凑界面推导低流量预算已经满足。

如果独立低流量连接仍是有效需求，须确认它与当前共享会话架构的关系，单独核对连接实现和协议测试；本次仅说明当前代码，未取消或重新批准此项需求。

### 3.4 流量展示与待确认要求

当前 `LiteView.vue` 状态栏显示连接/运行状态、加载提示、节点数、链路切换和会话名，以及停止/继续入口；组件和控制器中未定位到本文所述“本会话流量 ≈ X KB”的累计字段或展示。不能写成流量统计已接通，也不能据此取消原有统计需求。

流量统计要求与接线仍待确认：须定义统计方向、范围、重连后的累计策略和心跳排除方式，再与连接层实际数据核对。原文的首刷16KB及事件512B、验收段2048B存在不同口径；这些数值不作为已实测结果或新的硬性通过阈值。传输限制须对照权威协议和实际配置确认，预算验收需保留测量样本与边界。

## 4. 对话流渲染与交互

### 4.1 默认显示（§3.2 契约——只有用户消息 + 最终回复）
- **用户消息**：actorKind='user' 的节点 → 全文显示 summary（用户消息短，通常不截断）。**指令 token 样式**：正文中的 `[[command:/…]]` / `[[role:@…]]` token 经 `splitCommandPrompt`（与对话模式 `MessageBubble` 同源）渲染为样式化小标签（命令=主题金色、角色=蓝），不再裸显示 `[[ ]]` 包裹文本；普通文本保留换行/空格原样展示。
- **最终回复**：共享时间线中根会话面向用户的Agent消息是展示来源，按orderKey排序。正文直接显示，工具细节通过图标进入详情；子回传不是主回复信号。
- **中间节点**（工具/子任务/思考）：**只显示运行状态行**（⟳ 正在… / ✓ 完成），不显示内容；`toolNames` 可选显示（如 📎 read_file, write_file），`toolCalls` 轻量列表用于按调用逐个显示同一次 LLM 响应中的多个工具及各自状态。点击状态行 → node.get 按需拉全文（§4.4）。**思考行内折叠**：最终回复的「思考」直接展示在正文行上方，**默认折叠**（▸ 思考，点击展开；文字弱化为 secondary 与正文区分，同详情抽屉 交互）；工具节点合并的思考（同一次 LLM 响应并入 tool-batch）仍在抽屉内查看。
- **子任务展示**：根与子链路的节点归属来自共享时间线与执行投影；链路切换和任务说明见 §4.12。不能以设备profile事件折叠规则代替浏览器投影算法。

### 4.2 运行中状态

运行与连接状态通过共享会话视图读取，不由Lite直接监听单一事件并维护第二份状态。`useLiteViewController` 的状态条依次判断加载中、加载失败、历史投影的运行态、重连态、已连接空闲态。

当前模板及控制器未定位到本文所述标题栏“流式”开关，也未提供切换 `turnDelta` 后重建独立连接的路径。不能描述成已存在的操作；如果该开关仍是有效需求，需要与共享连接和流式展示策略一起确认，不由本次文档整理取消。

### 4.3 审批 / 提问交互（G4 全量下发，交互必须）
- **交互入口**：审批 / 提问交互**不再有常驻面板**，入口为 点击大模型响应回来的**工具调用簇按钮**（或时间轴工具块）→ 打开**详情抽屉**，在抽屉内**该工具调用卡**上完成交互（`LiteToolCallDetail` 卡片内嵌 `LiteInteractionView`）。**工具卡 ↔ 交互匹配**：审批 = interactionId 即该次工具调用的 callId；提问批 = 批内每题 questionId 即触发它的 callId（见下）。待处理 / 提交中的交互命中卡片 → 渲染交互视图；**交互完成后不再命中 → 卡片自动回到只读展示**。
- **审批（interrupt）**：`LiteInteractionView` 内展示：头部 `APPROVAL REQUEST` + 状态小点 / 状态药丸（非 pending 时）/ 倒计时（pending 显示剩余，超时「已超时」置灰）；下方 `ApprovalSummary`（标题「大模型需要…」+ 关键信息（工具名称 + 具体目标，如技能加载 = 工具名称 + 技能名称），未声明关键信息的工具回退能力/行为/对象）+ **风险摘要**（security.findings[0] 前 120 字，缺省兜底「未发现额外安全提示…」）+「技术详情」折叠区（完整操作参数 `ParsedArgs` + 文件变更 `FileChangeDiff`）；按钮【拒绝】【允许执行】——**允许后立即执行**，底部提示「批准后将立即执行，请先核对目标与变更。」。提交中 / 超时 / 断线时按钮禁用。
  - 批准 → interaction.approval.decide({interactionId, action:'accept', expectedRevision, commandId})；拒绝 → action:'reject'（interactionId=approvalId 同值）。
  - 结果经 interaction.changed（含 presetId）+ accept/rejected 事件反馈。
  - **id 映射（D 定案）**：interrupt 的 interactionId = 该 sense call id = 消息节点 toolCalls 中该 toolCall 的 call id；「技术详情」经 node.get({rootChatId, nodeId=所属消息节点, sections:['toolCalls']}) 一次拉取该节点全部调用后按 call id 定位该项。
- **提问（question_batch_requested）**：批内每题**分别挂在触发它的工具调用卡上**（questionId = callId），每题独立渲染：题干 + 类型提示（自由回答 / 可多选 · 再点已选项可取消）+ 错误行 + 选项卡区 / 自由文本输入框；**多题批次**每题头部显示进度「第 X/Y 题 · 已完成 N/Y」。提交按钮在任一卡底部（**全部题目答完才可提交**，提交中显示「提交中…」）。
  - **选项**：选项默认按**一行一个**卡片呈现，优先保证详情抽屉中的文字可读；只有详情抽屉内容容器达到足够宽度、每项仍有充足横向空间时才切换为一行两个，不能仅因外层窗口宽就误切双列。每个选项卡片内带「补充」按钮——**仅该选项选中后可用**，点击展开该选项的补充输入框（取消选中即收起并丢弃补充内容）。题末常驻「其他」卡片，其输入框本身作为**单选/多选的一个选项**：单选点击（圆形 radio 标记）即抢走其他选项的选中态、再点可取消，输入内容自动激活并清空其他选中；多选需手动勾选（方形复选框标记），输入内容自动勾选、清空内容即取消勾选。单选/多选均支持再次点击已选项取消选中。
  - **交互草稿**：已选、补充与自由文本存于窗口/根会话的 `rootUi.interactionDrafts`，同一页面内关抽屉再开可恢复；这是界面store状态，不承诺刷新或设备重启持久保存。
  - **自由文本题**：无 options 的题渲染为单行/多行文本框（freeText 提交）；Web 端可直接作答（低档 cancelled 降级仅面向 MCU 无键盘设备，Web 不适用）。
- 精简视图的待处理交互通过对应工具图标进入详情抽屉，不通过独立铃铛入口。
- 审批/提问交互结果在 lite 内闭环，不需要切到完整视图。

### 4.4 按需详情（node.get，G5）
- 详情入口打开 `DetailDrawer.vue`；按节点类型选择正文、思考和工具调用分节，不是每次点击都请求全部分节。已有完整本地内容优先写入分节缓存；工具批正文使用共享时间线合并的消息正文，不能假设后端工具批节点另有全文可拉。
- 需要远端内容时，通过 `useLiteCanonicalView.fetchNodeDetail` 调用 `agentApi.getTimelineNode`；正文/思考使用offset，工具调用使用toolCursor。按响应的hasMore及游标续拉，不把文档中的固定字节预算当作本轮已实测结论。
- 思考分节默认折叠，展开后显示对应缓存内容，必要时补拉；工具详情、正文和思考的来源分别检查。默认折叠是展示状态，不代表内容未传输或未加载。
- **工具调用风险展示**：toolCalls 中每项 toolCall 携带 `security?`（该工具 `authorizeToolCall` 判定原样透传，与审批 interrupt 同源；缺省 undefined 兼容旧数据）→ `LiteToolCallDetail` 在工具状态旁渲染 `RiskBadge compact`（**固定四档：安全=绿/中风险=黄/高风险=红/未知或未评估=灰**；config_manage 写操作 = 中风险，读操作 get/asset_get 直接放行且无判定，见 role-security.md）。
- **工具卡标题去重**：`LiteToolCallDetail` 卡片头部只保留 **icon + 风险徽章（compact）**——工具名/类型/执行状态/耗时已由抽屉顶部标题栏承担，卡片内不再重复展示。
- **详情抽屉宽度可拖拽**：抽屉左缘为拖拽手柄（ew-resize），宽度 clamp(320px, 拖拽值, 92% 容器宽)；拖拽结果按窗口 × 根会话持久于 LiteRootUiState（`detailDrawerWidth`，null=默认 min(460px, 92%)），重开抽屉/切回会话保持；抽屉体配主题化细滚动条（超长内容可拖拽滚动，§4.4 不再隐藏滚动条）。
- **工具详情展示重排**：
  - 字号与字重以当前组件样式和统一设计token为准，核验正文、字段、代码及标题可读性，不维护历次像素调整记录。
  - 工具类型、执行状态与风险信息避免重复，徽章尺寸与圆角遵守现行组件样式；真实对齐与可读性由用户验收。
  - **参数展示**：内置工具按专有组件分发，不套用通用折叠方案；外部工具的通用参数区才使用对应details布局。
  - **执行说明区只承载标题栏没有的信息**：抽屉标题栏已含工具名 + 状态 + 耗时，工具卡「执行说明」区不再显示动作句（已读取文件/已写入文件…）与状态句（执行完成），只保留「目标」（路径/命令/URL 等，等宽代码块）与「本次变更」列表；两者皆无（如提问工具）整区不显示。
  - **结果展示**：内置工具由各专有组件组织核心结果；外部工具使用通用结果区，其短结果展开、长结果预览的规则不能套到所有内置工具。
  - **工具游标续拉**：`loadToolCallsChain` 每次最多请求24页，遇到失败立即记录分节错误；响应无hasMore或无nextCursor时停止。有剩余内容时提供续拉入口。不能把“一次最多24页”写成保证首次打开就完整取回全部工具，也不能把请求错误当成完整加载。
  - **按工具类型渲染参数**：「问题 + 选项」形态参数（`question` + `options` + `multi_select`/`multiSelect`，如 ask_user_question 类工具）渲染为单选（○）/ 多选（□）选项列表区块，不再把 options 原文 JSON 列出；**选项说明完整展示在选项文字下方（浅色，不截断，）**；**已答时结果直接渲染进选项**——选中项 ✓ + 主色高亮背景，取消显示「用户已取消该问题」，自由文本/补充注记照树视图样式，提问工具不再单列「原始结果」；标量数组字段（文件列表/标签/选项等）渲染为逐行点号列表；命令/路径/URL/内容等关键字段保留等宽代码块。
  - **提问工具标题 + 说明**：header/rationale/nextStep 三个字段（大模型写的数据，非代码说明）从参数字段行移到「参数」上方独立块——header 作标题，「为什么需要你决定」「决定后会发生什么」作说明（与任务中心提问面板同标签）；参数字段行与「更多参数」折叠区同步排除这三个键。对话模式提问卡片（QuestionRenderer）与树视图悬停详情（QuestionAnswerDetail）同样展示这两条说明（数据一致）。
- **未知工具（other）**：不再展示 `sense.tools` description 工具说明行（，代码写死的说明信息不上 UI）；下方按「中文标签: 内容」逐字段行展示；嵌套对象/数组递归翻译键后 pretty-print。
- **工具详情专有展示边界（当前规则）**：Lite 抽屉按内置工具名清单分发专有详情，核心参数与结果直接展示，不提供通用「简介 / 参数折叠 / 结果预览」；外部自定义与 MCP 工具才使用通用展示。分发入口为 `LiteToolCallDetail`，工具名维护见 `builtinToolNames.ts`，新增后端内置 sense 时必须同步补齐 Lite 展示与对应人工操作卡。完整结果仍受抽屉分页加载边界约束，用户可用「继续加载更多工具内容」取回剩余部分。

### 4.5 发送
- **自适应输入框**：按内容增高并设滚动上限；展开入口、收起条件及高度由当前 `LiteView.vue` 与控制器维护，展开状态是界面状态，不是连接选项。
- 输入区使用主题派生样式；当前交互在详情抽屉，不以旧常驻提问面板配色定义主视图布局。
- **Enter 发送、Shift+Enter 换行**。chat.input.submit（命令面：立即 ack + 幂等 commandId + 客户端预分配 messageId）。
- 发送后：本地立即回显用户消息（messageId 预分配）→ input.updated 确认（去 content，设备本地已有文本）→ run.updated 开始运行。
- 输入队列满（INPUT_QUEUE_FULL 码）→ 提示「正在处理上一条，稍候」。

### 4.6 停止 / 继续
- 停止/继续入口通过共享命令层执行，按钮显隐读取运行与canResume状态；命令门关闭或提交中禁用。递归停止、权限和幂等须按公共命令接口与正式测试核对，不由Lite界面自行决定。
- run 中断（error / child_abandoned）→ 折叠为子任务失败状态行 + 主视图可继续（canResume）。

### 4.7 分页 / 更多
- 对话流顶部「加载更早」→ chat.timeline.get({rootChatId, before: orderKey, limit})（P1 游标）分页续拉；hasMore 控制按钮显隐。
- 节点数提示（nodeCount）在状态条显示。

### 4.8 连接恢复与展示

Lite从共享连接store派生连接状态，状态条通过 `liteStatus` 展示；重连分支文案为“重连中…”，并未显示重试次数。历史运行态判断优先于重连分支，所以不能承诺断线期间状态条始终展示重连文字。

会话恢复、订阅重建与重放由公共层负责，Lite不自行重跑一套加载链。恢复正确性须在共享会话层验证：断线前后的消息、运行终态、交互状态和重复命令分别核对，不能以连接变成已连接或界面仍保留历史数据作为恢复完成的唯一依据。

### 4.9 审批倒计时与终态

`useLiteInteractions.ts` 在存在带 `deadlineAt` 的pending/resolving交互时，每秒更新 `countdownNow`；无此类交互或组件卸载时清理定时器。剩余时间按 `deadlineAt - countdownNow` 计算，非进行中交互不显示倒计时。

时钟来自 `useLiteCanonicalView.calibratedNow`：优先采用共享会话的 `serverClockOffsetMs`，没有时回退共享交互store的校准时钟。不再描述为Lite独立连接通过done投影自行校准。

本地倒计时到零会显示“已超时”，`LiteInteractionView.vue` 据此禁用审批按钮；这只是本地展示和操作限制，不把交互store的状态自行改为expired，也不能证明服务端已拒绝。服务端终态与提交结果仍须读取共享交互状态核验。`expired` 状态文案为“已超时，未执行”。

验证时分别检查本地计时、按钮禁用、服务端终态和断线恢复后的状态，不能将其中一项通过推导为全部通过。

### 4.10 错误处理归属

审批与提问委托共享交互store执行，错误从 `errorsById`、`questionErrorsById` 读取；Lite不独立维护完整的六码状态机。提交方法返回布尔结果不等于服务端终态，仍读取共享交互记录判断完成、过期或取消。

发送、重试、停止和继续失败写入界面命令错误；详情加载失败保存分节错误，RATE_LIMITED还可写入命令错误。用户面保留服务端错误信息，不擅自生成成功结论或吞掉追踪标识。

STALE、已处理、冲突、队列满、限流和版本不兼容分别核对公共接口和实际渲染分支。没有源码入口的专用刷新按钮、自动退避或profile升级提示不写成已实现；需要这些行为时作为需求差异确认。

### 4.11 运行轨迹

lite 视图对话流上方的多流水线运行轨迹。**一轴 = 一个 Agent 流程**：主 Agent 一条，每个子 Agent 一条独立流水线；子 Agent 的块始终在其自身流水线上展示，不并入主流水线。轨迹区块为**独立区块**：上下保留内边距，轨道块在区块内垂直居中，第一条轨道不贴顶部标题（修正）。

**垂直布局**：轨迹区块高度**随内容自适应**（不固定高度、不居中大留白）——任务条多轨时自然变高，上下仅对称留白 **10px**（顶部内边距 10 = 底部内边距 3 + 横向滚动条轨道占位 7）；`max-height:168px` 仅作多轨溢出的兜底滚动上限。

**当前布局实现**

布局由 `apps/web/src/features/lite/trajectoryLayout.ts` 的 `computeTrajectoryLayout` 维护，节点投影与计时由 `executionMonitor.ts` 维护。当前算法不是各轨道从零开始的无时间定位流：

- 全局节点按 `startedAt` 和稳定key排序，共享压缩时间位置；相邻开始时间差按每秒1px映射，间隔上限24px并乘缩放系数。左侧预留76px标签区域。
- 用户节点归根会话，其余按 `sourceChatId` 分轨；轨道按首次开始时间排序。
- `isTimedNodeKind` 判定的执行节点按真实耗时映射宽度，下限10px、正常上限180px；其他节点固定宽，用户16px、其余12px，再应用缩放和下限。
- 同轨道位置取全局时间位置与前块右缘加1px的较大值，避免重叠。不同轨道不独立重置时间起点。
- 压缩判定使用标签区域、块宽总和与块间隔，不计时间空隙；超出可用宽度时执行块上限30px。容器宽度仍覆盖实际时间位置与块宽。

这些是已核对的当前算法，不自动代替交互需求确认。若希望使用完全无时间空隙或工具固定宽度的其他规则，须先确认需求及其与现有测试的差异，不能把旧开发描述当作现行算法。

**布局与视觉**
- 不展示时间刻度轴或空隙省略符；底层仍使用封顶后的时间间隔定位，不能将不显示刻度解释为没有时间位置。
- 块为标准矩形，**无圆角**（`border-radius: 0`）；相邻块之间 **1px 间隔**；类型用颜色区分（user=主色 / model=绿 / tool=黄+工具类型配色），不依赖虚线/边框区分。
- 轨道前缘显示当前 `track.label`，标签可切换所属Agent链路；标签区域与布局中的左侧预留宽度共同作用。
- 头部**去掉「时间轴」标题**，仅保留「缩放重置」按钮（非 100% 时显示），常规文档流行、不覆盖行标记。

**交互**
- 点击块 → 定位并高亮下方对应内容行（含闪光）；hover → 浮层详情（状态/耗时/类型/Agent；工具节点额外显示**工具类型名称**，如「命令/读取/写入/网页/委派/工具」；浮层底部有「点击定位下方内容」操作提示）；**运行反馈（ 性能修正）**：running 块宽度增长由 **CSS 动画**推进（1px×zoom/秒，经 `--bar-from/--bar-to/--bar-dur` 注入，到 180px 上限定格）——轨迹布局 memo 的签名**排除 elapsedMs**，每秒时钟 tick 不再重算/重写轨迹 inline style（消除「值未变却持续重绘」），运行期间零 JS 更新，运行结束由布局重算写入精确终宽并移除动画；`data-tooltype` 驱动工具类型配色。

### 4.12 链路标签栏与子 Agent 入口消息

正文列表（对话流）一次只展示一条链路（主 Agent / 子 Agent，见 §4.11 轨迹分轨）。链路切换与任务说明如下：

- **链路标签栏**：常驻**顶部状态条（lite-statusbar）内**一行链路标签——主 Agent（✧ 主 Agent）+ 各子 Agent（◆ 角色名），**顶层多个 Agent 全部用名字展示**、不折叠，激活项高亮、点击切换 activeLane，与轨迹行头角色名按钮（§4.11 交互）联动，两处均可切换；标签随节点出现增减，用户消息并入主 Agent 链路（§4.11）。
- **子 Agent 入口消息**：activeLane 为子 Agent 链路时，正文列表顶部渲染「任务委派」入口块——主 Agent 角色名 + ⇢ 任务委派 + 派发任务全文。全文取最早一条 `targetChatId` = 该子 Agent 的 dispatch 节点（direction=parent-to-child）的 content；长文默认截断（≤120 字）可点击展开。入口块独立于历史列表（不进时间轴/轮次排序），仅作子 Agent 链路任务说明——打开子 Agent 链路即可看到主 Agent 派给它的任务。

### 4.13 工具调用图标

正文工具图标由 `LiteView.vue` 渲染，图标映射位于 `clusterIcons.ts`，样式位于 `LiteView.styles.css`。当前实现与状态提示需分别核对：

- 工具使用 `MorphIcon` 矢量图标，类型颜色由 `data-tooltype` 决定；节点和工具说明通过浮层及可访问名称提供，点击打开详情抽屉。
- 普通工具按钮无边框、背景透明；打开详情的工具使用 `is-selected` 的1px主题色轮廓和2px轮廓偏移标记。不能把选中态写成仅变亮或底部线。
- 未处理提问通过 `is-attention` 下的图标闪烁提醒，与运行状态提示分开。运行状态小点的实际渲染和样式由对应组件维护，不能把小点等同于详情选中状态。
- 同一响应内工具并排展示；不同 `lite-cluster-unit` 间通过CSS伪元素绘制细分隔线，不使用ASCII分隔字符。不能由“不使用ASCII”推导没有任何视觉分隔。
- 悬停、选中、待处理提醒和运行状态是不同状态；核验时分别检查，并保留减少动画偏好及键盘访问的验证要求。

本节描述已核对的当前源码，不将旧版本外观要求或尚未确认的界面偏差改成新业务规则。实际可读性和视觉效果由用户验收。

### 4.14 发送 / 运行失败的错误展示

与节点树/完整视图同步，lite 覆盖全部错误类型（发送失败 + 运行失败两条路径，数据均来自 canonical store，复用 error-conventions 用户面一行中文 + detail 通道）：

- **发送失败（发送即被拒 / 命令报错）**：`submitInput` / `retryInput` 捕获异常后写入 `commandError` → `.lite-error-banner` 显示（沿用 §4.10 六码分支：INTERACTION_STALE 刷新 / ALREADY_RESOLVED 已处理 / COMMAND_CONFLICT 处理中 / INPUT_QUEUE_FULL 稍候 / RATE_LIMITED 稍后再试 / 其余原样显示 message）；同时 `.lite-failed-inputs` 保留失败消息行（错误文案 + 【重试】【移除】，既有行为）。**清除时机**：重试成功、或移除全部失败消息后 banner 一并清除（`removeFailedInput` 同步清空 `commandError`）。
- **运行失败（消息已发出、本轮运行中断）**：后端 error 通知写入 `session.run.status='failed'` + `run.error`/`run.errorFact`（见 error-conventions detail 通道）→ 对话流末尾渲染 `.lite-run-error` 条：一行 `run.error` 文案 + 可选【查看详情】展开 `errorFact.detail`（带 `[tracingId]` 检索指引，error-conventions §错误详情通道）；「继续运行」入口沿用状态条 §4.6（canResume 驱动，不重复放置按钮）。

**互斥与去重**：run 错误条仅在无 `commandError` 时显示（命令错误 banner 优先）；发送失败落 `run.status='paused'`（rollbackPreparedInput）不会被 run 错误条捕获——发送失败由 failed-inputs + banner 承载，不重复展示；run 错误保留至下次运行（新流首 chunk / done 时 reducer 清除）。

| 项 | 现有完整 UI | lite 极简 UI |
|---|---|---|
| 连接 | 现有 wsClient（?token=） | 独立 lite wsClient（?profile=lite&v=1&maxFrameBytes=2048&token=） |
| 数据源 | 全量 rootTimeline + 富事件 | lean 投影事件 + 按需 node.get |
| 消息渲染 | MessageBubble/MessageBranchTree/角色编制 | 纯文本行 + 状态行 + 摘要 |
| 审批 | PendingOperationsPanel | 内联审批行（参数精简展示） |
| 输入 | AgentComposer（富文本/媒体/斜杠菜单） | 单行输入 + 发送 |
| 状态 | ContextUsageBar/角色 tags | 精简状态条；流量计数接线待核实 |

### 5.1 与现有 UI 共存的操作约束

- 树、对话和精简视图使用共享会话与命令层；切换视图不等于转移独立连接的操作权。并发、授权与幂等行为以公共命令接口为准，不能由视图名称推导拒绝规则。
- **commandId 幂等兜底**：若用户在两视图快速交叉操作（切换竞态），同一 commandId + 相同参数的重发会被 request_journal 幂等层去重（返回首次结果）；不同参数的同 commandId 报 COMMAND_CONFLICT（§4.10 分支处理）。UI 生成 commandId 时按「一次用户意图一个 id」分配，天然规避冲突。
- **双连接心跳**：lite+完整视图两连接各自 ping 属设计内场景（服务端 ConnectionState 独立），流量计数只计业务帧不受影响（C 定案口径）；断线重连各自独立（§4.8）。

**前端渲染模块建议**（实现阶段）：
- apps/web/src/features/lite/（新目录）：LiteView.vue（主视图）、LiteStore（lean 数据流）、LiteEventMapper（事件→UI 映射）、DetailDrawer.vue（node.get 详情）、TrafficMeter（流量统计）。
- 复用：ws.ts 扩展 profile 支持、connection.ts 的 token 注入、http.ts。

## 6. 验收标准

1. 工作台窗口标题栏三档切换钮存在，切换 树/对话/精简 即时生效、per-window 持久化；rail「对话模式」按钮已移除（，入口统一标题栏三档）。
2. 精简视图读取共享会话和连接状态，不另建连接或重放状态；若需独立低流量连接，先解决 §3 的待确认要求后单独验收。
3. 默认只显示用户消息 + 最终回复；中间节点只显示状态行；点击状态行 node.get 拉全文；子任务状态行可展开 parent-to-child/child-to-parent lean 节点（§4.1）。
4. 审批（interrupt）/ 提问（question_batch）在 lite 内可完整交互并闭环；多选题（multiSelect）与自由文本题正确渲染（§4.3）。
5. 发送走 chat.input.submit，输入后立即回显 + run.updated 反映运行态。
6. 流量预算与统计按 §3.4 待确认事项核对，不把未接通的统计展示或互相冲突的数值当作已通过；确认有效限制后以实际测量验证。
7. 断线恢复通过共享连接与会话层核验，消息、运行和交互状态恢复且不重复执行命令；状态栏文案按 §4.8 的当前判断顺序检查。
8. **审批超时态**：按 §4.9 分别验证每秒更新、到零提示与按钮禁用、共享交互终态；本地倒计时不替代服务端到期处理。
9. **错误处理**：按 §4.10 核对共享交互错误、命令错误和分节错误，实际存在的恢复入口可操作；未接线分支明确保留待确认。
10. 视图切换不破坏共享会话的命令、订阅与重放；界面状态按窗口/根会话隔离，不以独立连接作为判断前提。
11. type-check + 前端构建通过；服务端 lite 测试不回归。
12. 工具调用图标按 §4.13 当前矢量图标映射显示，不用旧ASCII字符表或分隔线；状态指示与交互入口分别判断，窄屏仍可访问详情。
