# 角色端到端验收

角色配置通过结构校验并不等于角色可用。角色端到端验收在目标配置修订已经激活后，用目标角色的真实大脑、系统提示词和真实安全工具运行隔离场景，再由独立评估角色依据执行证据给出结论。

## 入口与执行边界

Cherry Nexus 通过 `role_acceptance` 感官提交目标角色与场景。该感官只负责调用验收服务；角色设计者不能给自己签发通过结论。

每个场景都在新的操作系统临时目录和新的临时 Agent 中执行。验收运行时只暴露目标角色原有工具与安全白名单的交集，并叠加以下不可放宽约束：

- 文件读取、搜索、写入和命令工作目录只能位于本场景临时目录。
- 命令最高只能申请 `workspace-write` 沙箱；破坏性、提权、系统、网络、凭证、动态代码、混淆和未知风险命令拒绝执行。
- `config_manage`、`install_skill`、角色派发/控制、用户提问、记忆修改、媒体生成、外部发送以及全部 MCP 工具不向目标角色暴露。
- 目标角色自己的显式 `deny` 始终保留；验收覆盖层只能收紧，不能放宽。
- 安全覆盖层判定为 `ask` 的本地操作由无人值守验收器预批准，不创建用户审批；硬拒绝仍返回 `sense_reject`。

验收服务不写入正常会话、配置或项目工作区。临时目录和进程内 Agent 在成功、失败、超时后都必须清理。

## 输入契约

```ts
interface RoleAcceptanceRequest {
  role: string
  scenarios: Array<{
    name: string
    prompt: string
    successCriteria: string
    forbiddenBehavior?: string[]
    fixtures?: Array<{ path: string; content: string }>
    expectedArtifacts?: string[]
  }>
}
```

场景名、数量、提示词、夹具体积和期望产物数量均有上限。夹具和产物路径必须是相对路径，不能含 `..`，解析后的真实目标也必须留在临时目录内。

## 报告契约

报告绑定当前激活的 `configRevisionId`，并逐场景返回：

- `pass`、`fail`、`needs_review` 或 `error` 状态；
- 目标角色最终回复与独立评估摘要；
- 实际工具调用、授权决定和执行/拒绝/失败结果；
- 场景产物及缺失的期望产物；
- 无法自动覆盖的能力和人工复核事项。

独立评估角色只接收场景目标、最终回复、工具轨迹和产物清单，不获得工具。确定性检查优先于模型判断：期望产物缺失、越界尝试或运行错误不能被评估角色的 `pass` 覆盖。外部网络、生产环境和真实发送能力在隔离验收中不会被测试，必须明确列入覆盖缺口或人工复核项。

## 激活修订门禁

验收开始时读取当前激活配置修订，并确认目标角色和独立评估角色都来自当前加载配置。报告生成前再次检查激活修订；若运行期间修订变化，本次结果标记为错误，不作为该角色的有效验收结论。
