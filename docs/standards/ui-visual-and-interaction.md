## 1. 字体字重规则

**任何 UI 内容的默认 `font-weight` 一律 400；仅 title 级别或特定关键词强调才可用 600。**

1. **默认内容必须 400**：正文、按钮文字、tip / tooltip / popover 辅助说明一律 400。
2. **600 是标题或关键词强调的专属语义**：仅 section heading（如「连接」）、字段 label（如「地址 / 密钥」）或需强调的关键词可用 600。
3. **弹出内容统一 400**：tip / tooltip / popover 的弹出内容保持 400，`b` / `strong` 内强调词上限 600。全局兜底为 `web/src/styles/element/index.scss` 的 `.el-popper { font-weight: 400 }`（popper teleport 到 body，故置全局非 scoped，防宿主继承加粗）。
4. **全局扫描不放过 >600**：任何 >600 的字重视为违规，降至 600。
5. **中文字号下限 12px（2026-09-02 增补）**：用户阅读性质的内容（正文、说明、参数值、结果、错误提示、字段 label 等会渲染中文的文本）字号一律 ≥12px；仅装饰性字形（aria-hidden 的图形符号）与纯数字徽标可保留更小字号。存量增量修正：修改样式时把触到处的小字号提至 12px，不批量改。
6. **存量增量修正**：旧实现**不批量改**，按「看到哪里改到哪里」增量修正；新增/修改样式时直接遵守。

**Why**：默认内容加粗破坏视觉层级与阅读节奏，加粗是标题或关键词强调的专属语义。用户视为严重错误用法。

## 2. 动作按钮前置禁用（先选后测）

**需要前置字段才能执行的动作按钮，前置字段缺失时直接不可点击 + 悬停提示缺什么；而不是可点后弹出「请先填写…」报错。**

1. **前置校验在渲染期完成**：字段缺失 → 按钮 `disabled`，不进入可点后报错的交互。
2. **悬停提示**：禁用态用 `el-tooltip` 包 `span` 触发容器（disabled 原生 button 不触发 hover/title），内容提示缺失的具体字段。
3. **字段校验顺序固定**：适配器 → 地址 → 密钥 → 模型；缺失提示如「请先填写适配器」「请先填写地址」「请先填写密钥」「请先选择模型」。
4. **特殊场景文案**：mock 等离线场景提示「离线模拟无需测试 / 无需刷新模型」。
5. **点击校验保留作兜底**：渲染期 disabled 是主防线，点击/提交时的校验保留为纵深防御。

**Why**：可点后报错是交互缺陷——「必须关联模型却得先点测试才报错要填模型」。先选后测才是正确交互。

## 3. 圆角规则

**新实现的 UI 一律直角（`border-radius: 0`）；仅少量特殊场景，且必须经用户明确确认后方可使用圆角。**

1. **新元素默认直角**：本批次新做的元素全部 `border-radius: 0`——按钮、卡片、面板、弹层、输入框等一律无圆角，不依赖任何预设圆角变量。
2. **历史存量不动**：已验收元素（消息气泡、审批按钮等沿用圆角的历史样式）不批量改，做到该处时再与用户确认是否收敛。
3. **特殊场景须确认**：确需圆角的单元素（视觉特例）先向用户明确确认，不擅自引入圆角。
4. **增量修正**：新实现一旦出现未确认的 `border-radius` 视为违规，降至 0 或撤回。

**Why**：用户强烈讨厌圆角，2026-08-26 连续两次指出「用户交互确认框」擅自使用圆角仍未收敛，故立为强制规范；与字重规则同为用户视觉强制约束。

## 4. 主题色调（深空电光双极强调色）

**项目主题色调为「深空电光」双极强调：深色模式电光青 `#22d3ee`（深空蓝紫基底 `#0b1020`），浅色模式靛蓝 `#4f46e5`（冷白基底 `#f5f7fc`）。两套均定义于 `web/src/styles/theme.css` 语义 token。**

1. **双极强调色常量**：深色 `--accent: #22d3ee`、浅色 `--accent: #4f46e5`，随 `data-theme` 翻转。浅色不用电光青深变体（冷白底对比度 ~2:1 不足），用靛蓝（~6:1）。浅色模式 `--el-color-primary` 由 `web/src/styles/element/index.scss` 的 SCSS 覆盖为靛蓝；深色模式由 `web/src/styles/theme.css` 的 `html.dark` 块覆盖为电光青（Element Plus 官方 `dark/css-vars.css` 硬编码默认蓝 `#409eff`，特异性 `html.dark`(0,1,1) 高于 `:root`(0,1,0)，必须用同特异性块显式覆盖）。
2. **高亮/激活/选中一律走主题色调**：新实现的 hover、active、选中态、按钮主色、辉光（`--accent-glow`）等场景，统一使用 `var(--el-color-primary)` / `var(--accent)` 及 `color-mix()` 派生，禁止硬编码其它色相。
3. **基底与表面走深空蓝紫/冷白梯度**：深色表面族（`--bg`/`--panel`/`--surface`）为深空蓝紫梯度（`#0b1020`→`#1b2444`），浅色为冷白梯度；禁止引入与基底不同色相的大面积底色。
4. **代码高亮（hljs）冷色系（浅/深双端）**：浅色端走语义 token 引用自动跟随；深色端用冷色系覆盖（Tokyo-night 方向：关键词紫 / 字符串绿 / 数字橙 / 标题青 / 注释灰蓝），允许蓝系。双端保证可读性。
5. **存量硬编码收敛**：暖金时代的存量硬编码（如会话列表 rgba 暖金、attention 暖橙描边）在触碰时收敛到新 token；PaperGameCard 纸牌、Import 霓虹弹窗、nyxus CRT（`--nx-*`）等**独立调色板子系统保持不动**（自成视觉身份，阶段2+ 再议融合）。
6. **新增硬编码色一律禁用**：新增 UI 的颜色值一律使用主题 token / 语义变量 / `color-mix` 派生，禁止直接写死新的色相值。

**Why**：2026-09-01 用户决策前端全面科技感重构，选定「深空电光」全新色系（深色深空蓝紫+电光青 / 浅色冷白+靛蓝），暖金 `#f6b73c` 品牌色弃用；hljs 随之解除「不含蓝」限制改冷色系。裁决记录见 [decisions.md](./decisions.md)。
