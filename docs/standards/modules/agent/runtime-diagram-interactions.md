# Agent 运行图交互入口规范 v1.0

> **状态**：强制执行。
> **适用范围**：`web/src/features/agent/workbench/runtime-diagram/**`、`WorkbenchDialog.vue` 及其待处理审批与提问入口。
> **事实说明**：当前布局与实现入口见 [Agent 运行头部与结果节点树](../../../frontend/runtime-diagram.md)。

## 1. 入口所有权

1. **Info 只解释节点**：右上角 Info 图标仅在鼠标悬浮或键盘聚焦时显示节点简介，移出或失焦即关闭。点击、触摸点按不得打开、固定或切换说明，也不得打开步骤详情或待处理操作。
2. **节点主体承载主操作**：普通步骤节点主体打开步骤实例详情；存在当前根待处理事项时，“等待审批”节点主体只把焦点移入已显示的当前根操作面板，不得复用 Info 行为。
3. **当前根就地处理**：当前根会话的审批与提问在事项出现时直接显示于“等待审批”节点正下方并水平居中，不经过摘要卡片、右侧工具栏或左下角浮层。节点主体是该面板的上下文聚焦入口，不是显示开关。
4. **最近可见祖先锚定**：折叠状态完全由用户选择，不得因待处理事项或 CRT 强制展开任何层。目标节点可见时面板锚定目标节点；目标节点被折叠隐藏时，使用运行图投影的可见代表，依次锚定最近可见祖先，整个头部收起时锚定头部。审批链为“等待审批 → 工具处理 → 内容记录 → 循环调度 → 头部”，CRT 链为“模型请求 → 模型调用 → 重试控制 → 工具处理 → 内容记录 → 循环调度 → 头部”。锚点或视口几何尚不可用时不得退回页面固定位置。
5. **持续可见与生命周期**：当前根只要仍有一项待处理事项，审批操作面板就保持显示，最后一项进入终态后自动移除。CRT 保留既有生命周期和空闲占位；折叠只改变其锚点，不改变是否显示或其内容来源。
6. **层级、移动与缩放**：两个面板位于工作台内容最高交互层，但低于连接断开等不可操作遮罩；画布平移和节点移动会同步移动锚点，画布缩放只更新锚点位置，不缩放面板内容，也不把面板限制到视口边缘。
7. **同锚点堆叠**：审批与 CRT 映射到同一可见代表时，审批面板紧贴节点并优先显示，CRT 在其下方留出 12px 间距；不得重叠或改为页面固定位置。
8. **其他根走右侧入口**：右侧待处理入口的计数、列表和浮层只包含其他根会话。当前根事项不得重复进入该入口，其他根事项也不得挂入当前节点下方。
9. **根身份以时间线为准**：当前流程的待处理归属优先使用已加载时间线的 `rootChatId`，时间线尚未可用时才回退当前选中会话 ID；不得直接用选中会话 ID 将当前根事项误分到“其他根”。当前面板、右侧计数和两处列表必须复用同一个根身份。
10. **进入流程必须恢复收件箱**：工作台进入或切换到一个根流程，以及连接恢复时，必须主动刷新持久待处理收件箱。不得依赖用户点击右侧铃铛，也不得假设全局通知一定晚于工作台挂载；实时通知与进入时刷新共同保证窗口出现。

## 2. 变更约束

- 不得从旧计划摘要、旧触摸方案或通用 tooltip 习惯推导 Info 点击行为；变更入口前必须先更新本规范和展示契约。
- Info、节点主体和右侧入口必须分别测试，不能只验证面板最终可见而忽略触发来源。
- 键盘可达性通过 Info 聚焦和节点主体聚焦提供；不得以补充触摸点击为由恢复说明固定功能。

## 3. Review 清单

- [ ] 点击或触摸 Info 是否保持无动作，且不会固定说明？
- [ ] 鼠标悬浮和键盘聚焦 Info 是否仍能查看说明，移出或失焦是否关闭？
- [ ] 普通步骤节点与“等待审批”节点是否执行各自的主操作？
- [ ] 手动折叠是否保持用户选择，并把审批与 CRT 分别迁移到最近可见代表节点下方？
- [ ] 整个头部收起时，审批与 CRT 是否锚定头部下方；同锚点时是否按“审批、12px、CRT”堆叠？
- [ ] 面板是否随画布移动、保持固定可读尺寸、不做视口边缘钳制，且不会退回页面固定位置？
- [ ] 当前根事项是否只在节点下方出现，右侧计数与列表是否只含其他根？
- [ ] 进入子会话或时间线根与选中会话不同时，当前根事项是否仍归入节点下方面板？
- [ ] 待办先于工作台打开、切换根流程或断线重连时，是否无需点击铃铛即可恢复节点下方面板？
