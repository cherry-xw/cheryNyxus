# 文档目录与生命周期规范

> 状态：强制执行。适用于采用本方案的项目文档。实际领域名称和源码映射由项目配置定义。

内容结构、任务定位和评审见[内容规范](./content.md)，临时任务见[计划规范](./plans.md)。

## 1. 分类与默认入口

统一入口维护稳定领域路由与操作前读取规则。`docs/README.md` 提供完整领域导航；已知目标时可直接进入领域 README，无需先枚举目录或顺序阅读所有上级入口。

| 文档角色 | 默认位置 | 职责 |
| --- | --- | --- |
| 领域实现 | `docs/<domain>/` | 模块职责、实现事实和扩展方式 |
| 共享契约 | `docs/shared/` | 跨模块协议、状态机和公共模型 |
| 质量 | `docs/quality/` | 验证边界与需保留的证据 |
| 指南 | `docs/guides/` | 面向任务的操作方法 |
| 规范 | `docs/standards/` | 按作用域维护的强制规则 |
| 计划 | `docs/plan/` | 未完成工作和恢复信息 |

这是角色模板。项目只建立实际需要的领域，并在默认入口明确名称与路径。文档根目录只放总索引，一级领域提供 README。默认入口只前置稳定路由、基础判断及规范直达链接，不复制详细正文或易变文件树。

## 2. 模块层级

大模块使用目录和 README，专题各自成文；小模块可用领域下单篇文档，多主题后再拆分。按稳定业务或运行边界组织，不机械复制源码目录。公共契约只有一个维护位置，调用方以链接引用。

## 3. 生命周期

README 负责边界、任务路由和直接子项。当前参考文档只描述现行事实。未完成工作按计划规范维护；长期知识与测试在收口时迁入正式位置。具有审计价值的历史资料可放入所属领域 `archive/` 并标记非权威；无审计价值且可从版本历史恢复的过程不另建长期副本。运行产物与持久文档分离，保留政策由项目配置明确。

## 4. 变更同步

新增、移动或删除文档时更新最近 README、修复入链，并检查链接、路径、孤儿文档和计划跟踪状态。一级分类变化时同时更新默认入口与文档总索引。重复导航只能包含路由信息，领域维护者负责一致性；事实正文遵循唯一 owner。
