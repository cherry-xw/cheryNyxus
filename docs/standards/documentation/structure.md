# 文档目录与生命周期规范

> 状态：强制执行。适用于采用本方案的项目文档。实际领域名称和源码映射由项目配置定义。

内容结构、任务定位和评审见[内容规范](./content.md)，临时任务见[计划规范](./plans.md)。

## 1. 文档角色与入口

统一入口维护稳定领域路由与操作前读取规则。文档总索引 `docs/README.md` 提供完整领域导航；各级入口的阅读路径与跳转要求见[内容规范](./content.md)第 2 节。

| 文档角色 | 默认位置 | 职责 |
| --- | --- | --- |
| 领域实现 | `docs/<domain>/` | 模块职责、实现事实和扩展方式 |
| 共享契约 | `docs/shared/` | 跨模块协议、状态机和公共模型 |
| 质量 | `docs/quality/` | 验证边界与需保留的证据 |
| 指南 | `docs/guides/` | 面向任务的操作方法 |
| 规范 | `docs/standards/` | 按作用域维护的强制规则 |
| 计划 | `docs/plan/` | 未完成工作和恢复信息 |
| 生成文档 | 项目配置声明的输出目录 | 由源文件、数据或命令产生的可再生内容，不是事实 owner |
| 外部来源镜像 | 项目配置声明的镜像目录 | 外部仓库或来源同步进来的副本，不是第二个事实 owner |
| 兼容跳转页 | 原路径或最近入口 | 只把历史路径导向当前 owner，引用迁移完成后删除 |

上表是长期事实的唯一角色划分：每类事实只在对应角色的目录中维护，其他位置按[内容规范](./content.md)第 5 节链接 owner。项目可以使用不同的目录名称，但这些角色必须可从统一入口定位。

这是角色模板。项目只建立实际需要的领域，并在统一入口明确名称与路径。文档根目录只放文档总索引，一级领域提供 README。统一入口只前置稳定路由、基础判断及规范直达链接，不复制详细正文或易变文件树。生成文档、外部来源镜像和兼容跳转页必须在项目配置中声明；未声明的输出或镜像不能自动获得长期文档地位。

## 2. 模块层级

大模块使用目录和 README，专题各自成文；小模块可用领域下单篇文档，多主题后再拆分。按稳定业务或运行边界组织，不机械复制源码目录。公共契约只有一个维护位置，调用方以链接引用。

## 3. 生命周期

README 只负责边界、任务路由和直接子项，要求见[内容规范](./content.md)第 3.1 节。当前参考文档只描述现行事实。未完成工作按[计划规范](./plans.md)维护；长期知识与测试在收口时按其第 3 节迁入正式位置。具有审计价值的历史资料可放入所属领域 `archive/` 并标记非权威；无审计价值且可从版本历史恢复的过程不另建长期副本。生成文档、外部来源镜像和兼容跳转页按[内容规范](./content.md)第 5.1 节处理，不能把输出或镜像当作第二份正文。运行产物与持久文档分离，`docs/plan/` 内的跟踪边界见[计划规范](./plans.md)第 1 节第 8 项，其他产物的保留政策由项目配置明确。

## 4. 变更同步

新增、移动或删除文档时更新最近 README、修复入链，并完成[内容规范](./content.md)第 8 节的检查项。一级分类变化时同时更新统一入口与文档总索引。导航可以在多个入口重复链接，但重复导航只能包含路由信息，领域维护者负责一致性；事实正文遵循[内容规范](./content.md)第 5 节的单一事实源要求。
