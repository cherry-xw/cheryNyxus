# 文档管理方案采用指南

本指南帮助新项目采用同目录的通用规则包。规则正文由[内容规范](./content.md)、[目录规范](./structure.md)和[计划规范](./plans.md)分别维护；[统一入口模板](./entry-template.md)提供可复制的启动基线。本指南只维护采用与评估流程。

## 1. 复制范围

整体复制本目录，包括 README、三份规范、入口模板、本指南和 `tools/` 可选工具目录。保留包内相对链接。将模板合入目标项目根 `AGENTS.md`，替换项目配置区；不要覆盖目标项目已有有效约定。不采用附带工具时可不复制 `tools/`，规则正文不依赖它。

各工具配置其支持的入口读取根 `AGENTS.md`，统一维护规则正文。用新会话验证入口是否被加载，不假设所有工具都自动识别同一文件名。

## 2. 配置项目

1. 确认实际源码、测试根和稳定业务边界，只为实际需要的领域建立 README。
2. 在根入口直接列出任务范围、领域职责和真实 README 链接，使首次定位无需枚举目录。范围未知时使用文档总索引。
3. 建立项目配置文档：明确协作规范入口、测试命令入口、人工验收范围、审批开关与审批人、计划台账保留和运行产物策略。
4. 入口按触发操作直接链接三份通用规范与项目政策，规定在相关操作开始前读取。
5. 总索引保留完整领域导航，并指定维护者同步根入口中的稳定路由。

## 3. 迁移现有文档

老项目没有文档或现有文档无法可靠导航时，先执行[存量项目梳理指南](./existing-project-guide.md)，建立经过验证的最小入口。已有结构基本可用时，再盘点各主题的事实 owner，核实契约与实现证据并合并重复定义。通用规则归规则包，业务事实归模块，项目特殊限制归项目配置或其引用的协作政策。

旧路径被引用时可在权威页面保留必要锚点，或在确实无法更新引用时保留兼容跳转页；兼容页必须说明淘汰条件并在引用迁移后删除。没有独立规则、操作方法或事实的普通跳转页直接合并进最近 README 或权威入口。不能同时保留两份规则正文。更新最近导航；移动文件时检查所有入链。长期知识从历史计划迁入正式文档，过程按项目保留政策清理。

先选择一个高频模块，补齐任务意图、权威说明、实现路径、关键符号和验证入口。其余模块随实际变更逐步治理，不要求一次性重写，也不创建没有内容的章节。

## 4. 运行检查

先检查本地链接、锚点和引用路径，再检查从文档总索引的可达性、默认路由一致性以及计划和产物的版本控制边界。项目选择现有工具或接入相应检查；本包不附带与某种语言或包管理器绑定的命令。

选几个真实任务验证：能否在操作前读到适用规则，能否直接找到模块与验证方式，是否仍需全仓搜索。结构可达不等于契约正确，内容与影响面仍需维护者评审。

## 5. 评估与升级

记录相同任务的读取次数、跳转次数、全仓搜索次数和默认入口长度。稳定一级路由应减少首次定位操作；详细模板、低频例子和历史过程不应挤入默认入口。常见任务建议在四次文档跳转内到达实现入口。

升级规则包时检查本地差异，将项目参数留在项目配置，更新模板新增的触发入口并重跑导航检查。包内规则相互引用，避免只复制一篇正文而遗漏依赖。

最低采用标准：默认入口可用，真实领域可直达，每项事实有唯一 owner，高频任务能定位到符号与验证，活动任务可恢复，长期知识不只存在于计划中。
