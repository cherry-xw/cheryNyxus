# CheryClaw 文档管理项目配置

本文件维护通用规则在本项目的参数和政策选择，不重定义[通用文档规范](../documentation/README.md)。任何适用操作开始前读取相应配置。稳定一级路由由根 [AGENTS.md](../../../AGENTS.md) 的项目配置区维护；[文档总索引](../../README.md) 提供相同目标的浏览入口，分类变化时同步两处导航。

## 1. 目录与实现边界

后端实现位于 `src/`，前端位于 `web/`；领域路由详见根入口。模块文档映射稳定职责，具体符号由领域入口维护。跨端架构、消息、数据模型与状态机统一由 `docs/shared/` 维护。

实际模块与验证入口分别从[后端](../../backend/README.md)、[前端](../../frontend/README.md)、[质量](../../quality/README.md)进入；长期测试使用项目已有测试设施（包括 Vitest），按目标模块的文件和命令验证，不在通用包中固化命令。

## 2. 计划政策

采用[通用计划规范](../documentation/plans.md)的活动状态与显式用户审批关口。全部必要验证通过后进入“待用户审批”；用户明确批准后，将长期事实迁入权威位置，从计划总入口移除任务并删除整个总任务目录，不保留“已完成”计划台账，也不再等待单独的删除指令。

每个计划小任务必须标注 1 至 5 档复杂度及依据。每次任务启动或分配前，执行者先向用户报告该任务的复杂度与建议的模型能力特征，再由用户确认具体使用的 Agent 或模型。复杂度字段不绑定固定的模型类型、名称或厂商；复杂度变化时重新评估并再次确认分配。

计划根固定为 `docs/plan/`。入口、任务 README、未完成子计划和可复用验证说明纳入 Git；一次性验证脚本放在任务 `verify/`，运行产物显式输出到 `verify/out/` 并由 Git 忽略。

任务级长期验收证据统一迁入 `docs/quality/verification/<task-id>/`，子目录与文件命名由[验证证据规范](../quality/verification/README.md)维护；自动命令原始输出、关键截图描述、人工清单结论、用户批准原文必须迁出，迁出后随任务目录整体删除。综合验证小任务的“反馈回填槽”在阶段一收口前必须清零，所有反馈仅登记在该槽内，不得另开修正任务或悬空待办。自动清单以“命令 + 退出码 + 关键断言行 + 产物”为唯一登记形式；人工清单只保留四类（真实视觉与交互、主观 UX 判断、跨设备/窗口/无障碍、性能体验），每条 ≤1 分钟；用户对自动清单采取抽样信任，不再逐条核对。

恢复任务从[计划总入口](../../plan/README.md)开始。

## 3. 验证与协作政策

提交和图片验证前读取[AI 协作规范](./ai-collaboration.md)。图片读取限制由该文件唯一维护。

自动验证不得启动或操控浏览器、Electron 等图形界面，不得执行页面截图、录屏、像素比对、浏览器 UI 自动化或以程序化 DOM/CSS 检查代替 UI 验收；浏览器构建本身不属于启动界面。浏览器与 Electron 实机操作、视觉与交互验收由用户按最后的手动清单执行并记录，除非用户对具体任务另有明确授权。自动检查通过而必要人工验收未完成时，任务仍处于“待综合验证”。

本项目的语音纠正和首次用户交互原则由根入口的项目约定区维护，不随通用规则包迁移。
