# 代码结构核对与回归

本文维护结构检查方法和当前可用命令，不保存开发批次、已完成清理台账或旧规模快照。测试结果判定见[测试范围与结果判定](baseline.md)，已确认的开放问题由[已知问题](../known-issues/README.md)维护。

## 引用与删除判断

- 先确认文件、符号及调用入口实际存在，再检查生产代码、测试、协议注册、动态加载和字符串调用。
- 没有直接 import 不等于无消费者；RPC处理器、插件入口、框架回调和公共导出必须核对实际注册关系。
- 已不存在的文件不列为待删除对象，不为旧文档恢复历史实现。
- 只在文件内部使用的函数，是否取消导出与是否删除函数是不同判断。测试消费者和对外契约也必须核对。
- 工具报告只提供线索；确认删除须说明当前消费者、行为影响与验证方式，不把未确认结论写成清理指令。

## 职责与重复实现

共享协议定义在 `packages/protocol/`，调用方使用其实际导出。核对重复时先判断语义、权限、错误和生命周期是否一致，不能仅按函数形状合并。

以下设计问题需要独立核实，不作为已经批准的重构要求：

- offset分页、编码游标与带查询指纹的游标具有不同恢复语义，不能为了共享代码而统一协议。
- 技能与插件导入流程的准备、确认和提交边界须分别核对，不能仅因流程相似就共用一个工厂。
- 各领域的注册入口是否需要统一，取决于真实消费者和维护成本，不以文件数量决定。

## 文件规模与拆分

当前规模从实际源码重新测量，排除第三方、生成物和构建目录。过去的行数、重复率或复杂度快照不能作为当前事实，也不能推出新增功能必须让总规模下降。

拆分依据职责、依赖、状态所有权和测试能力。正式行数约束以项目现行规范与测试为准，不从旧分析表引入新的阈值。源码行数下降不证明行为正确；协议、取消、错误、持久化和权限边界必须分别验证。

## 当前检查入口

以下脚本在根 `package.json` 声明；本表说明入口，不表示已在当前工作区运行通过。

| 命令 | 用途 |
| --- | --- |
| `pnpm deadcode:scan` | 项目自有死代码扫描入口 |
| `pnpm jscpd:dup` | 重复代码报告 |
| `pnpm jscpd:dup:check` | 对照配置基线检查新增重复 |
| `pnpm jscpd:deadcode` | 未使用代码候选报告 |
| `pnpm jscpd:complexity` | 复杂度报告 |
| `pnpm jscpd:health` | 汇总报告 |
| `pnpm regression:code` | 顺序执行重复检查、未使用代码报告和复杂度报告 |

配置位于根 `.jscpd.json`，重复指纹位于 `.jscpd-baseline.json`。检查前读取实际扫描范围与排除项，报告没有覆盖的目录不能算已验证。工具退出码按实际输出解释，不将报告完成当成所有问题已解决。

`pnpm jscpd:baseline` 会更新基线，不是只读验证。只有明确确认接受的重复及配置变更才可更新；不得为了消除失败自动刷新，也不得用基线屏蔽权限或业务回归。

## 结果维护

当前未解决问题须有位置、影响、证据与完成条件。解决后更新对应当前说明并删除开放条目，不追加完成历史。命令原始输出和开发追踪保存在仓库外或任务系统；长期文档保留可复用入口、当前限制和准确结论。
