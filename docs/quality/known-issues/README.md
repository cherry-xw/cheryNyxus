## 维护规则

1. 新问题先在本页新增一行并分配稳定 ID，再写入所属模块详情；列表只保留模块、类型、优先级、状态、一句话摘要和链接，不复制证据或操作步骤。
2. 类型使用 `人工复核`、`待修复` 或 `暂缓处理`；状态使用 `待用户复核`、`已确认待修复`、`处理中`、`已知/暂缓`。未经实际验证不得把“待人工复核”改成已通过。
3. 详情按真实模块或维护边界组织。新增内容后，任一详情文件超过 600 行时，必须按子模块或主题拆成新的详情文件并更新本目录链接；禁止机械命名为 `part-1`、`part-2`。
4. 本页保持短小，不写修复流水账。问题解决并完成所需验证后从当前列表移除；确有长期审计价值时迁入对应 `verification/` 或模块归档，而不是继续留在开放问题中。
5. UI 人工复核遵守 [前端 UI 视觉与交互规范](../../standards/frontend/ui-visual-and-interaction.md)：自动执行者不得运行浏览器/Electron、截图或 UI 自动化，结论由用户填写。

## 新问题最小信息

详情至少写明：现象或待确认点、影响范围、当前证据、处理决定、复核/修复入口和关闭条件。缺少事实时标为待复核，不推定为产品缺陷。
