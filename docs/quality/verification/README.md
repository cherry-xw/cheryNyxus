# 验收证据

> **状态**：强制执行。
>
> **适用范围**：所有已结束实施计划的长期验收证据；`docs/plan/<task-id>/` 任务目录被删除时，其验收证据须先迁入本目录才能执行整目录删除。

本目录保存仍有复核价值的质量证据与人工验收场景。记录描述已经执行的检查、已知限制和待完成人工验证，不替代功能文档或活动实施计划。

## 目录结构

每个已结束的实施计划在本目录下建立一个以 `<task-id>` 命名的子目录，与 `docs/plan/<task-id>/` 的任务 ID 保持一致；该子目录是任务收口前长期证据的唯一 owner。

```text
docs/quality/verification/
├── README.md
├── <task-id>/
│   ├── auto-output.md         # 自动清单原始命令输出（至少 1 份完整日志）
│   ├── auto-output-extra/     # 体积较大或多份自动输出（可选）
│   ├── manual-conclusion.md   # 人工清单结论文字（每条含目标、入口、结论、证据）
│   ├── approval.md            # 用户明确批准的原文记录
│   └── screenshots/           # 关键截图描述（不存图，只存路径与说明）
└── <历史平铺文件>             # 早期任务按单文件形式保留，禁止继续追加
```

## 任务子目录的最小内容

- `auto-output.md`：原样粘贴或附件化自动验证清单中每条命令的原始输出（至少退出码、关键断言行、时间戳）。允许按子主题拆分为多份，但必须以 `auto-output*.md` 命名。
- `manual-conclusion.md`：人工清单每条的最终结论（目标 / `verify/manual-final.md` 锚点 / 结论：通过 / 失败 / 待补 fixture / 执行人 / 日期 / 证据位置）。
- `approval.md`：用户在阶段三明确批准任务收口的原文记录，至少包含批准时间、批准人、批准范围（是否包含所有自动与人工清单）。
- `screenshots/`：用户留存的截图或视频描述（路径 + 一句话说明），不存放图片文件本身；图片类验证遵守 [AI 协作规范](../../standards/global/ai-collaboration.md)。

子目录的文件名固定为以上三类；项目配置允许在 `screenshots/` 下自定义二级结构。

## 必迁与不迁内容

- **必迁**：自动清单原始命令输出（至少 1 份完整日志）、关键截图的描述（不存图，只存路径与说明）、人工清单结论文字、用户明确批准的原文。
- **不迁**：实施细节段落、未通过命令的失败记录（除非作为已知问题长期跟踪）、与本次任务无关的文件改动。

## 迁出与删除

- 任务进入收口前必须完成迁出：把上述必迁内容写入 `docs/quality/verification/<task-id>/` 对应文件。
- 迁出完成前不得删除 `docs/plan/<task-id>/verify/` 与 `docs/plan/<task-id>/verify/out/`；迁出后这两类目录随任务目录整体删除。
- 任一必迁文件缺失时，禁止删除任务目录，参照 [Plan 操作方案](../../standards/documentation/plans.md#6-用户审批与总任务完成)的诊断矩阵定位。

## 抽样信任

- 自动验证清单的"抽样信任"结论统一登记在 `approval.md` 末尾，不另设文件。
- 抽样结论至少含：抽样条数、抽样编号、用户确认的退出码与断言行摘要、抽样日期。

## 历史兼容

- `config-hot-apply.md` 为早期任务的平铺文件，按历史事实保留，禁止继续追加或编辑。
- 此后所有新任务按本规范的 `<task-id>/` 子目录形式组织，老任务不再回写或重组。

## 维护规则

- 任务 ID 与 `docs/plan/README.md` 已删除的任务行保持一致；删除任务时同步删除对应子目录。
- 子目录不得保留与本次任务无关的迁移内容；如需保留长期问题，迁入 `docs/quality/known-issues/`。
- 本目录不得作为功能实现说明的来源；如需追溯实现细节，回到 `docs/` 权威文档或版本控制历史。
