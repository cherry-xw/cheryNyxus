# 源文件被外部覆盖/回滚的排查

> 适用场景：修改过的 `src/`、`web/src/` 源文件突然变回旧版、改动丢失，或反复横跳。

## 现象

- 刚改完的文件内容与预期不符，改动像从未存在过；
- 同一文件多次读取内容不同（时间戳变化）；
- git 里查不到自己的改动。

## 排查步骤

1. **先确认是否在 git 中**，不要盲目重做修改：
   - `git status --short`：看目标文件是否有未提交改动；
   - `git stash list`：看是否存在 stash（另一个进程可能先 stash 再提交）；
   - `git log --oneline -3`：看最近是否有自动/外部提交。
2. **判断是否为另一进程的 git stash / 提交操作**：
   - 文件状态干净（无未提交改动）→ 改动可能已被提交进历史，或仍在 stash 中；
   - 存在 stash 记录 → 改动被暂时收起，等对方 stash pop / 提交后会自动恢复；
   - 文件反复横跳（一会儿旧版一会儿新版）→ 有进程正在写入，先找出发起方（`Get-Process`、`Get-CimInstance Win32_Process` 看 node/python/编辑器语言服务器等），确认其行为。
3. **等待片刻再复查**：若是 git stash 自动恢复场景，稍等后文件会回到正确状态。
4. **不要在覆盖窗口期内反复重做**：先确认写入方已停止，再开始编辑，避免再次被冲掉。

## 要点

- 发现文件被外部覆盖时，**第一动作是查 git 状态确认归属**，而不是立刻重写；
- 多个会话/进程并行工作时，先同步工作区归属，避免互相覆盖。
